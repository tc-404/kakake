================================================================================
  咔咔珂 Kakake · Termux（安卓手机）使用教程（从零到能聊天）
  适用: Android 7.0 及以上、64 位（arm64）机型
  启动脚本: 项目根目录 start.sh（和 Linux / macOS 共用同一份）
================================================================================

【动手前先了解手机跑机器人的现实情况】
  1) 能跑，但吃电、发热，安卓还会主动杀后台。适合拿闲置旧手机长期插电当小服务器，
     不建议用主力机。
  2) 手机上跑不了 NapCat。NapCat 需要 Linux 版 QQ 客户端和图形环境，
     手机没有这些条件；mk 在 Termux 里会直接把 NapCat / snowLuma / 宝塔菜单拦住。
     所以手机上的咔咔通常是「主动去连别处的协议端」，见第 8 步。
  3) 首次启动要装依赖 + 构建前端，手机上约 5-15 分钟，全程别息屏、别切走 Termux。
  4) 内存小于 3 GB 的机型构建前端很容易被系统杀掉，这不是脚本的问题，
     是安卓的内存管理如此。

【手机要求】
  · Android 7.0+（推荐 10 及以上）
  · 64 位处理器（arm64）。极老的 32 位机型 Termux 仓库里可能没有可用 Node
  · 内存 ≥ 3 GB（越大越稳）
  · 剩余存储 ≥ 3 GB
  · 稳定的 Wi-Fi

--------------------------------------------------------------------------------
第 1 步：安装 Termux（这一步选错后面全是坑）
--------------------------------------------------------------------------------
Termux 必须从下面两个地方之一下载：
  · F-Droid：https://f-droid.org/packages/com.termux/
  · GitHub Releases：https://github.com/termux/termux-app/releases
    （arm64 机型选文件名里带 arm64-v8a 的那个 apk）

  ▸ 不要装应用商店（Google Play）里那个 Termux
    那是很久不更新的旧版本，pkg 装东西会各种 404 / 版本冲突，
    官方已经不再维护 Play 版本。
  ▸ 已经装了 Play 版怎么办
    完全卸载后重新装 F-Droid 或 GitHub 版。两个来源签名不同，不能覆盖安装。
  ▸ 装完先原样打开一次
    第一次打开会自己初始化环境，等它出现 $ 提示符再操作。

--------------------------------------------------------------------------------
第 2 步：初始化 Termux 并装 Node.js
--------------------------------------------------------------------------------
在 Termux 里逐条执行（手机上打字麻烦，建议长按粘贴）：

       pkg update && pkg upgrade -y
       pkg install -y nodejs-lts git unzip
       node -v

  能看到 v22.x.x（≥ v20 就行）即可。

  ▸ pkg update 时提示 Unable to locate package / 全是 404
    原因：默认镜像不通（国内常见）。
    解决：执行  termux-change-repo  ，用音量键和回车选一个国内镜像
          （清华 TUNA、中科大 USTC 都可以），选完再 pkg update。

  ▸ E: Could not get lock / dpkg 被中断
    解决：按提示执行  apt --fix-broken install  ，或
          rm -f $PREFIX/var/lib/dpkg/lock* 后重试（谨慎，仅在确实卡死时用）。

  ▸ nodejs 和 nodejs-lts 冲突
    原因：这两个包提供同一个 node，装了一个再装另一个会冲突。
    解决：只留一个。想换的话先 pkg uninstall nodejs 再装 nodejs-lts。
          nodejs-lts 目前是 22.x，满足本项目 Node ≥ 20 的要求。

  ▸ 装完 node -v 提示 command not found
    解决：关掉 Termux（从后台划掉）重新打开。仍不行执行
          echo $PREFIX     # 应该是 /data/data/com.termux/files/usr
          ls $PREFIX/bin/node

--------------------------------------------------------------------------------
第 3 步：先做好「不被安卓杀掉」的设置（很关键）
--------------------------------------------------------------------------------
不做这一步，你会发现「息屏一会儿机器人就掉线了」。

1) 关掉 Termux 的电池优化
   手机设置 → 应用管理 → Termux → 电池 / 耗电管理
   选择「无限制 / 不受限制 / 允许后台高耗电」，关掉「省电策略」。
   国产系统里的说法各不相同，常见位置：
     小米/红米：设置 → 应用设置 → 应用管理 → Termux → 省电策略 → 无限制
     华为/荣耀：设置 → 电池 → 应用启动管理 → Termux → 手动管理，三项全开
     OPPO/一加/realme：设置 → 电池 → 应用耗电管理 → Termux → 允许后台运行
     vivo：设置 → 电池 → 后台高耗电 → 允许 Termux

2) 在 Termux 的通知里点一次「ACQUIRE WAKELOCK」
   从状态栏下拉找到 Termux 的常驻通知，点这个按钮，系统就不会轻易回收它。
   本项目的 start.sh 在 Termux 下也会自动申请 wake lock，看到这行就是成功了：
       [INFO] 已申请 termux-wake-lock（息屏后继续运行），退出本脚本时自动释放
   不想让它自动申请就加参数：bash start.sh nolock

  ▸ termux-wake-lock: command not found
    解决：pkg install -y termux-api
          并且从 F-Droid / GitHub 装一个 Termux:API 应用（要和 Termux 同来源）。
          没装也能跑，只是少了息屏保活，掉线概率变高。

3) Android 12 及以上还要关掉「幻影进程」清理（否则会莫名 Killed）
   安卓 12 起系统会统计 Termux 的子进程数，超过 32 个就直接杀。
   Node + npm 很容易超。两个办法：
     · 电脑上用 adb（一次性，重启手机后失效的机型请重复执行）：
         adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent"
         adb shell "/system/bin/device_config put activity_manager \
           max_phantom_processes 2147483647"
     · 或在开发者选项里找「后台进程限制」，设为「标准限制」而不是更严格的档位。
   症状对照：构建到一半整个进程组消失、终端只留一个 Killed，多半就是这个。

--------------------------------------------------------------------------------
第 4 步：把项目放到正确的位置
--------------------------------------------------------------------------------
必须放在 Termux 的家目录里，也就是 ~ （$HOME）下面：

       ~/kakake        # 实际路径是 /data/data/com.termux/files/home/kakake

  ▸ 绝对不能放在 /sdcard、/storage/emulated 这些共享存储里
    那里的文件系统没有可执行位、不支持符号链接，npm 安装和前端构建一定失败。
    项目已经做了拦截，放错位置启动时会直接告诉你：
       [ERROR] 项目在安卓共享存储里: /sdcard/kakake
               共享存储不支持可执行位与符号链接，npm 安装和前端构建一定失败。
               请搬到 Termux 家目录再启动：
                 cp -r "/sdcard/kakake" ~/kakake && cd ~/kakake && bash start.sh
    照着最后那条命令做就行。

从手机「下载」目录取压缩包的完整流程：

       termux-setup-storage        # 弹窗点「允许」，只需做一次
       cd ~
       unzip ~/storage/downloads/kakake.zip -d ~
       ls ~/kakake                 # 确认解压出来了

  ▸ termux-setup-storage 没有弹窗 / 执行后 ~/storage 是空的
    解决：手机设置 → 应用管理 → Termux → 权限 → 手动打开「存储」，再执行一次。

  ▸ unzip: command not found
    解决：pkg install -y unzip

--------------------------------------------------------------------------------
第 5 步：启动
--------------------------------------------------------------------------------
       cd ~/kakake
       bash start.sh

  手机上建议直接用 bash start.sh，不用 ./start.sh，可以绕过权限和换行符的问题。

  可选参数（可叠加）：
       bash start.sh force      强制重新构建前端界面
       bash start.sh verbose    保留全部安装/构建日志，构建失败时用它看原因
       bash start.sh nolock     不申请 termux-wake-lock（Termux 专用参数）

  ▸ bash: ./start.sh: Permission denied
    解决：chmod +x start.sh ，或者干脆用 bash start.sh

  ▸ bad interpreter: /usr/bin/env: no such file or directory
    原因：Termux 里没有 /usr/bin/env 这个路径（它在 $PREFIX/bin 下）。
    解决：bash start.sh

  ▸ 首次启动很慢是正常的
    脚本会依次做：装依赖 → 构建前端 → 打包后端。手机上 5-15 分钟很常见。
    这期间保持 Termux 在前台、屏幕别灭。想看进度就用 verbose。

  ▸ 项目自动做了两件手机专属处理，看到这些提示属正常
       [Kakake] Termux 环境 · PREFIX=/data/data/com.termux/files/usr
       ...  TMPDIR → /data/data/com.termux/files/usr/tmp
    安卓没有 /tmp，脚本会自己准备临时目录；
    内存小的机型还会自动给 Node 限定堆上限，用「构建慢一点」换「不被系统杀」。

--------------------------------------------------------------------------------
第 6 步：首次启动会看到什么
--------------------------------------------------------------------------------
     [Kakake] Termux 环境 · PREFIX=/data/data/com.termux/files/usr
     [Kakake] Installing backend dependencies (npm install)...
     ...
     咔咔珂 Kakake v0.4.15 启动中...
     运行环境: Termux · Android 14 · arm64 · Node 22.20.0 · Termux 0.118.0
     Termux 环境已识别 · PREFIX=/data/data/com.termux/files/usr
     建议先执行 termux-wake-lock，否则息屏后安卓可能杀掉后台进程

最后几行是关键信息：

     启动完成 · 后台控制台: http://127.0.0.1:8787（本机） /
                            http://192.168.1.37:8787（局域网）
     登录密钥 (初始): Xk3!qm7Yv2#tRb9Ldz4A
     快捷登录（本机）: http://127.0.0.1:8787/?key=Xk3!qm7Yv2#tRb9Ldz4A
     快捷登录（同一 Wi-Fi 局域网）: http://192.168.1.37:8787/?key=...
     会话：无互动 30 分钟退出 · 自登录起最长 3 小时 · 重启框架需重新登录

手机上不会显示「外网」地址，因为手机没有公网 IP，这是刻意省掉的，不是出错。

  ▸ 后台端口 xxx 小于 1024，安卓非 root 无法监听
    原因：改过 data/config.json 的 port，填了 80 之类的小端口。
    解决：改回 8787 或其他 1024 以上的端口。

--------------------------------------------------------------------------------
第 7 步：登录后台
--------------------------------------------------------------------------------
方式一（就在这台手机上看）：
  长按终端里的「快捷登录（本机）」链接 → 打开，或者自己在手机浏览器输入
       http://127.0.0.1:8787
  然后粘贴日志里的登录密钥。

方式二（用电脑操作，屏幕大好操作，推荐）：
  电脑和手机连同一个 Wi-Fi，电脑浏览器打开日志里那条「局域网」地址，例如
       http://192.168.1.37:8787

首次登录要同意协议并设置自己的密码，之后就用新密码登录。
密钥文件：~/kakake/data/auth-key.json

  ▸ 电脑打不开手机上的控制台
    ① 确认两台设备在同一个 Wi-Fi，且路由器没开 AP 隔离（访客网络常开着）
    ② 确认 data/config.json 里 host 是 0.0.0.0
    ③ 手机的局域网 IP 会变（重连 Wi-Fi、重启后），重新看一次启动日志里的地址
    ④ 手机连的是流量而不是 Wi-Fi 时，局域网地址不存在

  ▸ 忘记密码
    Ctrl+C 停掉 → rm ~/kakake/data/auth-key.json → 重新 bash start.sh，
    会生成新的初始密钥。

  ▸ 手机浏览器上控制台很挤
    控制台做了移动端适配，但功能多、信息密，能用电脑就用电脑。

--------------------------------------------------------------------------------
第 8 步：手机上怎么接 QQ（重点，和电脑/服务器不一样）
--------------------------------------------------------------------------------
再强调一次：手机上跑不了 NapCat。所以要让手机上的咔咔「主动去连」别处的协议端。

推荐做法 A：协议端在服务器或电脑上，手机主动连过去
  · 那台机器上先把 NapCat 跑起来，开好 WebSocket 服务器（正向 WS，比如 3001 端口）
  · 手机咔咔后台 → 连接 → 添加 → OneBot「正向 WS」
    地址填那台机器的 IP（同 Wi-Fi 就填 192.168.x.x，公网服务器填公网 IP），
    端口填 3001
  · 这样连接是手机主动发起的，手机没有公网 IP 也没关系

做法 B：同一 Wi-Fi 内，让电脑上的 NapCat 反向连手机
  · 手机咔咔里加 OneBot「反向 WS」，监听 6700
  · 电脑上 NapCat 的 WS 客户端填 ws://手机局域网IP:6700
  · 缺点：手机 IP 一变就断，需要在路由器里给手机绑定固定 IP

做法 C：微信 BOT
  · 扫码登录即可，不需要端口和域名，手机上最省事的一种，见 连接教程.txt。

不推荐在手机上折腾的：
  · QQ 开放平台官方机器人的 Webhook 需要公网 80/443/8080/8443 回调地址，
    手机做不到（除非自己套内网穿透，属于进阶折腾）。
  · 用 proot-distro 在手机里装 Debian 再跑 NapCat + arm64 版 QQ：理论可行，
    但内存和图形环境的坑很多，mk 不支持这条路，本文不展开。

各种对接方式的字段怎么填，看同目录 连接教程.txt。

第 9 步（可选）：在手机上用 mk 管理
--------------------------------------------------------------------------------
mk 2.6.0 起支持 Termux。手机上不需要 root、也不用 sudo：

       cd ~
       bash mk            # 首次运行即安装

  安装位置全都在 Termux 自己的目录下：
       脚本本体   $PREFIX/lib/mk-tools/mk
       全局命令   $PREFIX/bin/mk   （之后直接输入 mk 即可）
       日志目录   $PREFIX/var/log/mk-tools/

  手机上可用的菜单：
       [4] 咔咔操作      安装/启停咔咔、装 Node、构建 Web UI、看登录密钥
       [5] 端口验证      查端口占用（手机上没有 ss/netstat 也能查，走 /proc 兜底）
       [6] 构建 MK 源码
       [9] 开机自启      用 Termux:Boot 实现（安卓没有 systemd）

  手机上会被拦住的菜单（点了会告诉你原因）：
       [1] 宝塔  [2] NapCat  [3] snowLuma  [7] 实验功能  [10] 字体包
       这些都需要 root、systemd 或图形桌面，手机上没有。

  ▸ 「[4] 咔咔操作 → [9] 查看登录密钥」会标出地址来自哪张网卡
    面板里 ← 后面就是网卡名和类型：

         手机浏览器: http://127.0.0.1:8787
         同 Wi-Fi 其他设备: http://192.168.1.37:8787  ← wlan0（Wi-Fi）
         登录密钥: ...
         备选地址: http://10.51.22.7:8787  ← rmnet_data0（蜂窝数据）

    只有标着「Wi-Fi」「有线」「热点/USB 共享」的地址，同一局域网的电脑才连得上。
    若标的是「蜂窝数据」或「VPN」，mk 会直接给出警告 —— 说明手机当前没连 Wi-Fi，
    或者 VPN / 加速器把地址抢走了；连上 Wi-Fi、关掉 VPN 再看一次即可。
    手机上同时有多张网卡时，其余地址会列在「备选地址」里，可以逐个试。

  ▸ 咔咔操作里的「便携版」在手机上不能选
    便携版自带的是 x86_64 + glibc 的 Node，安卓是 arm64 + bionic，跑不起来。
    手机上只能装源码版，mk 会直接告诉你这一点。

  开机自启的前提（三个都要满足，缺一个就不会自启）：
    1) 装了 Termux:Boot 应用，且和 Termux 同一来源（F-Droid 或 GitHub）
    2) 装好后手动打开过一次 Termux:Boot（不打开它不会注册开机广播）
    3) 系统里把 Termux 和 Termux:Boot 的电池优化都关掉
  启用后 mk 会生成 ~/.termux/boot/20-kakake.sh，开机时自动申请 wake lock 并拉起咔咔。

--------------------------------------------------------------------------------
第 10 步：常见报错速查（Termux 专属）
--------------------------------------------------------------------------------
【被系统杀掉类】手机上最常见

  ▸ 终端只剩一个 Killed，进程没了
    原因：内存不足被杀，或安卓 12+ 的幻影进程清理。
    解决：① 先按第 3 步把电池优化、wake lock、幻影进程三件事都做了
          ② 清掉其他后台应用再构建
          ③ 构建阶段实在过不去，可以在电脑上构建好再把整个项目拷到手机
             （拷贝时连 packages 目录一起拷，手机上就不用再构建了）

  ▸ 息屏几分钟后机器人掉线，亮屏又好了
    原因：没拿 wake lock，或电池优化没关。
    解决：回到第 3 步。确认启动日志里有「已申请 termux-wake-lock」那行。

  ▸ 切到别的应用一会儿回来，Termux 重启了
    原因：系统内存回收激进（小内存机型常见）。
    解决：把 Termux 加入「锁定/加锁」的最近任务列表（各家系统在多任务界面长按），
          并减少后台应用。

【安装构建类】

  ▸ ENOENT: no such file or directory ... /tmp/...
    原因：安卓没有 /tmp。
    解决：正常情况脚本已自动设置 TMPDIR，如果你自己改过就恢复默认；
          手工修：export TMPDIR=$PREFIX/tmp && mkdir -p $TMPDIR

  ▸ EPERM / ENOTSUP / operation not permitted，且路径里带 /sdcard
    原因：项目放在共享存储里。
    解决：搬到 ~/kakake（见第 4 步）。

  ▸ npm install 卡住或反复超时
    解决：脚本在 Termux 下已经关掉 audit/fund 并把并发降到 8。
          还是不行就换网络（移动网络切 Wi-Fi），或指定源：
            KAKAKE_NPM_REGISTRY=https://registry.npmmirror.com bash start.sh

  ▸ JavaScript heap out of memory
    解决：脚本已按内存自动限堆；仍失败就关后台应用重试，或按上面的办法
          在电脑上构建好再拷过来。

  ▸ 存储空间不足 / No space left on device
    解决：df -h $HOME 看剩余空间。node_modules 加构建产物大约要 1.5-2 GB。

【mk 与权限类】

  ▸ No 'su' binary found
    sudo requires a 'su' binary that supports the '-c' ... options
    原因：手机没有 root。Termux 的 sudo/tsu 只是去调用系统的 su，未 root 的机器
          上根本没有 su，所以 sudo 会在 mk 还没开始跑之前就直接失败。
    解决：把 sudo 去掉就行，mk 2.6.0 在 Termux 下不需要 root：
            cd ~
            bash mk
          （不要去装 tsu、也不要试着改 sudo，未 root 的手机上没有任何办法提权。
            mk 的安装目录全在 $PREFIX 下，本来就属于你自己，不需要提权。）

  ▸ 下载下来的文件名是 mk.sh，会不会有问题？
    不会。bash mk.sh 一样能装，mk 安装时会统一改名成 $PREFIX/bin/mk。
    想省事可以下载时就存成 mk：curl -fsSL -o mk "…/mkbot/mk" && bash mk

  ▸ 装完之后输入 mk 提示 command not found
    解决：新开一个 Termux 会话（左侧右滑 → NEW SESSION），或执行 hash -r。

  ▸ 菜单里 [1] 宝塔 / [2] NapCat / [3] snowLuma / [7] 实验功能 / [10] 字体包 点不动
    这不是报错。这些功能要 root、systemd 或图形桌面，手机上没有，mk 会主动拦住
    并说明原因。手机上能用的是 [4] [5] [6] [9]。

【端口与网络类】

  ▸ 端口 8787 已被占用
    手机上一般没有 ss / netstat，可以直接查内核表：
      cat /proc/net/tcp | awk '{print $2}' | grep -i ':2253'
      （2253 是 8787 的十六进制。用 mk 的 [5] 端口验证会自动帮你换算。）
    最省事的做法：把 Termux 从后台划掉重开，再启动。

  ▸ ss: command not found / netstat: command not found
    解决：pkg install -y iproute2 net-tools（可选，mk 没有它们也能查）。

  ▸ 没有权限监听端口 xxx（EACCES）
    原因：端口 < 1024，安卓非 root 不允许。
    解决：改 data/config.json 的 port 为 8787 之类的高位端口。

  ▸ 同一个 Wi-Fi 下，别的设备打不开手机给出的登录地址
    先看启动日志里那行「快捷登录（同一 Wi-Fi 局域网 · wlan0/Wi-Fi）」，
    括号里是这个地址所属的网卡；用 mk 管理的话，
    「[4] 咔咔操作 → [9] 查看登录密钥」里 ← 后面标的也是同一个信息。
    按下面的顺序排查：

    1) 括号里不是 wlan0/Wi-Fi，而是「蜂窝数据」或「VPN」
       运营商给蜂窝分配的常常也是 10.x 私网地址，看着像内网，但局域网里
       根本连不到它。把蜂窝数据和 VPN 关掉、只留 Wi-Fi，重启咔咔再看。
       日志里若还列出了「本机还有其它内网地址」，可以逐个试。

    2) 地址确实来自 Wi-Fi，但还是连不上 —— 大概率是路由器的「AP 隔离」
       也叫客户端隔离、AP isolation。开启后同一 Wi-Fi 下的设备互相不通，
       访客网络几乎默认都开着。
       验证：用另一台设备 ping 手机那个 IP，不通就是被隔离了。
       解决：进路由器后台关掉 AP 隔离 / 客户端隔离；或者两台设备都别接访客网络。

    3) 两台设备其实不在同一网段
       路由器把 2.4G 与 5G 拆成两个 SSID、或者 Mesh/子路由又做了一层 NAT 时会这样。
       对比两边 IP 的前三段，不一致就说明不同网段，改连同一个 SSID 再试。

    4) 确认监听地址是 0.0.0.0
       看 data/config.json 里的 host，必须是 0.0.0.0；填 127.0.0.1 时
       只有手机自己能访问。

    5) 一开始能连，息屏一会儿就不行了
       这是安卓省电把进程杀了，不是网络问题，见本节前面的「被系统杀掉类」。

    补充：安卓本身不会阻止别的设备连进来，Termux 监听 8787 这类高位端口
          也不需要任何额外授权，所以问题基本都出在第 1、2 条。

【面板数据类】

  ▸ 面板上 CPU 核心数偏少，甚至只显示 1 核
    这不是取错了，是安卓为省电把空闲的核热插拔下线了。
    咔咔现在读的是内核里那份不受在线状态影响的清单
    （/sys/devices/system/cpu/present），显示的是真实核心数；
    当在线核数少于总核数时，会额外标出「在线 N」，比如「8 核（在线 2）」。
    这个在线数会随负载上下浮动，属正常现象。

  ▸ 面板上看不到手机的完整硬件信息
    安卓不允许普通应用读取其他应用的进程、也不开放部分传感器与硬件节点。
    能拿到的：芯片型号（Android 12+ 起系统必须提供）、真实核心数、最高主频、
              内存总量与可用量、项目所在分区的容量、本进程自身的 CPU 与内存占用。
    拿不到的：整机 CPU 总占用率、电池与温度、其他 App 的进程和内存。
    这些限制来自安卓本身，不 root 没有办法绕过。

  ▸ 内存显示的占用比手机设置里看到的低/高
    咔咔用的是内核给的 MemAvailable（不触发换页就能拿到的内存），
    而不是「完全空闲」的内存——安卓会主动把空闲内存拿去做文件缓存，
    只看完全空闲的话会常年显示 90% 以上占用，没有参考价值。
    另外总量会比宣传的容量小一些，因为内核和基带预留了一部分，属正常。

第 11 步：日常怎么用
--------------------------------------------------------------------------------
启动    cd ~/kakake && bash start.sh
停止    Ctrl+C（音量减 + C 也可以，Termux 键盘上有 CTRL 键）
后台跑  先在通知里点 ACQUIRE WAKELOCK，然后可以切到别的应用，别划掉 Termux
更新    覆盖新版源码后 bash start.sh force
重置产物 rm -rf packages 再启动，会自动重建
用 mk   mk → [4] 咔咔操作 → [5]/[6]/[7] 启动/停止/重启

备份（重要，手机随时可能出问题）：
       cp -r ~/kakake/data ~/storage/downloads/kakake-data-backup
       cp -r ~/kakake/plugins ~/storage/downloads/kakake-plugins-backup
  备份到共享存储只是为了方便你导出，运行时的项目本体仍必须在 ~ 里。

想同时开多个终端：Termux 左侧边缘右滑 → NEW SESSION，一个跑咔咔一个敲命令。

【Termux 路径】
  $PREFIX                     /data/data/com.termux/files/usr
  $HOME                       /data/data/com.termux/files/home
  共享存储入口                ~/storage/shared、~/storage/downloads
                              （需先跑 termux-setup-storage）
  临时目录                    $PREFIX/tmp（脚本会自动设成 TMPDIR）

【咔咔目录】
  ~/kakake/data/              配置与运行数据（config.json、auth-key.json…）
  ~/kakake/log/               运行日志
  ~/kakake/plugins/           插件
  ~/kakake/packages/          构建产物，可整夹删除、自动重建

【mk 在手机上的路径】
  $PREFIX/lib/mk-tools/       脚本与相关文件
  $PREFIX/bin/mk              全局命令
  $PREFIX/var/log/mk-tools/   日志
  ~/.termux/boot/20-kakake.sh 开机自启脚本（启用自启后才有）

【data/config.json 常改项】
  "host": "0.0.0.0"       监听地址，想让电脑访问就保持这个
  "port": 8787            必须 ≥ 1024
  "logLevel": "info"      排查问题可改 debug
  "apiTimeoutMs": 120000  调用协议端接口的超时（毫秒）

【环境变量开关】
  KAKAKE_FORCE_WEB_BUILD=1    等价于 force
  KAKAKE_VERBOSE_BOOT=1       等价于 verbose
  KAKAKE_NPM_REGISTRY=...     指定 npm 源
  KAKAKE_BOOTSTRAP_DRY_RUN=1  只检查依赖和构建，不启动服务
  KAKAKE_NO_WEB=1             不托管 Web 控制台，只跑后端（省内存）
  用法示例：KAKAKE_VERBOSE_BOOT=1 bash start.sh
