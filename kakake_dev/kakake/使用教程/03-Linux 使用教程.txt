================================================================================
  咔咔珂 Kakake · Linux 使用教程（从零到能聊天）
  适用: 主流 x86_64 / arm64 发行版（Debian 11+、Ubuntu 20.04+、CentOS Stream 9、
        Rocky/Alma 8+、Fedora、Arch 等）
  两条路线: mk 一键脚本（推荐服务器）或 手动 ./start.sh
================================================================================

【先说清楚三件事】
  1) 咔咔珂本身不带 QQ 登录能力，它只是「机器人框架」。
     真正登录 QQ 的是 NapCat / SnowLuma 之类的协议端，两者通过 WebSocket 对接。
  2) Linux 上有两种用法，任选其一：
       路线 A：用 mk 脚本（当前版本 2.6.0）。装 NapCat、装 Node、启停咔咔、
               开机自启、端口排查都在菜单里点，适合服务器，也适合新手。
       路线 B：手动 ./start.sh。适合自己已经装好 Node、只想跑框架的人。
  3) 首次启动要装依赖 + 构建前端，视网络和机器 3-20 分钟；之后启动只要几秒。

【机器要求】
  · CPU 架构 x86_64 或 arm64
  · 内存 ≥ 1 GB（512 MB 也能跑，但前端构建大概率 OOM，必须加 swap，见第 7 步）
  · 硬盘剩余 ≥ 3 GB
  · glibc ≥ 2.28（官方 Node 20+ 的硬性要求）
  · Node.js 20+（没有的话 mk 能帮你装，或自己装）

【先确认发行版够不够新】
       ldd --version        # 看 glibc 版本，要 ≥ 2.28
     常见对照：
       Debian 10 / Ubuntu 18.04 / CentOS 7 → glibc 2.17~2.28，官方 Node 20+ 跑不起来
       Debian 11+ / Ubuntu 20.04+ / Rocky 8+ → 没问题
     CentOS 7 上强行装会报：
       node: /lib64/libm.so.6: version `GLIBC_2.27' not found
     这个报错没有便捷解法，请换发行版或换机器。

--------------------------------------------------------------------------------
路线 A：用 mk 脚本（推荐）
--------------------------------------------------------------------------------
第 A1 步：把仓库里的 mk 文件传到服务器，然后安装

       cd ~                       # mk 文件放哪都行
       sudo bash mk               # 首次运行即安装；等价于 sudo bash mk --install

  安装完成后：
       脚本本体   /usr/local/lib/mk-tools/mk
       全局命令   mk（软链在 /usr/local/bin/mk，输入 MK / Mk 也认）
       日志目录   /var/log/mk-tools/

第 A2 步：打开菜单

       sudo mk

  主菜单：[1] 宝塔 [2] NapCat [3] snowLuma [4] 咔咔操作 [5] 端口验证
          [6] 构建 MK 源码 [7] 实验功能 [8] 卸载 mk [9] 开机自启 [10] 字体包 [0] 退出

第 A3 步：装协议端（以 NapCat 为例）
       主菜单 [2] NapCat操作 → [2] 安装框架-后台安装 → 选版本/镜像
       装完 → [3] 启动框架 → [9] 查看面板登录密钥
       浏览器打开 http://服务器IP:6099/webui 用密钥登录，扫码登上 QQ

第 A4 步：装并启动咔咔
       主菜单 [4] 咔咔操作
         · 菜单顶部会显示「安装形态: 源码版 / 便携版」和 Node 状态
         · [2] 安装咔咔     → 会问你要源码版还是便携版
              源码版：下载 kakake.zip，需要 Node，启动前会构建前端
              便携版：下载 kakake-linux-x64.zip，自带 Node 和已构建产物，
                      不用装 Node、不用构建，最省事
         · [3] 安装 Node.js → 只有源码版且本机没 Node 时才需要
                              （装到 mk 私有目录，不污染系统）
         · [5] 启动咔咔
         · [9] 查看登录密钥 → 浏览器进 http://服务器IP:8787
         · [10] 构建 Web UI → 界面没更新时用
       重装咔咔会保留 data/ 和 plugins/，不会丢配置和插件。

第 A5 步：开机自启
       主菜单 [9] 开机自启 → 分别可为 NapCat 和咔咔写入 systemd 服务
       咔咔的服务名是 mk-kakake.service，也可以直接用 systemctl 管：
       systemctl status mk-kakake     查看状态
       journalctl -u mk-kakake -f     实时看日志

第 A6 步：端口被占用时
       主菜单 [5] 端口验证 → 输入 8787 或 6700，能看到占用进程并选择杀掉

  ▸ 群里发的图片全是方块 / 插件截图乱码
    原因：服务器没装中文字体。
    解决：主菜单 [10] 字体包操作 → 先 [2] 扫描，再按网络情况选 [3]/[4]/[5]/[6]。

mk 的完整菜单说明见同目录 MK工具教程.txt。

路线 B：手动用 start.sh
--------------------------------------------------------------------------------
第 B1 步：装 Node.js 20+

  Debian / Ubuntu：
       curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
       sudo apt install -y nodejs
  RHEL 系（Rocky / Alma / CentOS Stream）：
       curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo -E bash -
       sudo dnf install -y nodejs
  Arch：
       sudo pacman -S nodejs npm
  不想动系统包管理器（推荐，装在自己家目录，不用 sudo）：
       curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
       source ~/.bashrc && nvm install 22

  验证：
       node -v      # 要 ≥ v20
       npm -v

  ▸ apt/dnf 装完 node -v 还是 v12/v18
    原因：系统源里的 Node 太旧，或装了多个。
    解决：用上面 NodeSource 的脚本，或改用 nvm。
          which -a node 可以看到到底有几个。

第 B2 步：放项目并启动

       # 建议放家目录
       cd ~
       unzip kakake.zip -d ~/       # 或 git clone / scp 上传
       cd ~/kakake
       chmod +x start.sh
       ./start.sh

  可选参数（可叠加）：
       ./start.sh force      强制重新构建前端界面
       ./start.sh verbose    保留全部安装/构建日志，排查失败时用
       ./start.sh nolock     Termux 专用，Linux 上写了没作用

  ▸ bash: ./start.sh: Permission denied
    解决：chmod +x start.sh   或直接 bash start.sh

  ▸ bash: ./start.sh: /usr/bin/env: bad interpreter: No such file or directory
    原因：文件被改成 Windows 换行（CRLF）。
    解决：sed -i 's/\r$//' start.sh
          （本仓库用 .gitattributes 强制脚本为 LF，正常不会遇到）

  ▸ unzip: command not found
    解决：sudo apt install unzip   /   sudo dnf install unzip

  ▸ 千万不要 sudo ./start.sh
    那会把 node_modules 和 data 的属主变成 root，之后普通用户读写都报 EACCES。
    已经发生了就：sudo chown -R $(whoami):$(whoami) ~/kakake

第 4 步：首次启动会看到什么（两条路线一样）
--------------------------------------------------------------------------------
     [Kakake] Installing backend dependencies (npm install)...
     ...（装依赖、构建前端、打包后端）
     咔咔珂 Kakake v0.4.15 启动中...
     运行环境: Linux 5.15.0-119-generic · x64 · Node 22.20.0

最后几行是关键信息：

     启动完成 · 后台控制台: http://127.0.0.1:8787（本机） /
                            http://10.0.0.5:8787（局域网） /
                            http://203.0.113.20:8787（外网）
     登录密钥 (初始): Xk3!qm7Yv2#tRb9Ldz4A
     快捷登录（本机）: http://127.0.0.1:8787/?key=Xk3!qm7Yv2#tRb9Ldz4A
     快捷登录（公网）: http://203.0.113.20:8787/?key=...
     会话：无互动 30 分钟退出 · 自登录起最长 3 小时 · 重启框架需重新登录

服务器上就用「公网」那条地址在自己电脑的浏览器里打开。
如果外网地址显示成 <服务器IP>，说明网卡上看不到公网 IP（NAT / 弹性公网 IP 常见），
框架会再向云厂商元数据接口问一次，稍等几秒可能补打一条；
也可以自己指定：KAKAKE_PUBLIC_HOST=你的公网IP ./start.sh

  ▸ 用 ./start.sh 起的服务，SSH 一断开就没了
    原因：进程是 SSH 会话的子进程。
    解决：用 mk 的 [5] 启动咔咔（它自己转后台），或者用 screen / tmux：
            sudo apt install -y tmux
            tmux new -s kakake
            cd ~/kakake && ./start.sh
            # Ctrl+B 松手再按 D 退出，进程继续跑
            tmux attach -t kakake        # 回来看日志
    也可以 nohup ./start.sh > log/boot.log 2>&1 &

第 5 步：登录后台
--------------------------------------------------------------------------------
1) 把「快捷登录」那条完整链接复制到浏览器，会自动带密钥登录。
2) 或打开 http://服务器IP:8787 手动粘贴密钥。
3) 首次登录要同意协议并设置自己的密码，之后用新密码登录。

密钥存放位置：~/kakake/data/auth-key.json
用 mk 的话直接 [4] 咔咔操作 → [9] 查看登录密钥。

  ▸ 浏览器一直转圈 / 连接超时（本机 curl 却正常）
    先在服务器上自测：
      curl -I http://127.0.0.1:8787
    能返回 HTTP 头说明框架没问题，问题在网络层，按下面顺序查：
      ① 云厂商安全组 / 防火墙规则有没有放行 8787（阿里云、腾讯云、AWS 都要单独配）
      ② 系统防火墙：
         ufw：      sudo ufw allow 8787/tcp && sudo ufw reload
         firewalld：sudo firewall-cmd --permanent --add-port=8787/tcp
                    sudo firewall-cmd --reload
      ③ data/config.json 里 host 是不是 0.0.0.0（写成 127.0.0.1 就只能本机访问）

  ▸ 忘记密码
    停掉服务 → rm ~/kakake/data/auth-key.json → 重启，会生成新的初始密钥。

  ▸ 提示需要重新登录
    设计如此：闲置 30 分钟、登录满 3 小时、框架重启，都要重新登录。

第 6 步：接上 QQ
--------------------------------------------------------------------------------
同一台服务器上跑 NapCat + 咔咔，最省事的是「反向 WebSocket」：
  · 咔咔后台 → 连接 → 添加 → OneBot「反向 WS」，监听 0.0.0.0:6700
  · NapCat WebUI → 网络配置 → 添加 WebSocket 客户端 → ws://127.0.0.1:6700
  · 两边都启用，咔咔的连接卡片变「已连接」即成功

NapCat 跑在 Docker 里时不能填 127.0.0.1（那是容器自己），要填宿主机地址：
  ws://172.17.0.1:6700    （172.17.0.1 是默认 docker0 网桥地址）

详细步骤和另外四种对接方式（正向 WS / HTTP 服务器 / HTTP SSE / HTTP 客户端）
见同目录 连接教程.txt。

  ▸ 8787 和 6700 是两个不同的东西
    8787 = 咔咔后台控制台端口（data/config.json 的 port）
    6700 = 反向 WS 监听端口（后台连接里配）
    反向 WS 的端口不需要对公网开放，只在服务器内部用。

第 7 步：常见报错速查（Linux）
--------------------------------------------------------------------------------
【内存不足类】这是小内存 VPS 上最常见的问题

  ▸ 构建卡住后进程凭空消失，或报 Killed / JavaScript heap out of memory
    原因：前端构建（Vite/Rollup）内存峰值高，被内核 OOM Killer 杀了。
    确认：dmesg -T | grep -i -E 'killed process|out of memory' | tail
    解决办法（按推荐顺序）：
      ① 加 swap（1 GB 内存的机器建议给 2 GB swap）：
           sudo fallocate -l 2G /swapfile
           sudo chmod 600 /swapfile
           sudo mkswap /swapfile
           sudo swapon /swapfile
           echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
         free -h 能看到 Swap 那行有值即生效。
      ② 用 mk 装「便携版」，它自带已构建好的前端，完全不需要在本机构建。
      ③ 临时限堆：NODE_OPTIONS=--max-old-space-size=1024 ./start.sh force
    脚本对 4 GB 及以下内存的机器会自动限堆，但 512 MB 无 swap 仍会失败。

【依赖安装类】

  ▸ npm install exited with code 1 / ECONNRESET / ETIMEDOUT
    解决：脚本已默认用 https://registry.npmmirror.com。仍失败可换官方源：
            KAKAKE_NPM_REGISTRY=https://registry.npmjs.org ./start.sh
          国外机器建议直接用官方源，国内镜像反而慢。

  ▸ 404 Not Found - GET https://nodejs.org/dist/...
    原因：npm 的 registry 被设成了 Node 二进制镜像地址（宝塔环境常见）。
    解决：脚本会自动纠正并打印「npm registry → ...」；仍失败就
          npm config delete registry 后重来。

  ▸ tsx not found after npm install. Delete node_modules and retry.
    解决：rm -rf node_modules && ./start.sh

  ▸ EACCES: permission denied
    原因：之前用 sudo 跑过，文件属主变成了 root。
    解决：sudo chown -R $(whoami):$(whoami) ~/kakake

  ▸ EMFILE: too many open files
    解决：ulimit -n 4096（当前会话生效）；长期改 /etc/security/limits.conf。

【启动与端口类】

  ▸ 端口 8787 已被占用：先停掉占用它的进程，或改 data/config.json 里的 port
    查占用：
      ss -tlnp | grep 8787
      # 没有 ss 就用 netstat（需 net-tools）或直接读 /proc
      netstat -tlnp | grep 8787
    确认不是自己上次没关干净的咔咔后再 kill；或换端口（改 config.json 的 port）。
    用 mk 的话：主菜单 [5] 端口验证，能查能杀。

  ▸ 没有权限监听端口 xxx（EACCES）
    原因：端口 < 1024，普通用户不能监听。
    解决：改成 8787 之类的高位端口。真要用 80/443 就在前面加 Nginx 反代。

  ▸ 监听地址 xxx 在本机不存在：改回 0.0.0.0 即可
    原因：config.json 的 host 写成了本机没有的 IP（比如写了公网 IP，
          但云服务器网卡上其实只有内网 IP）。

  ▸ 日志里出现 fetch failed
    原因：多数是同时存在 IPv4 和不通的 IPv6，Node 先试了 IPv6。
    解决：KAKAKE_DNS_RESULT_ORDER=ipv4first 启动试一下，确认是这个原因后
          再从系统层面处理（关 IPv6 或修好它）。

  ▸ 想用域名 + HTTPS 访问控制台
    在服务器上装 Nginx 做反代即可，咔咔本身只提供 HTTP。
    反代要记得转发 WebSocket 相关的 Upgrade / Connection 头，
    否则控制台的实时日志和连接状态会不刷新。

【mk 相关】

  ▸ 此操作需要 root 权限，请使用: sudo mk
    解决：加 sudo。mk 要写 /usr/local 和 /var/log，普通用户没权限。

  ▸ mk: command not found
    原因：还没安装到系统。
    解决：sudo bash mk 先装一次。

  ▸ 菜单里显示「Node.js 未安装」但我明明装了
    原因：mk 的检测顺序是 mk 私有 Node → PATH 里的 node → 常见路径。
          用 nvm 装的 Node 在 sudo 环境下 PATH 里可能看不到。
    解决：要么在 mk 菜单里 [3] 装一份私有 Node，要么装成系统级（NodeSource）。

  ▸ 「该功能仅限 Linux 服务器」
    这是在手机 Termux 里才会出现的提示，服务器上不会看到。

第 8 步：日常怎么用
--------------------------------------------------------------------------------
用 mk：
  启动/停止/重启   主菜单 [4] → [5]/[6]/[7]
  看运行日志       tail -f /var/log/mk-tools/kakake-runtime.log
  开机自启         主菜单 [9]（systemd 服务 mk-kakake.service）

手动：
  启动    cd ~/kakake && ./start.sh   （建议放进 tmux）
  停止    Ctrl+C，或 pkill -f packages/server/main.mjs
  更新    覆盖新版源码后 ./start.sh force
  重置产物 rm -rf packages 再启动，会自动重建（纯产物目录，不含数据）
  备份    只需备份 ~/kakake/data 和 ~/kakake/plugins

自己写一个 systemd 服务（不想用 mk 时）。
下面整段可以直接复制粘贴执行，注意 EOF 那行必须顶格，不能带空格：

sudo tee /etc/systemd/system/kakake.service >/dev/null <<'EOF'
[Unit]
Description=Kakake Bot
After=network-online.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/home/你的用户名/kakake
ExecStart=/usr/bin/node scripts/bootstrap.mjs
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

粘完之后依次执行：
  sudo systemctl daemon-reload
  sudo systemctl enable --now kakake
  systemctl status kakake
  journalctl -u kakake -f

  ▸ 记得把 User 和 WorkingDirectory 里的「你的用户名」换成实际用户名。
  ▸ ExecStart 里的 node 路径要用 which node 查到的实际路径。
    nvm 装的 Node 形如 /home/你的用户名/.nvm/versions/node/v22.20.0/bin/node，
    而且 nvm 的路径不在 systemd 的默认 PATH 里，必须写绝对路径。
  ▸ 第一次务必先手动 ./start.sh 成功跑通再交给 systemd。
    首次启动要装依赖和构建，扔后台不方便看报错。
  ▸ 报 Job for kakake.service failed 时看 journalctl -u kakake -n 50 的输出，
    十有八九是 node 路径或 WorkingDirectory 写错了。

附：目录与开关速查
--------------------------------------------------------------------------------
【咔咔目录】
  ~/kakake/data/        配置与运行数据（config.json、auth-key.json、connections.json…）
  ~/kakake/log/         运行日志
  ~/kakake/plugins/     安装的插件
  ~/kakake/plugins_two/ 按账号隔离的插件运行副本
  ~/kakake/packages/    构建产物，可整夹删除、自动重建

【mk 目录】
  /usr/local/lib/mk-tools/            脚本与私有 Node
  /usr/local/bin/mk                   全局命令
  /var/log/mk-tools/                  各类日志
  /var/log/mk-tools/kakake-runtime.log 咔咔运行日志
  /usr/share/fonts/mk-cjk/            mk 装的中文字体

【data/config.json 常改项】
  "host": "0.0.0.0"       监听地址，一般不用改
  "port": 8787            后台端口
  "logLevel": "info"      排查问题可改 debug
  "apiTimeoutMs": 120000  调用协议端接口的超时（毫秒）

【环境变量开关】
  KAKAKE_FORCE_WEB_BUILD=1    等价于 ./start.sh force
  KAKAKE_VERBOSE_BOOT=1       等价于 ./start.sh verbose
  KAKAKE_NPM_REGISTRY=...     指定 npm 源
  KAKAKE_BOOTSTRAP_DRY_RUN=1  只检查依赖和构建，不启动服务
  KAKAKE_NO_WEB=1             不托管 Web 控制台（只跑后端）
  KAKAKE_PUBLIC_HOST=...      手动指定公网 IP/域名
  KAKAKE_DNS_RESULT_ORDER=ipv4first   出现 fetch failed 时可试
