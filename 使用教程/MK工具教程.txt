================================================================================
  MK 工具使用教程（Linux 服务器 / Termux 安卓手机）
  脚本：仓库根目录 mk（安装后全局命令也叫 mk）
  当前文档对应脚本版本：2.7.7
================================================================================

【这是干什么的】
mk 是一键管理脚本，交互菜单里可以：
  · 装/管宝塔
  · 装/启停 NapCat（QQ）
  · 装/启停 SnowLuma（Docker 或直接安装）、装兼容 QQ
  · 装/启停咔咔珂、装 Node、构建 Web UI
  · 查端口占用、构建 MK 插件源码、NapCat 实验魔改、开机自启
  · 检测/安装中文字体包（软件源、国内代理镜像、本地文件）

【适用环境】
  · Linux 服务器（需 bash；多数操作要 root / sudo）→ 全部功能可用
  · Termux（安卓手机，2.6.0 起支持）→ 免 root，但只有部分功能可用，见下方说明
  · 不是 Windows 本机用的；Windows 请用仓库里的 start.bat 起咔咔
  · 咔咔支持两种形态（mk 会自动识别；安装时可二选一）：
      源码版：下载 kakake.zip，含 scripts/bootstrap.mjs，启动前可构建 Web，可用 mk 私有/系统 Node
      便携版：下载 kakake-linux-x64.zip，含 runtime/bin/node + packages/server/main.mjs，无需再装 Node、无需构建 Web
        解压后统一装到 ~/kakake（zip 内目录名可以是 kakake 或 kakake-linux-x64）
        手动部署时把 kakake-linux-x64 目录内容放到 ~/kakake 亦可
        便携版仅限 x86_64 + glibc，安卓（arm64 + bionic）不可用，手机上只能装源码版

【Termux（安卓手机）差异一览】
  可用：[4] 咔咔操作、[5] 端口验证、[6] 构建 MK 源码、[9] 开机自启、[8] 卸载 mk、[10] 字体包（仅检测）
  拦截：[1] 宝塔、[2] NapCat、[3] snowLuma、[7] 实验功能、[12] Docker
        （这些依赖 root / systemd / X11 桌面，手机上没有；点进去会说明原因并返回）
        [10] 字体包在手机上改为「仅检测不安装」：读 /system/fonts、$PREFIX/share/fonts
             等目录，用 fc-list（装了 fontconfig 时）报告是否已有中文字体；不写系统目录、
             不下载/安装字体、也不需要 root。安装字体仍请在电脑/服务器上做。
  路径：安装目录改挂到 $PREFIX 下，不写 /usr/local 与 /var/log
          脚本本体  $PREFIX/lib/mk-tools/mk
          全局命令  $PREFIX/bin/mk
          日志目录  $PREFIX/var/log/mk-tools/
  权限：无需 root，也不要加 sudo（Termux 里本来就没有）
  Node：走 pkg install nodejs-lts（当前为 22.x），而不是下载官方二进制
  自启：安卓没有 systemd，改用 Termux:Boot，脚本写在 ~/.termux/boot/20-kakake.sh
  临时目录：安卓没有 /tmp，统一走 $PREFIX/tmp
  端口查询：手机上常缺 ss / netstat，[5] 端口验证会自动改读 /proc/net/tcp
  手机完整部署步骤见《04-Termux 安卓手机 使用教程.txt》

--------------------------------------------------------------------------------
一、安装 / 更新 mk
--------------------------------------------------------------------------------
把仓库里的 mk 文件拷到服务器后（或用已有路径）：

  # 首次安装或强制更新到系统（需要 root）
  sudo bash mk
  # 或
  sudo bash mk --install

  # Termux（安卓手机）：不要加 sudo
  bash mk

安装完成后（Linux）：
  · 脚本本体：/usr/local/lib/mk-tools/mk
  · 全局命令：mk  （软链到 /usr/local/bin/mk）
  · 日志目录：/var/log/mk-tools/

日常打开菜单（已装过全局命令时）：

  sudo mk
  # 或
  mk

常用参数：
  mk --version / -v     查看版本
  mk --help / -h        用法说明
  mk --check / -c       语法检查
  mk --install / -i     强制重装/更新
  mk --uninstall / -u   卸载 mk 工具本身（不自动卸 NapCat/咔咔，见菜单）

三、推荐上手流程（服务器上从零到可聊）
--------------------------------------------------------------------------------
1) sudo bash mk 安装 mk（若尚未安装）
2) 主菜单 → [2] NapCat → [2] 安装框架（后台装，可看进度）
3) NapCat 装完 → [3] 启动 → [9] 看面板登录密钥，浏览器进 NapCat WebUI 扫码
4) 主菜单 → [4] 咔咔操作
     · 菜单会显示「安装形态: 源码版 / 便携版」
     · 便携版：Node 显示「便携内置」，可直接 [5] 启动；无需 [3] 装 Node、无需 [10] 构建 Web
     · 源码版：若提示没有 Node，可 [3] 安装 Node.js（mk 私有一份）
       若本机已有全局 Node，菜单会显示「系统全局」，一般可直接用，不必再装
     · [2] 安装咔咔 → 会询问源码版 / 便携版 → [5] 启动咔咔
       （源码版未构建 Web 时启动会先构建；便携版可直接启动）
     · 重装仍保留 data/ 与 plugins/
     · [9] 查看登录密钥 → 浏览器打开控制台（默认端口 8787）
5) 按《连接教程.txt》把 NapCat / SnowLuma 与咔咔连上（推荐本机反向 WS）
6) 端口冲突：主菜单 → [5] 端口验证
7) 中文方块/截图乱码：主菜单 → [10] 字体包操作 → 先 [2] 扫描，再按网络情况安装

四-B、snowLuma 菜单（主菜单 [3]）
--------------------------------------------------------------------------------
  [2] 安装 SnowLuma       可选 Docker 安装 / 直接安装（解压发行包）
  [3] 卸载 SnowLuma
  [4] 安装 QQ             按架构与已装 SnowLuma 版本列出兼容下载地址并可安装
  [5] 启动 QQ             常规模式会同时拉起 Xvfb+VNC+noVNC 扫码桌面
  [6] 停止 QQ             常规模式一并停扫码桌面
  [7] 彻底杀死 QQ         强杀 /opt/QQ 进程树并短时压制自动拉起（不关 VNC）
  [8] 卸载 QQ             卸宿主 linuxqq（/opt/QQ）
  [9] 启动 SnowLuma
  [10] 停止 SnowLuma
  [11] 重启 SnowLuma
  [12] 查看日志
  [13] 查看 WebUI 登录信息
  [14] 查看扫码地址       noVNC / VNC 端口与密码
  [15] 仅启动远程查看
  [16] 仅停止远程查看     不影响 QQ
  [17] 配置扫码端口/密码  noVNC/VNC 均可改（默认 6081/5900）
  [18] WebUI 监听地址/外部访问  直接安装版 WebUI 只绑 127.0.0.1 时，一键开放外部访问

说明：
  · Docker：镜像 motricseven7/snowluma:latest，内置 QQ + noVNC（默认 6081）+ WebUI（5099）
    mk 起容器时已带 SNOWLUMA_WEBUI_HOST=0.0.0.0（WebUI 对外）、SNOWLUMA_QQ_FLAGS（关 GPU 防泄漏）、
    --ulimit nofile 抬高句柄上限；数据卷 snowluma-data 挂到 /app/data（SnowLuma 配置/onebot.json/
    runtime.json 都在这），另两卷 /app/.config、/app/.local/share 存 QQ 客户端配置与登录态
  · 直接安装：解压到 /opt/SnowLuma；「启动 QQ」会装并启动 Docker 同款扫码栈
    （Xvfb :99 + openbox/fluxbox + x11vnc + noVNC；默认端口 5900/6081）
  · 扫码密码（noVNC/VNC）：官方镜像会把 vncpasswd 这类公开示例值当作未设置并改用随机密码，
    所以 mk 装 Docker 时会自动生成一个随机强密码（形如 snow-xxxx）作为 VNC_PASSWD，并在 [13]
    登录信息里显示实际生效的密码；[13] 会直接从容器日志/启动日志抓 noVNC 与 WebUI(admin) 的真实
    密码显示，抓不到时给出 docker logs 查询命令。直接安装(native) 用 mk 自带 VNC，密码本地即生效
  · 端口可改：菜单 [17]，或编辑 /var/log/mk-tools/snowluma-vnc.env，也可
    export MK_SNOWLUMA_NOVNC_PORT=8081 MK_SNOWLUMA_VNC_PORT=5901
    （注意：Docker 模式端口/密码在建容器时固定，改完要「卸载→重装」容器才生效）
  · WebUI 外部访问（菜单 [18]，仅直接安装版需要）：某些版本 WebUI 只监听 127.0.0.1，直连服务器
    外部打不开。[18] 首选「改 SnowLuma 监听 0.0.0.0」——写入偏好后，mk 在启动 SnowLuma 时注入
    环境变量 SNOWLUMA_WEBUI_HOST（优先级高于 runtime.json），本体直接对外监听，干净不占额外端口；
    改完若在运行会问你是否立即重启生效。[3] 改回仅本机 127.0.0.1。万一某旧版本不认这个变量，
    [4] 提供 socat 兜底：在「本机IP:同端口」转发到 127.0.0.1（首次会自动装 socat 并放行防火墙）。
    Docker 模式已对外，无需此项。注意：WebUI 暴露到公网有风险，请设强密码并尽量只放行可信来源。
  · 扫码：浏览器打开 http://服务器IP:端口/ ，在 QQ 窗口扫码（不是完整 Linux 桌面）
  · 安装 QQ：优先读官网 rainbow（dldir1v6.qq.com 新域名），失败再试 GitHub 归档镜像
  · 旧 qqdl.gtimg.cn 通道仅作备用（不少网络已 404）
  · 与 NapCat 共用 /opt/QQ 时请注意互相启停，避免冲突

四-C、Docker 菜单（主菜单 [12]）
--------------------------------------------------------------------------------
  [2] 安装 Docker         官方脚本 get.docker.com；可选阿里云镜像源（国内推荐），装完自动 enable+start
  [3] 卸载 Docker         移除引擎（高风险），可选一并删除 /var/lib/docker 全部镜像/容器/卷
  [4] 启动 Docker 服务    systemctl start docker
  [5] 停止 Docker 服务    systemctl stop docker
  [6] 重启 Docker 服务    systemctl restart docker
  [7] 查看容器列表        docker ps -a（名称/状态/镜像/端口）
  [8] 查看资源使用        docker stats 快照（CPU/内存/网络）+ docker system df（磁盘占用）
  [9] 查看外放端口/访问地址  逐容器列出发布到宿主机的端口，并拼出 http://本机IP:端口/ 与公网地址
  [10] 容器 启停/重启/暂停/恢复  输入容器名后选择 start/stop/restart/pause/unpause
  [11] 删除容器           docker rm -f（高风险，需二次确认）

说明：
  · 仅限 Linux 服务器（依赖内核特性 + root）；Termux 手机上此项被拦截
  · [9] 的访问地址：绑定 0.0.0.0/所有网卡的端口会给出局域网与公网两个 http 地址；绑定 127.0.0.1
    的标「仅本机」，外部访问不到——要对外请改容器的 -p 映射或加反向代理。http 链接只是猜测，
    非网页服务（如纯 OneBot WS）忽略即可
  · snowLuma 选 Docker 模式安装时，若没装 Docker 会直接问你要不要现在装（走的就是本菜单的安装逻辑）

【Node 显示说明】
菜单会显示类似：
  * Node.js v22.x.x (mk 管理)     ← 用的 /usr/local/lib/mk-tools/nodejs
  * Node.js v20.x.x (系统全局)   ← 用的 PATH / 常见路径里的 node
  * Node.js v22.x.x (便携内置)   ← 用的 ~/kakake/runtime/bin/node
  * Node.js v22.x.x (Termux pkg) ← 手机上 pkg install nodejs-lts 装的
  * Node.js 未安装               ← 都没有，需先装再启动咔咔

检测顺序：便携内置 → mk 私有 Node → （Termux）$PREFIX/bin/node → PATH 里的 node
          → 常见路径（如 /usr/bin/node、nvm/fnm/volta）
启动咔咔、构建 Web、开机自启都会走这套解析，不强制必须装 mk 私有 Node。
Termux 上 [3] 安装 Node.js 走的是 pkg install nodejs-lts（22.x），
注意 nodejs 与 nodejs-lts 互相冲突，装之前先卸掉另一个。

九、开机自启（主菜单 [9]）
--------------------------------------------------------------------------------
Linux：可分别为 NapCat、咔咔写入 systemd 服务并启用
       （服务名 mk-napcat.service / mk-kakake.service）。
       咔咔自启同样依赖能解析到可用的 Node.js。

Termux：安卓没有 systemd，改用 Termux:Boot。启用后生成
       ~/.termux/boot/20-kakake.sh，开机时自动申请 termux-wake-lock 再拉起咔咔。
       生效需要三个前提，缺一个都不会自启：
         1) 装了 Termux:Boot 应用，且与 Termux 同来源（F-Droid 或 GitHub）
         2) 装好后手动打开过一次 Termux:Boot（不打开不会注册开机广播）
         3) 系统里把 Termux 与 Termux:Boot 的电池优化都关掉
