================================================================================
  MK 工具使用教程（Linux 服务器）
  脚本：仓库根目录 mk（安装后全局命令也叫 mk）
  当前文档对应脚本版本：2.5.6+
================================================================================

【这是干什么的】
mk 是 Linux 上一键管理脚本，交互菜单里可以：
  · 装/管宝塔
  · 装/启停 NapCat（QQ）
  · 装/启停 SnowLuma（Docker 或直接安装）、装兼容 QQ
  · 装/启停咔咔珂、装 Node、构建 Web UI
  · 查端口占用、构建 MK 插件源码、NapCat 实验魔改、开机自启
  · 检测/安装中文字体包（软件源、国内代理镜像、本地文件）

【适用环境】
  · Linux 服务器（需 bash；多数操作要 root / sudo）
  · 不是 Windows 本机用的；Windows 请用仓库里的 start.bat / start.sh 起咔咔
  · 咔咔支持两种形态（mk 会自动识别；安装时可二选一）：
      源码版：下载 kakake.zip，含 scripts/bootstrap.mjs，启动前可构建 Web，可用 mk 私有/系统 Node
      便携版：下载 kakake-linux-x64.zip，含 runtime/bin/node + packages/server/main.mjs，无需再装 Node、无需构建 Web
        解压后统一装到 ~/kakake（zip 内目录名可以是 kakake 或 kakake-linux-x64）
        手动部署时把 kakake-linux-x64 目录内容放到 ~/kakake 亦可
--------------------------------------------------------------------------------
一、安装 / 更新 mk
--------------------------------------------------------------------------------
把仓库里的 mk 文件拷到服务器后（或用已有路径）：

  # 首次安装或强制更新到系统（需要 root）
  sudo bash mk
  # 或
  sudo bash mk --install

安装完成后：
  · 脚本本体：/usr/local/lib/mk-tools/mk
  · 全局命令：mk  （软链到 /usr/local/bin/mk）
  · 日志目录：/var/log/mk-tools/

日常打开菜单（已装过全局命令时）：

  sudo mk
  # 或
  mk

常用参数：
  mk --version / -v     查看版本
  mk --help / -h        用法说明
  mk --check / -c       语法检查
  mk --install / -i     强制重装/更新
  mk --uninstall / -u   卸载 mk 工具本身（不自动卸 NapCat/咔咔，见菜单）


--------------------------------------------------------------------------------
二、主菜单一览
--------------------------------------------------------------------------------
  [1] 宝塔操作          安装/管理宝塔面板
  [2] NapCat操作        安装、启停、配置 NapCat
  [3] snowLuma操作      安装/启停 SnowLuma 与兼容 QQ
  [4] 咔咔操作          安装咔咔、Node、启停、Web UI、登录密钥
  [5] 端口验证          查占用、杀进程（OneBot / 控制台端口排查常用）
  [6] 构建 MK 源码      给解压后的 MK 插件源码跑构建
  [7] 实验功能          NapCat 插件系统魔改（白名单/上传/刷新按钮）
  [8] 卸载 mk 工具      卸掉 mk 自身
  [9] 开机自启          NapCat / 咔咔 systemd 自启
  [10] 字体包操作       检测中文字体；软件源/镜像下载/本地安装
  [0] 退出

子菜单里一般：
  [0] / [1] 返回上一级
  其余数字按提示操作


--------------------------------------------------------------------------------
三、推荐上手流程（服务器上从零到可聊）
--------------------------------------------------------------------------------
1) sudo bash mk 安装 mk（若尚未安装）
2) 主菜单 → [2] NapCat → [2] 安装框架（后台装，可看进度）
3) NapCat 装完 → [3] 启动 → [9] 看面板登录密钥，浏览器进 NapCat WebUI 扫码
4) 主菜单 → [4] 咔咔操作
     · 菜单会显示「安装形态: 源码版 / 便携版」
     · 便携版：Node 显示「便携内置」，可直接 [5] 启动；无需 [3] 装 Node、无需 [10] 构建 Web
     · 源码版：若提示没有 Node，可 [3] 安装 Node.js（mk 私有一份）
       若本机已有全局 Node，菜单会显示「系统全局」，一般可直接用，不必再装
     · [2] 安装咔咔 → 会询问源码版 / 便携版 → [5] 启动咔咔
       （源码版未构建 Web 时启动会先构建；便携版可直接启动）
     · 重装仍保留 data/ 与 plugins/
     · [9] 查看登录密钥 → 浏览器打开控制台（默认端口 8787）
5) 按《连接教程.txt》把 NapCat / SnowLuma 与咔咔连上（推荐本机反向 WS）
6) 端口冲突：主菜单 → [5] 端口验证
7) 中文方块/截图乱码：主菜单 → [10] 字体包操作 → 先 [2] 扫描，再按网络情况安装


--------------------------------------------------------------------------------
四、NapCat 菜单（主菜单 [2]）
--------------------------------------------------------------------------------
  [2] 安装框架-后台安装   选版本/镜像后后台跑官方安装脚本
  [3] 启动框架
  [4] 停止框架
  [5] 重启框架
  [6] 配置框架           含网络配置等
  [7] 卸载框架
  [8] 查看日志
  [9] 查看 NapCat 面板登录密钥
  [10] 查看安装进度      （仅安装进行中时有用）

说明：
  · 安装脚本地址由 mk 内置（经代理拉取 NapCat-Installer）
  · 指定版本时还会按所选镜像代理拉取 NapCat.Shell.zip
  · 默认安装路径常见为 ~/Napcat 或 /opt/QQ（以安装脚本与本机检测为准）


--------------------------------------------------------------------------------
四-B、snowLuma 菜单（主菜单 [3]）
--------------------------------------------------------------------------------
  [2] 安装 SnowLuma       可选 Docker 安装 / 直接安装（解压发行包）
  [3] 卸载 SnowLuma
  [4] 安装 QQ             按架构与已装 SnowLuma 版本列出兼容下载地址并可安装
  [5] 启动 QQ             常规模式会同时拉起 Xvfb+VNC+noVNC 扫码桌面
  [6] 停止 QQ             常规模式一并停扫码桌面
  [7] 彻底杀死 QQ         强杀 /opt/QQ 进程树并短时压制自动拉起（不关 VNC）
  [8] 卸载 QQ             卸宿主 linuxqq（/opt/QQ）
  [9] 启动 SnowLuma
  [10] 停止 SnowLuma
  [11] 重启 SnowLuma
  [12] 查看日志
  [13] 查看 WebUI 登录信息
  [14] 查看扫码地址       noVNC / VNC 端口与密码
  [15] 仅启动远程查看
  [16] 仅停止远程查看     不影响 QQ
  [17] 配置扫码端口/密码  noVNC/VNC 均可改（默认 6081/5900）

说明：
  · Docker：镜像 motricseven7/snowluma:latest，内置 QQ + noVNC（默认 6081）+ WebUI（5099）
  · 直接安装：解压到 /opt/SnowLuma；「启动 QQ」会装并启动 Docker 同款扫码栈
    （Xvfb :99 + openbox/fluxbox + x11vnc + noVNC；默认端口 5900/6081，密码 vncpasswd）
  · 端口可改：菜单 [17]，或编辑 /var/log/mk-tools/snowluma-vnc.env，也可
    export MK_SNOWLUMA_NOVNC_PORT=8081 MK_SNOWLUMA_VNC_PORT=5901
  · 扫码：浏览器打开 http://服务器IP:端口/ ，在 QQ 窗口扫码（不是完整 Linux 桌面）
  · 安装 QQ：优先读官网 rainbow（dldir1v6.qq.com 新域名），失败再试 GitHub 归档镜像
  · 旧 qqdl.gtimg.cn 通道仅作备用（不少网络已 404）
  · 与 NapCat 共用 /opt/QQ 时请注意互相启停，避免冲突


--------------------------------------------------------------------------------
五、咔咔菜单（主菜单 [4]）
--------------------------------------------------------------------------------
  [2] 安装咔咔           下载/部署到 ~/kakake
  [3] 安装 Node.js       装到 mk 私有目录（启动时优先用这份）
  [4] 卸载 Node.js       只卸 mk 私有 Node，不动系统全局 Node
  [5] 启动咔咔
  [6] 停止咔咔
  [7] 重启咔咔
  [8] 配置咔咔           连接等配置入口
  [9] 查看登录密钥       控制台账号密钥（data/auth-key.json）
  [10] 构建 Web UI       强制重建前端（Vite → packages/web/dist）
  [11] 卸载咔咔

【Node 显示说明】
菜单会显示类似：
  * Node.js v22.x.x (mk 管理)     ← 用的 /usr/local/lib/mk-tools/nodejs
  * Node.js v20.x.x (系统全局)   ← 用的 PATH / 常见路径里的 node
  * Node.js 未安装               ← 两边都没有，需先装再启动咔咔

检测顺序：mk 私有 Node → PATH 里的 node → 常见路径（如 /usr/bin/node、nvm/fnm/volta）
启动咔咔、构建 Web、开机自启都会走这套解析，不强制必须装 mk 私有 Node。


--------------------------------------------------------------------------------
六、端口验证（主菜单 [5]）
--------------------------------------------------------------------------------
用于排查 OneBot 监听口（如 6700）或咔咔控制台（如 8787）被占用。
可按提示查看占用进程，并杀掉冲突进程后再启动。


--------------------------------------------------------------------------------
七、构建 MK 源码（主菜单 [6]）
--------------------------------------------------------------------------------
把解压后的 MK 插件源码目录路径贴进去（含 package.json / vite.config 的那层）。
需 Node 20+（同样认 mk 私有或系统全局）。
构建日志在 /var/log/mk-tools/ 相关文件中。


--------------------------------------------------------------------------------
八、实验功能（主菜单 [7]）
--------------------------------------------------------------------------------
对已安装的 NapCat 做插件相关魔改（有版本范围限制）：
  · 魔改白名单限制
  · 魔改插件上传
  · 魔改刷新插件按钮
  · 一键应用全部魔改
已魔改会跳过；版本不在支持范围会拒绝。非必要勿乱点。


--------------------------------------------------------------------------------
九、开机自启（主菜单 [9]）
--------------------------------------------------------------------------------
可分别为 NapCat、咔咔写入 systemd 服务并启用。
咔咔自启同样依赖能解析到可用的 Node.js。


--------------------------------------------------------------------------------
九-B、字体包操作（主菜单 [10]）
--------------------------------------------------------------------------------
  [2] 扫描检测中文字体     fc-list / 常见包名 / mk 安装目录
  [3] 软件源一键安装       apt/yum/dnf/pacman（走本机已配置的国内或官方源）
  [4] 下载安装文泉驿微米黑 体积较小；可选直连 / 国内 GitHub 代理 / 自定义 URL
  [5] 下载安装 Noto CJK SC 覆盖更好；镜像选择同上
  [6] 从本地文件安装       无外网：先 scp 字体到服务器再填路径（.ttf/.otf/.ttc）
  [7] 刷新字体缓存         fc-cache

说明：
  · 手动下载的字体会放到 /usr/share/fonts/mk-cjk/
  · 安装日志：/var/log/mk-tools/font-install.log
  · 完全断网不要选下载，用 [6]；能上系统软件源但上不了 GitHub 时优先 [3]


--------------------------------------------------------------------------------
十、日志与路径速查
--------------------------------------------------------------------------------
  mk 安装目录          /usr/local/lib/mk-tools/
  mk 全局命令          /usr/local/bin/mk
  mk / NapCat 等日志   /var/log/mk-tools/
  mk 私有 Node         /usr/local/lib/mk-tools/nodejs/bin/node
  SnowLuma 直接安装    /opt/SnowLuma
  SnowLuma WebUI       5099
  SnowLuma 扫码桌面    noVNC 6081 / VNC 5900（Docker 与常规安装均支持）
  noVNC 资源目录       /usr/share/novnc 或 /usr/local/lib/mk-tools/novnc
  咔咔默认家目录       ~/kakake
  咔咔控制台默认端口   8787（以 data/config.json 的 port 为准）
  中文字体（mk 安装）  /usr/share/fonts/mk-cjk/


--------------------------------------------------------------------------------
十一、和《连接教程》怎么配合
--------------------------------------------------------------------------------
mk 负责「装起来、跑起来」；
连 NapCat / SnowLuma / QQ 官方 / 微信 的具体参数见：

  使用教程/连接教程.txt

例如本机最省事组合：
  咔咔反向 WS 0.0.0.0:6700 + NapCat / SnowLuma 的 WS 客户端连 ws://127.0.0.1:6700
