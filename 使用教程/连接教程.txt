================================================================================
  咔咔珂 连接教程（现版本）
  涵盖：
    · OneBot / NapCat：反向 WS、正向 WS、HTTP 服务器、HTTP SSE 服务器、HTTP 客户端
    · QQ 官方机器人：官方 WS、官方 HTTPS（Webhook）
    · 微信 BOT：iLink 扫码登录 + 长轮询
    · KOOK 机器人：机器人 Token 直连 KOOK 网关（WebSocket）
    · Telegram Bot：getUpdates 长轮询 / setWebhook HTTPS 回调 / 本地 Bot API Server
================================================================================

【先看这几条】
1. 平时每个机器人账号只启用「一种」对接方式即可；OneBot 正反向 + 多种 HTTP 不要一起开，易重复收消息。
   Telegram 的 getUpdates 与 setWebhook 同样互斥，同时开报 409。
2. Access Token / Token 两边必须一致；两边都空 = 不鉴权。
3. 咔咔后台默认端口 8787（控制台），和 OneBot 监听口（6700/6701 等）不是一回事。
   Telegram Webhook 回调地址是 https://域名/tgbot/<连接id>，由反代转到 8787。
4. NapCat「容器安装」时：容器访问宿主机上的咔咔，一般用 Docker 网关
   http://172.17.0.1:端口
   （个别环境可能是 host.docker.internal 或宿主机内网 IP，以实际为准。）
5. 宿主机访问「已映射端口」的 NapCat，一般用
   http://127.0.0.1:端口
6. HTTP 上报（NapCat HTTP Client → 咔咔）鉴权：NapCat 用 Token 做 X-Signature，
   不是简单的 Bearer；咔咔已支持。Token 填一样即可。
7. 五种连接类型对应各自的插件页签：
     OneBot / NapCat  →「插件」
     QQ 官方机器人    →「QQ官方机器人」
     微信 BOT         →「微信机器人」
     KOOK 机器人      →「插件」页里的「KOOK」页签
     Telegram Bot     →「Telegram」页签（插件目录前缀 TG-plugin-）
   连接启用后，再在对应页签里按「该连接」开关插件。


--------------------------------------------------------------------------------
一、反向 WebSocket（推荐入门 · OneBot）
--------------------------------------------------------------------------------
含义：咔咔开 Server 监听；NapCat 用 WebSocket Client 连过来。

【咔咔】连接 → 添加 → OneBot「反向 WS」
  名称：随意，如「反向」
  监听地址：0.0.0.0          （仅本机可填 127.0.0.1）
  监听端口：6700             （常用默认）
  Access Token：如 10086     （可留空，两边一致即可）
  启用：开

【NapCat · 本机/非容器】网络 → WebSocket 客户端（Client）
  启用：开
  名称：随意
  URL：ws://127.0.0.1:6700
  Token：与咔咔相同
  其余按默认即可

【NapCat · Docker 容器】
  同上，但 URL 改为：
  ws://172.17.0.1:6700
  （咔咔必须监听 0.0.0.0:6700，不能只绑 127.0.0.1，否则容器连不上。）

【自检】
  咔咔日志有客户端连入；NapCat 无持续重连报错。


--------------------------------------------------------------------------------
二、正向 WebSocket
--------------------------------------------------------------------------------
含义：NapCat 开 WebSocket Server；咔咔主动连过去。

【咔咔】添加 → OneBot「正向 WS」
  名称：随意，如「正向」
  NapCat 地址：127.0.0.1     （宿主机访问已映射的 NapCat）
  NapCat 端口：3001          （常用；以 NapCat 实际为准）
  Access Token：与 NapCat 相同
  启用：开

【NapCat · 本机/非容器】网络 → WebSocket 服务端（Server）
  启用：开
  Host：0.0.0.0
  Port：3001
  Token：与咔咔相同

【NapCat · Docker 容器】
  NapCat：同上（容器内 0.0.0.0:3001，并做好端口映射到宿主机 3001）
  咔咔：地址仍填 127.0.0.1，端口填映射后的端口（如 3001）
  若咔咔也在另一容器且不在同一网络，则填 NapCat 容器 IP 或服务名，不要填 127.0.0.1。

【注意】
  正向端口不要填 6700（那是反向监听口，会连到咔咔自己）。
  正向与反向不要同时开同一套业务，以免重复收消息。


--------------------------------------------------------------------------------
三、HTTP 三种模式总览
--------------------------------------------------------------------------------
  ① HTTP 服务器      ：咔咔另开端口收 POST 上报；再调 NapCat HTTP API
  ② HTTP SSE 服务器  ：与①类似，并多支持 SSE 订阅；接 NapCat 填法同①
  ③ HTTP 客户端      ：不另开上报口；走咔咔主站 /onebot/http/<连接id>
                       并可主动连 NapCat 的 HTTP SSE

日常接 NapCat：优先 ①；不想多开端口再用 ③；② 一般给第三方 SSE 用。


--------------------------------------------------------------------------------
三-①、HTTP 服务器（最常用 HTTP）
--------------------------------------------------------------------------------
含义：NapCat HTTP Client 把事件 POST 到咔咔；咔咔再用 NapCat HTTP Server 调 API。

【咔咔】添加 →「HTTP 服务器」
  名称：随意，如「HTTP」
  监听地址：0.0.0.0
  监听端口：6701
  NapCat HTTP API（apiUrl）：http://127.0.0.1:3000
  Access Token：如 10086
  启用：开

  成功日志类似：
  HTTP 事件上报监听: http://127.0.0.1:6701 （API: http://127.0.0.1:3000）

【NapCat · 本机/非容器】
  1）HTTP 服务端（Server）—— 给咔咔调 API
     启用：开
     Host：0.0.0.0
     Port：3000
     Token：10086（与咔咔一致）
     消息格式：Array（常用）

  2）HTTP 客户端（Client）—— 事件上报到咔咔
     启用：开
     URL：http://127.0.0.1:6701
     Token：10086
     消息格式：Array

【NapCat · Docker 容器】
  HTTP Server：同上（映射宿主机 3000）
  HTTP Client 的 URL 改为：
     http://172.17.0.1:6701
  咔咔 apiUrl 仍用：
     http://127.0.0.1:3000
  （前提：容器 3000 已映射到宿主机）
  咔咔监听必须是 0.0.0.0:6701，不要用 127.0.0.1（否则容器报 ECONNREFUSED）。

【常见报错】
  ECONNREFUSED 172.17.0.x:6701
    → URL/监听地址不对，或咔咔只绑了 127.0.0.1
  401 Unauthorized
    → Token 不一致；或旧版咔咔不认 X-Signature（请更新咔咔后再试）


--------------------------------------------------------------------------------
三-②、HTTP SSE 服务器
--------------------------------------------------------------------------------
含义：咔咔监听端口，可收 NapCat 的 POST；也可让其他程序用 SSE 订阅事件。
接 NapCat 时，参数与「HTTP 服务器」相同。

【咔咔】添加 →「HTTP SSE 服务器」
  监听地址：0.0.0.0
  监听端口：6701（或其它空闲口）
  NapCat HTTP API：http://127.0.0.1:3000
  Access Token：与 NapCat 一致
  启用：开

【NapCat · 本机】
  HTTP Server：0.0.0.0:3000 + Token
  HTTP Client：http://127.0.0.1:6701 + Token

【NapCat · Docker】
  HTTP Client：http://172.17.0.1:6701 + Token
  其余同「HTTP 服务器」

说明：NapCat 侧一般不必再开「HTTP SSE 服务端」；那是 NapCat 对外推 SSE 用的。
咔咔这种模式是「咔咔自己当 SSE 源」。


--------------------------------------------------------------------------------
三-③、HTTP 客户端
--------------------------------------------------------------------------------
含义：不另开 6701；事件可 POST 到咔咔控制台端口上的路径；
同时咔咔会尝试连接 NapCat 的 HTTP SSE，并用 NapCat HTTP API 发动作。

【咔咔】添加 →「HTTP 客户端」
  名称：随意
  NapCat 地址：127.0.0.1
  NapCat 端口：3000          （指向 NapCat HTTP API / SSE 根地址）
  Access Token：如 10086
  启用：开

  启用后在连接详情/日志中查看「事件上报地址」，形如：
  http://127.0.0.1:8787/onebot/http/<连接id>
  （8787 为咔咔后台端口；连接 id 以界面为准，可复制。）

【NapCat · 本机/非容器】（推荐：HTTP Client 上报）
  1）HTTP Server：0.0.0.0:3000，Token 一致（API）
  2）HTTP Client：
     URL：http://127.0.0.1:8787/onebot/http/<连接id>
     Token：与咔咔一致
  3）可选：若希望咔咔用 SSE 拉事件，再开 NapCat「HTTP SSE 服务端」
     （端口需与咔咔填写的 NapCat 地址端口一致，或保证能连上）

【NapCat · Docker 容器】
  HTTP Server：映射 3000 到宿主机；咔咔填 127.0.0.1:3000
  HTTP Client URL：
     http://172.17.0.1:8787/onebot/http/<连接id>
  （不要用 127.0.0.1，那是容器自己，不是宿主机咔咔。）

【注意】
  改用本模式时，请关掉原来的「HTTP 服务器 6701」那条，避免同一事件报两次。
  安全组/防火墙需放行 8787（若从外网或跨机访问上报地址）。


--------------------------------------------------------------------------------
四、QQ 官方机器人
--------------------------------------------------------------------------------

【官方 WS】（推荐，无需域名）
  咔咔主动连腾讯 Gateway，一般不需要域名/反代。

  咔咔：连接 → 添加 →「QQ 官方 · WS」
    名称：随意
    AppID / AppSecret：开放平台「机器人」凭证
    沙箱：调试期可开；正式环境关
    添加后默认关闭 → 确认信息无误再启用

  昵称与头像由官方 API 自动拉取，无需手填。

【官方 HTTPS】（Webhook，需域名 + HTTPS）
  含义：腾讯向你的回调地址 POST 事件；咔咔挂在主端口路径上等待。

  咔咔：
    添加 →「QQ 官方 · HTTPS」
    AppID / AppSecret / 沙箱
    公网回调基址（可选）：https://你的域名
      （填了之后界面可一键复制完整回调 URL）
    启用后复制：
      回调 URL：https://你的域名/gfbot/<连接id>
      或路径：/gfbot/<连接id>

  反代（宝塔等）：
    域名 → http://127.0.0.1:8787
    （与后台同一条反代即可，路径原样转发）

  开放平台：
    回调地址填上面复制的 HTTPS URL
    公网端口须为 80/443/8080/8443（用 443 最省事）
    保存时平台会发校验请求，咔咔自动用 AppSecret 签名响应

  注意：
    - 必须用可信 HTTPS 证书（反代搞定）
    - 不要和官方 WS 对同一机器人重复开两套收事件
    - 插件请到「QQ官方机器人」页签，按该连接开关


--------------------------------------------------------------------------------
五、微信 BOT（iLink）
--------------------------------------------------------------------------------
含义：走微信官方 iLink 渠道；手机微信扫码登录后，咔咔长轮询收消息并回发。
不需要 NapCat，也不需要公网域名。

【添加】
  咔咔：连接 → 添加 →「微信BOT」
  名称：随意，如「微信」
  添加成功后默认未登录；界面会提示先扫码。

【扫码登录】
  1. 在连接卡片点「扫码登录」（未登录时点「启用」也会自动弹出二维码）
  2. 用微信扫描弹窗中的二维码，并在手机上确认
  3. 若二维码图未显示，可用弹窗里的「备用登录链接」在浏览器打开后再用微信扫
  4. 登录成功后，连接摘要会显示账号信息；凭证保存在本机 data/ 中

【启用】
  登录成功后再打开「启用」开关，即可开始收发。
  若未登录就点启用 → 会先弹出扫码，登录成功后再启用。

【退出 / 换号】
  点「清除登录」或重新「扫码登录」即可换号。
  清除后需重新扫码才能收消息。

【插件】
  到「微信机器人」页签，对该连接打开需要的插件（如 WX-plugin-wxbot）。
  改插件代码后：对该连接关闭再打开对应插件，才会刷新 plugins_two 副本。

【注意】
  - 一台咔咔可添加多个微信BOT连接（多号），各自独立登录与插件开关
  - 不依赖 6700/6701 等 OneBot 端口；也不占用 QQ 官方回调路径
  - 语音气泡受 iLink 平台限制时，插件可能以「文件」形式发送音频，属正常兼容


--------------------------------------------------------------------------------
六、KOOK 机器人
--------------------------------------------------------------------------------
含义：直连 KOOK 官方机器人网关（WebSocket）。只要一个机器人 Token 即可，
不需要 NapCat，也不需要公网域名 / 端口映射。

【拿 Token】
  1. 打开 KOOK 开发者中心（developer.kookapp.cn）→「应用」
  2. 新建或选择一个应用 → 进入「机器人」页
  3. 复制机器人 Token（形如 1/xxxx=/xxxxxxxxxxxx==）
  （机器人要先被邀请进目标服务器，并开好所需权限/频道，才能收发消息。）

【添加】
  咔咔：连接 → 添加 →「KOOK 机器人」
  名称：随意，如「KOOK」（留空默认「KOOK 机器人」）
  KOOK 机器人 Token：粘贴上一步复制的 Token
  添加后默认「关闭」，先不用开。

【启用】
  打开「启用」开关 → 咔咔自动连 KOOK 网关，并拉取机器人身份
  （用户名 / 认证编号 / 头像），连接摘要随即显示账号信息。
  未填 Token 就点启用会被拦下，提示「请填写 KOOK 机器人 Token」。

【插件】
  到「插件」页的「KOOK」页签，对该连接打开需要的插件（如 ss-plugin-xxx）。
  改插件代码后：对该连接关闭再打开对应插件，才会刷新 plugins_two 副本。

【自检】
  · 连接卡片状态变为「已连接 KOOK」；日志有网关连上、身份识别记录
  · 往机器人所在的频道发条消息，看咔咔是否出现上报日志

【注意】
  - Token 属敏感凭证，切勿泄露；泄露后到开发者中心重置
  - 一台咔咔可添加多个 KOOK 连接（多号），各自独立身份与插件开关
  - 不依赖 6700/6701 等 OneBot 端口，也不占用 QQ 官方回调路径

七、参数速查表
--------------------------------------------------------------------------------

模式              咔咔关键字段              对端
--------------  ----------------------  ----------------------------------
反向 WS          监听 0.0.0.0:6700       NapCat WS Client → ws://宿主:6700
正向 WS          连 127.0.0.1:3001       NapCat WS Server  0.0.0.0:3001
HTTP 服务器      监听 :6701 + apiUrl     NapCat Server:3000 + Client→:6701
HTTP SSE 服务器  同 HTTP 服务器          同 HTTP 服务器
HTTP 客户端      连 NapCat:3000          Server:3000 + Client→:8787/onebot/http/id

微信 BOT         扫码登录即可             微信 iLink（无需端口/域名）
KOOK 机器人      Token 直连               KOOK 网关（咔咔主动连，无需端口/域名）

「宿主」在本机安装 = 127.0.0.1
「宿主」在 NapCat 容器内访问咔咔 = 172.17.0.1（常见）


--------------------------------------------------------------------------------
八、推荐组合（按场景）
--------------------------------------------------------------------------------
A. 最省事、本机都装在一起（QQ · NapCat）
   → 反向 WS：咔咔 6700 + NapCat WS Client ws://127.0.0.1:6700

B. NapCat 在 Docker，咔咔在宿主机
   → 反向 WS：咔咔 0.0.0.0:6700 + NapCat ws://172.17.0.1:6700
   或 HTTP 服务器：咔咔 0.0.0.0:6701 + NapCat Client http://172.17.0.1:6701
                 + NapCat Server 3000 映射到宿主机，咔咔 apiUrl=http://127.0.0.1:3000

C. 只有一个对外端口 / 反代域名（QQ · NapCat）
   → HTTP 客户端：上报走 http(s)://域名/onebot/http/<id>

D. QQ 开放平台官方机器人、不想折腾反向代理
   → QQ 官方 · WS（填 AppID/Secret 启用即可）

E. QQ 官方机器人必须走 Webhook
   → QQ 官方 · HTTPS + 域名反代到 8787，回调填 /gfbot/<连接id>

F. 微信个人号 / 企业微信 iLink 机器人渠道
   → 微信BOT：添加 → 扫码 → 启用 →「微信机器人」页签开插件

G. KOOK 官方机器人
   → KOOK 机器人：开发者中心复制 Token → 添加 → 启用 →「插件」页「KOOK」页签开插件


--------------------------------------------------------------------------------
九、配置改完后
--------------------------------------------------------------------------------
1. 保存 NapCat / 开放平台 / 微信扫码状态，并确认对应连接已启用。
2. 咔咔连接开关打开；必要时重启咔咔。
3. 往测试群/私聊发一条消息，看咔咔是否出现上报日志。
4. 到对应插件页签确认该连接下插件已开启。
5. 端口占用可用 mk「端口验证 → 杀掉进程」排查（OneBot / 控制台端口）。
6. Linux 上如何安装/使用 mk 脚本（NapCat、咔咔启停等）见同目录《MK工具教程.txt》。

十、Telegram Bot（BotFather → 三种对接方式）
--------------------------------------------------------------------------------
含义：用 BotFather 签发的 token 直连 Telegram Bot API，不需要 NapCat / QQ 客户端，
      也不需要挂一个聊天软件在后台。框架用 getMe 回填机器人 ID / @用户名 / 显示名，
      并以「机器人 ID」作为插件与数据的账号隔离键（plugins_two/<机器人ID>/<插件ID>）。

【第一步 · BotFather 建机器人】（Telegram 里操作，只做一次）
  1. 找 @BotFather，发 /newbot
  2. 按提示起「显示名」和「用户名」（用户名必须以 bot 结尾、全局唯一）
  3. 拿到一串 token，形如 123456789:AAH...（唯一凭证，等同密码：别发群里、别提交 GitHub）
  4. 常用开关（都是给 @BotFather 发 / 命令，再选中你的机器人）：
       /setprivacy        隐私模式：关掉才能收到群里普通消息（见下方「坑 1」）
       /setcommands       设置指令菜单（用户输入 / 时弹出的提示）
       /setdescription /setabouttext /setuserpic   简介 / 关于 / 头像
       /setinline         开 Inline Mode（任意聊天框输入 @机器人 查询）
       /setjoingroups     允许 / 禁止被拉进群
       /token /revoke     重新签发 token（旧的立刻失效）
     ★ Inline Mode、加入群组、Bot-to-Bot、Managed Bots 这些都是 BotFather 开关，
       默认不一定开，用到哪个开哪个。

【咔咔】连接 → 添加 → Telegram Bot
  名称：随意，如「TG 主机器人」
  类型：Telegram Bot
  Bot Token：粘贴 BotFather 给的那一串
  接入方式 mode：长轮询 polling（默认） / Webhook webhook
  启用：开
  保存后框架自动调 getMe，回填 telegramBotUserId / telegramBotUsername / telegramBotFirstName。

【方式一 · getUpdates 长轮询（推荐入门，无需公网）】
  接入方式选 polling 即可，不用域名、不用证书、不用公网 IP。
  原理：框架反复调 getUpdates，用 offset 游标确认已处理的 update；
        timeout 秒数挂起长连接、limit 控制单次取回条数（1-100）。
  可调项：
      长轮询超时 telegramPollingTimeout   默认 30 秒
      单次上限   telegramPollingLimit     1-100，默认 100
      订阅类型   telegramAllowedUpdates   留空用框架默认全集
                                          （chat_member / message_reaction 等需显式订阅）
      游标       telegramOffset           框架自动确认并持久化，重启不会重复收
  断线按退避策略自动重连。Update 在 Telegram 服务器最多保留 24 小时，
  长时间离线后多余的会丢，别把它当消息队列用。

【方式二 · setWebhook（有公网域名 + HTTPS 时）】
  1. 准备公网域名与可信证书（自签证书要作为 certificate 上传，CN / SAN 必须与域名匹配）。
     官方只接受 443 / 80 / 88 / 8443 四个端口，别的端口一律拒绝。
  2. 咔咔这边：接入方式选 webhook，填
       Webhook URL：https://bot.example.com/tgbot/<连接id>
                    回调路径固定 /tgbot/<连接id>（<连接id> 在连接列表里看），
                    反代必须把这一路径原样转发到咔咔（默认 8787）。
       Secret Token：1-256 位，只能用 A-Z a-z 0-9 _ -。
                     框架用它校验每个请求的 X-Telegram-Bot-Api-Secret-Token 头，
                     不一致直接拒绝。
       可选：最大连接数 telegramWebhookMaxConnections（1-100）、固定投递 IP、
             自签证书路径 telegramWebhookCertificatePath、
             丢弃积压更新 telegramDropPendingUpdates、
             响应内直接回复 telegramWebhookReplyInResponse
             （把本次事件产生的首个 API 调用放进 2xx 响应体，省一次请求但拿不到 result）。
  3. Nginx 反代示例（把 /tgbot/ 转到本机 8787）：
       server {
         listen 443 ssl;
         server_name bot.example.com;
         ssl_certificate     /etc/letsencrypt/live/bot.example.com/fullchain.pem;
         ssl_certificate_key /etc/letsencrypt/live/bot.example.com/privkey.pem;
         location /tgbot/ {
           proxy_pass http://127.0.0.1:8787;
           proxy_set_header Host $host;
           proxy_set_header X-Telegram-Bot-Api-Secret-Token
                            $http_x_telegram_bot_api_secret_token;
         }
       }
     注意 proxy_pass 结尾不要加 /，否则 /tgbot/<id> 会被改写成 /。
  4. 自检命令（浏览器或 curl，<token> 换成自己的）：
       setWebhook     https://api.telegram.org/bot<token>/setWebhook?url=https://bot.example.com/tgbot/<连接id>&secret_token=xxx
       getWebhookInfo https://api.telegram.org/bot<token>/getWebhookInfo
                      ← 看 url / pending_update_count / last_error_message
       deleteWebhook  https://api.telegram.org/bot<token>/deleteWebhook
                      ← 切回轮询前必须先删
  5. polling 与 webhook 互斥：同时用会报 409 Conflict
     （"can't use getUpdates method while webhook is active"）。

【方式三 · 本地 Bot API Server（大文件 / 内网 / 性能）】
  什么时候需要：要传 >50MB 的文件、要下 >20MB 的文件、不想每次走公网、
                或希望 getFile 直接拿到本地绝对路径时。
  官方服务器：上传 50MB / 下载 20MB；
  本地服务器：上传 2000MB / 下载无大小限制，可用 HTTP + 任意端口，
              getFile 返回的 file_path 是服务器上的本地绝对路径，不用再下载。
  切换步骤：
       a. 先在官方服务器调 logOut（一个 token 同一时刻只能挂一种服务器）；
       b. 启动 telegram-bot-api 本地服务（--local 模式）；
       c. 咔咔连接里把 telegramApiBase 填成 http://127.0.0.1:8081 之类地址。
  取舍：本地服务器降低了延迟、解开了文件限制，但 webhook 的 HTTPS / 公网可达、
        证书、端口转发都得自己管；小机器人用默认官方服务器最省事。
  ★ telegramApiBase 与 mode 是正交的：polling / webhook 都能配本地服务器。

【测试环境】
  勾上「测试环境 / telegramTestEnv」，请求会走 /bot<token>/test/METHOD，
  在 Telegram 测试环境里跑，不碰真实会话、不发真实消息，适合调试新指令。
  测试环境的机器人要在 @BotFather 里单独建（选测试环境），别拿生产 token 打测试地址。

【网络 / 代理】
  服务器直连不通 api.telegram.org 时，在连接里填 telegramProxyUrl，
  例如 http://127.0.0.1:7897。这是连接级配置，跟「工具 → 视频解析」的
  X_PROXY_URL 环境变量是两回事。Webhook 方式还要求 Telegram 能反向访问你的公网地址，
  那是入向，和出向代理无关。

【Telegram 专属的坑】
  1. 群里收不到普通消息 → 隐私模式默认开启，机器人只收 /命令、@它 的回复和服务消息。
     给 @BotFather 发 /setprivacy 关闭；★ 关完必须把机器人移出群、再重新拉进群才生效。
  2. 401 Unauthorized → token 填错 / 已吊销 / 测试环境 token 打到生产地址。
  3. 429 Too Many Requests → 单聊约 1 条/秒、群组 20 条/分钟、广播约 30 条/秒。
     响应带 retry_after，按它的秒数退避重试，别无脑猛发；批量广播先排队限速。
  4. can't parse entities → MarkdownV2 没转义特殊字符，或改用 HTML（框架默认更省心）。
  5. 机器人之间互回死循环（Bot-to-Bot 默认关）→ 判断消息 from.is_bot，别回机器人。
  6. 图片 / 文件重复上传 → 复用 file_id，别每次重新传。
  7. 群里的指令要写 /cmd@你的机器人 才强制指向你的机器人；解析时把 @用户名 后缀剥掉。
  8. 插件页签：Telegram Bot 对应「Telegram」页签，插件目录前缀必须是 TG-plugin-。
  9. 回调地址不通 → 确认公网可达、端口是 443/80/88/8443 之一、反代原样转发
     /tgbot/<连接id>、Secret Token 一致、证书 CN / SAN 与域名匹配。
