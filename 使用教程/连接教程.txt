================================================================================
  咔咔珂 连接教程（现版本）
  涵盖：
    · OneBot / NapCat：反向 WS、正向 WS、HTTP 服务器、HTTP SSE 服务器、HTTP 客户端
    · QQ 官方机器人：官方 WS、官方 HTTPS（Webhook）
    · 微信 BOT：iLink 扫码登录 + 长轮询
================================================================================

【先看这几条】
1. 平时每个机器人账号只启用「一种」对接方式即可；OneBot 正反向 + 多种 HTTP 不要一起开，易重复收消息。
2. Access Token / Token 两边必须一致；两边都空 = 不鉴权。
3. 咔咔后台默认端口 8787（控制台），和 OneBot 监听口（6700/6701 等）不是一回事。
4. NapCat「容器安装」时：容器访问宿主机上的咔咔，一般用 Docker 网关
   http://172.17.0.1:端口
   （个别环境可能是 host.docker.internal 或宿主机内网 IP，以实际为准。）
5. 宿主机访问「已映射端口」的 NapCat，一般用
   http://127.0.0.1:端口
6. HTTP 上报（NapCat HTTP Client → 咔咔）鉴权：NapCat 用 Token 做 X-Signature，
   不是简单的 Bearer；咔咔已支持。Token 填一样即可。
7. 三种连接类型对应三套插件页签：
     OneBot / NapCat  →「插件」
     QQ 官方机器人    →「QQ官方机器人」
     微信 BOT         →「微信机器人」
   连接启用后，再在对应页签里按「该连接」开关插件。


--------------------------------------------------------------------------------
一、反向 WebSocket（推荐入门 · OneBot）
--------------------------------------------------------------------------------
含义：咔咔开 Server 监听；NapCat 用 WebSocket Client 连过来。

【咔咔】连接 → 添加 → OneBot「反向 WS」
  名称：随意，如「反向」
  监听地址：0.0.0.0          （仅本机可填 127.0.0.1）
  监听端口：6700             （常用默认）
  Access Token：如 10086     （可留空，两边一致即可）
  启用：开

【NapCat · 本机/非容器】网络 → WebSocket 客户端（Client）
  启用：开
  名称：随意
  URL：ws://127.0.0.1:6700
  Token：与咔咔相同
  其余按默认即可

【NapCat · Docker 容器】
  同上，但 URL 改为：
  ws://172.17.0.1:6700
  （咔咔必须监听 0.0.0.0:6700，不能只绑 127.0.0.1，否则容器连不上。）

【自检】
  咔咔日志有客户端连入；NapCat 无持续重连报错。


--------------------------------------------------------------------------------
二、正向 WebSocket
--------------------------------------------------------------------------------
含义：NapCat 开 WebSocket Server；咔咔主动连过去。

【咔咔】添加 → OneBot「正向 WS」
  名称：随意，如「正向」
  NapCat 地址：127.0.0.1     （宿主机访问已映射的 NapCat）
  NapCat 端口：3001          （常用；以 NapCat 实际为准）
  Access Token：与 NapCat 相同
  启用：开

【NapCat · 本机/非容器】网络 → WebSocket 服务端（Server）
  启用：开
  Host：0.0.0.0
  Port：3001
  Token：与咔咔相同

【NapCat · Docker 容器】
  NapCat：同上（容器内 0.0.0.0:3001，并做好端口映射到宿主机 3001）
  咔咔：地址仍填 127.0.0.1，端口填映射后的端口（如 3001）
  若咔咔也在另一容器且不在同一网络，则填 NapCat 容器 IP 或服务名，不要填 127.0.0.1。

【注意】
  正向端口不要填 6700（那是反向监听口，会连到咔咔自己）。
  正向与反向不要同时开同一套业务，以免重复收消息。


--------------------------------------------------------------------------------
三、HTTP 三种模式总览
--------------------------------------------------------------------------------
  ① HTTP 服务器      ：咔咔另开端口收 POST 上报；再调 NapCat HTTP API
  ② HTTP SSE 服务器  ：与①类似，并多支持 SSE 订阅；接 NapCat 填法同①
  ③ HTTP 客户端      ：不另开上报口；走咔咔主站 /onebot/http/<连接id>
                       并可主动连 NapCat 的 HTTP SSE

日常接 NapCat：优先 ①；不想多开端口再用 ③；② 一般给第三方 SSE 用。


--------------------------------------------------------------------------------
三-①、HTTP 服务器（最常用 HTTP）
--------------------------------------------------------------------------------
含义：NapCat HTTP Client 把事件 POST 到咔咔；咔咔再用 NapCat HTTP Server 调 API。

【咔咔】添加 →「HTTP 服务器」
  名称：随意，如「HTTP」
  监听地址：0.0.0.0
  监听端口：6701
  NapCat HTTP API（apiUrl）：http://127.0.0.1:3000
  Access Token：如 10086
  启用：开

  成功日志类似：
  HTTP 事件上报监听: http://127.0.0.1:6701 （API: http://127.0.0.1:3000）

【NapCat · 本机/非容器】
  1）HTTP 服务端（Server）—— 给咔咔调 API
     启用：开
     Host：0.0.0.0
     Port：3000
     Token：10086（与咔咔一致）
     消息格式：Array（常用）

  2）HTTP 客户端（Client）—— 事件上报到咔咔
     启用：开
     URL：http://127.0.0.1:6701
     Token：10086
     消息格式：Array

【NapCat · Docker 容器】
  HTTP Server：同上（映射宿主机 3000）
  HTTP Client 的 URL 改为：
     http://172.17.0.1:6701
  咔咔 apiUrl 仍用：
     http://127.0.0.1:3000
  （前提：容器 3000 已映射到宿主机）
  咔咔监听必须是 0.0.0.0:6701，不要用 127.0.0.1（否则容器报 ECONNREFUSED）。

【常见报错】
  ECONNREFUSED 172.17.0.x:6701
    → URL/监听地址不对，或咔咔只绑了 127.0.0.1
  401 Unauthorized
    → Token 不一致；或旧版咔咔不认 X-Signature（请更新咔咔后再试）


--------------------------------------------------------------------------------
三-②、HTTP SSE 服务器
--------------------------------------------------------------------------------
含义：咔咔监听端口，可收 NapCat 的 POST；也可让其他程序用 SSE 订阅事件。
接 NapCat 时，参数与「HTTP 服务器」相同。

【咔咔】添加 →「HTTP SSE 服务器」
  监听地址：0.0.0.0
  监听端口：6701（或其它空闲口）
  NapCat HTTP API：http://127.0.0.1:3000
  Access Token：与 NapCat 一致
  启用：开

【NapCat · 本机】
  HTTP Server：0.0.0.0:3000 + Token
  HTTP Client：http://127.0.0.1:6701 + Token

【NapCat · Docker】
  HTTP Client：http://172.17.0.1:6701 + Token
  其余同「HTTP 服务器」

说明：NapCat 侧一般不必再开「HTTP SSE 服务端」；那是 NapCat 对外推 SSE 用的。
咔咔这种模式是「咔咔自己当 SSE 源」。


--------------------------------------------------------------------------------
三-③、HTTP 客户端
--------------------------------------------------------------------------------
含义：不另开 6701；事件可 POST 到咔咔控制台端口上的路径；
同时咔咔会尝试连接 NapCat 的 HTTP SSE，并用 NapCat HTTP API 发动作。

【咔咔】添加 →「HTTP 客户端」
  名称：随意
  NapCat 地址：127.0.0.1
  NapCat 端口：3000          （指向 NapCat HTTP API / SSE 根地址）
  Access Token：如 10086
  启用：开

  启用后在连接详情/日志中查看「事件上报地址」，形如：
  http://127.0.0.1:8787/onebot/http/<连接id>
  （8787 为咔咔后台端口；连接 id 以界面为准，可复制。）

【NapCat · 本机/非容器】（推荐：HTTP Client 上报）
  1）HTTP Server：0.0.0.0:3000，Token 一致（API）
  2）HTTP Client：
     URL：http://127.0.0.1:8787/onebot/http/<连接id>
     Token：与咔咔一致
  3）可选：若希望咔咔用 SSE 拉事件，再开 NapCat「HTTP SSE 服务端」
     （端口需与咔咔填写的 NapCat 地址端口一致，或保证能连上）

【NapCat · Docker 容器】
  HTTP Server：映射 3000 到宿主机；咔咔填 127.0.0.1:3000
  HTTP Client URL：
     http://172.17.0.1:8787/onebot/http/<连接id>
  （不要用 127.0.0.1，那是容器自己，不是宿主机咔咔。）

【注意】
  改用本模式时，请关掉原来的「HTTP 服务器 6701」那条，避免同一事件报两次。
  安全组/防火墙需放行 8787（若从外网或跨机访问上报地址）。


--------------------------------------------------------------------------------
四、QQ 官方机器人
--------------------------------------------------------------------------------

【官方 WS】（推荐，无需域名）
  咔咔主动连腾讯 Gateway，一般不需要域名/反代。

  咔咔：连接 → 添加 →「QQ 官方 · WS」
    名称：随意
    AppID / AppSecret：开放平台「机器人」凭证
    沙箱：调试期可开；正式环境关
    添加后默认关闭 → 确认信息无误再启用

  昵称与头像由官方 API 自动拉取，无需手填。

【官方 HTTPS】（Webhook，需域名 + HTTPS）
  含义：腾讯向你的回调地址 POST 事件；咔咔挂在主端口路径上等待。

  咔咔：
    添加 →「QQ 官方 · HTTPS」
    AppID / AppSecret / 沙箱
    公网回调基址（可选）：https://你的域名
      （填了之后界面可一键复制完整回调 URL）
    启用后复制：
      回调 URL：https://你的域名/gfbot/<连接id>
      或路径：/gfbot/<连接id>

  反代（宝塔等）：
    域名 → http://127.0.0.1:8787
    （与后台同一条反代即可，路径原样转发）

  开放平台：
    回调地址填上面复制的 HTTPS URL
    公网端口须为 80/443/8080/8443（用 443 最省事）
    保存时平台会发校验请求，咔咔自动用 AppSecret 签名响应

  注意：
    - 必须用可信 HTTPS 证书（反代搞定）
    - 不要和官方 WS 对同一机器人重复开两套收事件
    - 插件请到「QQ官方机器人」页签，按该连接开关


--------------------------------------------------------------------------------
五、微信 BOT（iLink）
--------------------------------------------------------------------------------
含义：走微信官方 iLink 渠道；手机微信扫码登录后，咔咔长轮询收消息并回发。
不需要 NapCat，也不需要公网域名。

【添加】
  咔咔：连接 → 添加 →「微信BOT」
  名称：随意，如「微信」
  添加成功后默认未登录；界面会提示先扫码。

【扫码登录】
  1. 在连接卡片点「扫码登录」（未登录时点「启用」也会自动弹出二维码）
  2. 用微信扫描弹窗中的二维码，并在手机上确认
  3. 若二维码图未显示，可用弹窗里的「备用登录链接」在浏览器打开后再用微信扫
  4. 登录成功后，连接摘要会显示账号信息；凭证保存在本机 data/ 中

【启用】
  登录成功后再打开「启用」开关，即可开始收发。
  若未登录就点启用 → 会先弹出扫码，登录成功后再启用。

【退出 / 换号】
  点「清除登录」或重新「扫码登录」即可换号。
  清除后需重新扫码才能收消息。

【插件】
  到「微信机器人」页签，对该连接打开需要的插件（如 WX-plugin-wxbot）。
  改插件代码后：对该连接关闭再打开对应插件，才会刷新 plugins_two 副本。

【注意】
  - 一台咔咔可添加多个微信BOT连接（多号），各自独立登录与插件开关
  - 不依赖 6700/6701 等 OneBot 端口；也不占用 QQ 官方回调路径
  - 语音气泡受 iLink 平台限制时，插件可能以「文件」形式发送音频，属正常兼容


--------------------------------------------------------------------------------
六、参数速查表
--------------------------------------------------------------------------------

模式              咔咔关键字段              对端
--------------  ----------------------  ----------------------------------
反向 WS          监听 0.0.0.0:6700       NapCat WS Client → ws://宿主:6700
正向 WS          连 127.0.0.1:3001       NapCat WS Server  0.0.0.0:3001
HTTP 服务器      监听 :6701 + apiUrl     NapCat Server:3000 + Client→:6701
HTTP SSE 服务器  同 HTTP 服务器          同 HTTP 服务器
HTTP 客户端      连 NapCat:3000          Server:3000 + Client→:8787/onebot/http/id
QQ 官方 · WS     AppID + Secret          腾讯 Gateway（咔咔主动连）
QQ 官方 · HTTPS  AppID + Secret + 域名   回调 https://域名/gfbot/<连接id>
微信 BOT         扫码登录即可             微信 iLink（无需端口/域名）

「宿主」在本机安装 = 127.0.0.1
「宿主」在 NapCat 容器内访问咔咔 = 172.17.0.1（常见）


--------------------------------------------------------------------------------
七、推荐组合（按场景）
--------------------------------------------------------------------------------
A. 最省事、本机都装在一起（QQ · NapCat）
   → 反向 WS：咔咔 6700 + NapCat WS Client ws://127.0.0.1:6700

B. NapCat 在 Docker，咔咔在宿主机
   → 反向 WS：咔咔 0.0.0.0:6700 + NapCat ws://172.17.0.1:6700
   或 HTTP 服务器：咔咔 0.0.0.0:6701 + NapCat Client http://172.17.0.1:6701
                 + NapCat Server 3000 映射到宿主机，咔咔 apiUrl=http://127.0.0.1:3000

C. 只有一个对外端口 / 反代域名（QQ · NapCat）
   → HTTP 客户端：上报走 http(s)://域名/onebot/http/<id>

D. QQ 开放平台官方机器人、不想折腾反向代理
   → QQ 官方 · WS（填 AppID/Secret 启用即可）

E. QQ 官方机器人必须走 Webhook
   → QQ 官方 · HTTPS + 域名反代到 8787，回调填 /gfbot/<连接id>

F. 微信个人号 / 企业微信 iLink 机器人渠道
   → 微信BOT：添加 → 扫码 → 启用 →「微信机器人」页签开插件


--------------------------------------------------------------------------------
八、配置改完后
--------------------------------------------------------------------------------
1. 保存 NapCat / 开放平台 / 微信扫码状态，并确认对应连接已启用。
2. 咔咔连接开关打开；必要时重启咔咔。
3. 往测试群/私聊发一条消息，看咔咔是否出现上报日志。
4. 到对应插件页签确认该连接下插件已开启。
5. 端口占用可用 mk「端口验证 → 杀掉进程」排查（OneBot / 控制台端口）。
6. Linux 上如何安装/使用 mk 脚本（NapCat、咔咔启停等）见同目录《MK工具教程.txt》。
