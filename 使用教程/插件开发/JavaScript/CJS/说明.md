# JavaScript 轨 · CJS 版（野鸡 JS 开发）：`require` + `module.exports`，不用编译

> 不用编译。改完 `index.js` 存盘 → 覆盖 `plugins/` 里的文件 → 重载插件，就生效了。
>
> **这条轨和「ESM 版」是同一件事的两种写法**，效果、目录结构、钩子名字全都一样，只有「怎么交出函数 / 怎么引入别的文件」不同：
>
> | | ESM 版 | CJS 版（本页） |
> | --- | --- | --- |
> | 交出钩子 | `export async function plugin_init(ctx) {}` | `module.exports = { plugin_init }` |
> | 引入别的文件 | `import x from './x.js'` | `const x = require('./x.js')` |
> | 入口文件名 | `index.mjs` | `index.js`（建议） |
> | `package.json` 的 `type` | `"module"` | `"commonjs"` |
>
> **该选哪条**：新写插件选 ESM 版；手上是从 NapCat 之类宿主搬过来的老插件、或者你就是习惯 `require` 写法，选这条。**两种写法可以同时装在同一个机器人里**，互不影响。
>
> **好消息**：宿主带了 CJS 兼容层，所以老插件**不用改一行代码**就能直接放进去——`module.exports`、`require('./helper.js')` 都照常工作，也不用为了跑起来去加 `package.json`。

## 一、先明确要做出来的效果

| 对方发送 | 机器人做什么 |
| --- | --- |
| `你好` | 回复 `你好呀` |
| `帮助` | 回复可用指令列表 |
| `ping` | 回复 `pong` |
| `禁言 QQ号 秒数` | 调 `set_group_ban`（仅群聊，机器人需有群管权限；秒数 `0` 为解除） |

判断方式一律是**正向匹配**：`if (text === '你好') { … }`。不要写「不等于就拦下来」。

## 二、装载用的文件夹

把下面这个 `kakake-plugin-hello-cjs` **整个文件夹**拷到：

```text
咔咔珂项目根目录/plugins/kakake-plugin-hello-cjs/
```

文件夹里应该有三样：

```text
kakake-plugin-hello-cjs/
  package.json   ← 名字、入口（main）、type: commonjs
  plugin.json    ← 显示名、入口（entry）、简介
  index.js       ← 你的代码
  插件文档.md     ← 可选：控制台插件列表的「查看说明」就读它（示例夹里已带一份）
```

> **别只丢一个 `index.js`**。入口查找顺序是 `plugin.json.entry` → `package.json.main` → `index.mjs` → `index.js` → `index.cjs` → `main.mjs` → `main.js` → `main.cjs`：只放 `index.js`（或 `index.cjs`）**也能加载、也能跑**，但控制台里会显示成文件夹名（`kakake-plugin-hello-cjs`）、没有中文名和简介。想让插件在列表里像个正经插件，两个 JSON 一起放。

### 什么时候必须放 `package.json`

兼容层已经把「入口是 CJS」和「包内 `.js` 是 CJS」两件事都接管了，所以：

| 你的插件长什么样 | 不放 `package.json` 能跑吗 |
| --- | --- |
| 单文件 `index.js`，只有 `module.exports` | 能跑 |
| 多文件，入口 `require('./helper.js')` | 能跑（兼容层会连包内 `.js` 一起按 CJS 编译） |
| 入口用 `import` 引了一个 CJS 写法的 `.js` | 不能——混装要自己处理，见第八节 |

> 就算能跑，**也建议放一个**：`package.json` 里写 `"type": "commonjs"`，等于把这个插件包的模块格式明明白白告诉 Node，比靠兼容层兜底更稳，控制台里也才有中文名和简介。

> **不要写 `"type": "module"`**：那是在声明这个包用 ESM，插件包的 `.js` 会被当成 ESM 解析，里面的 `module.exports` 立刻报错。要么写 `"commonjs"`，要么干脆不写这个字段。

## 三、两个 JSON 各管什么

### `package.json`

- **`name`** —— 建议和文件夹名一致；
- **`version`** —— 版本号；
- **`type`** —— 固定 `"commonjs"`（也可以不写）；
- **`main`** —— 入口，写 `index.js`；
- **`plugin`** —— 控制台里显示的**中文名**；
- **`description`** —— 简介。

### `plugin.json`

- **`name`** —— 插件 ID；
- **`displayName`** —— 中文显示名；
- **`author`** / **`version`** —— 作者 / 版本；
- **`entry`** —— 入口，写 `index.js`（要和 `package.json` 的 `main` 一致）；
- **`description`** —— 简介。

> **改插件名时**：插件 ID 永远是**文件夹名**，控制台显示的**插件名**按 `plugin.json.displayName` → `package.json.plugin` → `package.json.name` → `plugin.json.name` → 文件夹名 依次取第一个有值的。所以改名要动四处：文件夹名、`plugin.json.displayName`、`package.json.plugin`，以及两个 JSON 里的 `name`（和文件夹名保持一致最省事）。

## 四、CJS 的三个写法要点

**① 钩子不是 `export` 出去的，是「挂到 `module.exports` 上」**

```js
// 先写函数（这里不需要 export）
async function plugin_init(ctx) {
  ctx.logger.info('插件已加载');
}

async function plugin_onmessage(ctx, event) {
  // …
}

// 最后统一交出去，写成**字面量对象**，框架靠名字找到它们
module.exports = {
  plugin_init,
  plugin_onmessage,
};
```

- 名字必须**和框架认的名字完全一致**：`plugin_init`、`plugin_onmessage`、`plugin_onevent`、`plugin_cleanup`；
- **用字面量对象**。`module.exports = { plugin_init }` 这样写就行；不建议写成 `module.exports = 运行时拼出来的对象`（框架也认，但没必要冒险）。

**② 别的文件用 `require` 引，不用 `import`**

```js
// 同目录
const { greet } = require('./helper.js');

// 子目录
const { pad } = require('./lib/util.js');

// Node 内置模块
const fs = require('node:fs');
const path = require('node:path');
```

- **`.js` 后缀建议写全**。ESM 里可以省，CJS 里 Node 会尝试补全，但写全不会出错、也不会因为目录同名文件产生歧义；
- 相对路径的 `./` 不能省（`require('helper.js')` 会被当成 npm 包名去找，找不到就报错）；
- **`require` 是同步的**：`const x = require('./x.js')` 当场就拿到了 `module.exports`，不用 `await`；
- 只在这个文件里用到的模块，`import` 那套习惯在这里换成 `require` 即可，函数体写法完全不变。

**③ 单个函数要交出去时用 `exports`**

```js
exports.plugin_init = async function (ctx) { /* … */ };
// 等价于
module.exports.plugin_init = async function (ctx) { /* … */ };
```

> ⚠️ **不要写 `exports = { plugin_init }`**。`exports` 只是 `module.exports` 的一个初始引用，直接给它**重新赋值**会把引用断开，框架拿到的是一个空对象——插件会被判定成「缺少 plugin_init」。要整体交出去就写 `module.exports = { … }`。

## 五、下面的代码窗怎么读

> **分步 ①～⑥ 都是片段，不能单独运行**：它们是拆开的零件（① 假设已有 `event`，③④⑤ 依赖 ① 和 ②）。真正装载进 `plugins/` 的，是后面那份**完整可运行**的 `index.js`。

1. **分步 ①～⑥** —— 每块只讲一件事：
   - ① 取出对方文字 → ② 怎么发回复 → ③ 匹配「你好」 → ④ 匹配「帮助」 → ⑤ 匹配「ping」 → ⑥ 调用协议接口（禁言）
2. **完整可运行** —— 把 ①～⑥ 拼起来的整份 `index.js`，装载就用这一份；
3. **两个 JSON** —— 装载包必备。

### 读代码时请特别注意这两点

**① `getText` 只认 `event.message` 数组**

它用 `Array.isArray(event.message) ? event.message : []` 兜底。好处是不报错，坏处是：**万一协议端上报的是 CQ 字符串，它会安静地返回空串，所有指令全部失效**，你只会看到「机器人不理我」。

所以完整示例里加了一行自检，日志会直接提醒你：

```js
if (typeof event.message === 'string') {
  ctx.logger.warn('当前连接上报的是 CQ 字符串，请在协议端把消息上报格式改成数组（array）');
}
```

**② `ctx.actions.call` 成功给数据，失败直接抛错**

- 成功：返回接口的 `data`（`send_group_msg` 里通常是 `{ message_id }`）；
- 失败：**抛异常**（机器人不是管理员、接口名写错、连接断开、超时都会抛）。

所以调用接口要包一层 `try / catch`，否则失败时你什么都看不到：

```js
try {
  await ctx.actions.call('set_group_ban', {
    group_id: event.group_id,
    user_id: qq,
    duration: seconds,
  });
  await sendReply(ctx, event, `已禁言 ${qq} ${seconds} 秒`);
} catch (err) {
  // err.message 里就是失败原因
  await sendReply(ctx, event, `操作失败：${err && err.message ? err.message : err}`);
}
```

## 六、收尾：别忘了 `plugin_cleanup`

只要在 `plugin_init` 里挂了定时器、开了连接、订阅了事件，就应该在 `plugin_cleanup` 里收掉。它在插件**关闭或重载**时被调用：

```js
// 挂在模块作用域，供 init 和 cleanup 共用（CJS 每个文件就是一个作用域，这里的变量不会漏到外面）
let timer = null;

async function plugin_init(ctx) {
  ctx.logger.info('插件已加载');
  timer = setInterval(() => {
    // 定时要做的事
  }, 60 * 60 * 1000);
}

async function plugin_cleanup(ctx) {
  ctx.logger.info('插件正在卸载 / 重载，开始收尾');
  if (timer) {
    clearInterval(timer);
    timer = null;
  }
  // 其它收尾：断开连接、把内存里的数据落盘等
}

module.exports = { plugin_init, plugin_cleanup };
```

> **不写会怎样**：插件每次重载都会再挂一个定时器，越跑越多，最后连日志都刷不动。
>
> **`plugin_cleanup` 单独加的时候**，记得把上面 `module.exports` 那一行也补上它——漏写了函数就白写，框架看不到。

## 七、装好怎么测

1. 拷好文件夹 → 打开插件的**总开关**；
2. 打开**连接**里的该插件开关；
3. 逐条发：`你好`、`帮助`、`ping`，看回复是否正确；
4. 群里试 `禁言 <QQ> 10`（需管权限）；
5. 到「日志」页确认加载信息与报错。

> **日志里看到 `已按 CJS 兼容模式加载`**：说明这个插件的入口是 CJS 写法，但会被 Node 当成 ESM 解析，是兼容层把它救回来的。**能正常跑，不用管**；想让它走「正规路径」，在插件目录补一个写着 `"type": "commonjs"` 的 `package.json` 即可。

## 八、学会之后，改哪里？

- **改触发词或回复**：改完整 `index.js` 里对应的 `if (text === '…')` 与 `sendReply(…, '…')`；
- **调别的协议接口**：照分步 ⑥ 的写法，把 `'set_group_ban'` 换成目标接口名，参数对象换成该接口需要的字段——**常用接口名与必需参数见「总览」第六节**；
- **想 @ 人 / 引用回复 / 发图片**：把 `message` 数组里多加几个消息段，段类型和字段见「总览」第六节；
- **想区分群聊 / 私聊**：看 `event.message_type`；
- **想拿发送者 QQ / 群号**：看 `event.user_id` / `event.group_id`；
- **想拿昵称、群名片、是不是管理员**：看 `event.sender`；想撤回消息用 `event.message_id`——**完整事件字段见「总览」第五节**；
- **想存数据**：写到 `ctx.dataPath` 目录，别写死在插件目录里（重装插件会被覆盖）；
- **想给用户写用法说明**：在插件目录放 `插件文档.md`，控制台插件列表会出现「查看说明」。

### 报错怎么读（CJS 专有）

| 日志里的报错 | 什么意思 | 怎么办 |
| --- | --- | --- |
| `缺少 plugin_init` | 交出去的对象里没有 `plugin_init` | 检查名字拼写；是不是写成了 `exports = { … }`（见第四节 ③），改成 `module.exports = { … }` |
| `Cannot find module './helper.js'` | `require` 的路径不对 | 相对路径的 `./` 别省、`.js` 后缀写全，并确认那个文件真的拷进插件目录了 |
| `插件把 CommonJS 写法的 .js 当成 ES module 引了` | 入口用 `import` 引了一个 CJS 写法的 `.js`（报错里会点名是哪个文件） | 见下面的混合写法说明 |
| `插件入口把两套写法混在同一个文件里了` | 同一个文件里既有 `import` / `export`，又有 `require` / `module.exports` | 见下面的混合写法说明第 3 条 |

### CJS 和 ESM 混着写怎么办

兼容层管的是 **`require()` 这条路**：入口是 CJS，它 `require` 进来的包内 `.js` 都会按 CJS 编译。它管不到的是**反过来**的情况——入口本身用 `import`/`export`，却又 `import` 了一个写着 `module.exports` 的 `.js`：这条走的是 ESM 加载器，不看 CJS 兼容层。

真遇到这种混装，两条路任选一条：

1. **把那个文件改名成 `.cjs`**（`require('./helper.cjs')` 或 `import x from './helper.cjs'` 都认），格式不再有歧义；
2. **在插件目录放一个不带 `"type": "module"` 的 `package.json`**，让整个插件包默认按 CommonJS 解析。

> **最省心的做法是别混**：一个插件要么整包 CJS（本页），要么整包 ESM（ESM 版）。

> ⚠️ **第 3 种混法救不回来**：同一个文件里既有 `import` / `export`，又有 `require` / `module.exports`。这个文件当 ESM 跑会报 `require is not defined`，当 CJS 跑又会报 `Cannot use import statement outside a module`——改名、加 `package.json` 都没用，只能**把其中一套写法换掉**（整份改成一个格式）。日志里对应的报错是「插件入口把两套写法混在同一个文件里了」。
