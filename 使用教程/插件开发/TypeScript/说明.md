# TypeScript 轨（野鸡 TS 开发）：源码 → 构建 → 装产物

> 这一轨和「其它插件源码」的做法一致：写 `src/index.ts` → `npm run build` → 把**生成的产物夹**拷进 `plugins/`。

业务逻辑与 JavaScript 轨完全一样：**正向匹配**指令、`ctx.actions.call` 调协议、`你好` / `帮助` / `ping` / `禁言 QQ号 秒数`。

---

## 一、两棵目录树

### 源码工程（你写代码、执行构建）

```text
使用教程/插件开发/TypeScript/hello-src/
  package.json / plugin.json / tsconfig.json / vite.config.ts
  插件文档.md               ← 可选：构建时会一起拷进产物夹
  src/index.ts
  kakake-plugin-hello/     ← npm run build 后生成的产物夹
    package.json
    plugin.json
    index.mjs
    插件文档.md
```

### 装进咔咔珂（只拷产物夹）

```text
plugins/kakake-plugin-hello/
  package.json
  plugin.json
  index.mjs
  插件文档.md   ← 可选：控制台插件列表的「查看说明」就读它
```

> **两个常见错误**：只拷一个 `index.mjs`（能跑，但插件列表里会显示成文件夹名、没有中文名和简介——两个 JSON 是显示名与简介的来源）；或者把整个 `hello-src`（含 `node_modules`、源码、构建配置）当插件装进去。正确做法是**只拷产物夹**。

---

## 二、依赖与构建

进入 `hello-src/` 目录后执行：

```bash
npm install
npm run build
```

- `npm install` —— 拉取 `vite`、`typescript` 等构建工具；
- `npm run build` —— 生成 `kakake-plugin-hello/` 三件套。

构建完成后确认产物夹里确实有 `package.json`、`plugin.json`、`index.mjs`（加上可选的 `插件文档.md`），再把**这个产物夹**拷到 `plugins/`。

> **改了 `src/index.ts` 就必须重新 build**，然后覆盖产物夹。运行时读的是产物，不是源码——这是新手最常见的「改了没反应」。

---

## 三、源码配置要点

### `package.json` / `plugin.json`

- `main` 与 `entry` 都指向产物里的 `index.mjs`；
- 改插件名时：插件 ID 永远是**文件夹名**，控制台显示的**插件名**按 `plugin.json.displayName` → `package.json.plugin` → `package.json.name` → `plugin.json.name` → 文件夹名 依次取第一个有值的。所以改名要动四处：文件夹名、`plugin.json.displayName`、`package.json.plugin`，以及两个 JSON 里的 `name`（和文件夹名保持一致最省事）。

### `vite.config.ts`

- `outDir: 'kakake-plugin-hello'` —— 决定产物文件夹名；
- 负责把 `src/index.ts` 打成 `index.mjs`；
- 构建结束时把两个 JSON 写入产物夹。

## 四、关于类型：这是教学简化版

示例里的 `type Ctx = { … }` 是**为了让你看得懂而手写的简化类型**，它只声明了教程用到的几个字段，方便编辑器给出提示。

真实宿主提供了完整的类型定义，字段比示例多得多（配置、路由、数据目录、框架环境等）：

- `NapCatPluginContext` —— 也就是 `ctx` 的真实类型；
- `PluginModule` —— 插件可导出的全部钩子（`plugin_init`、`plugin_onmessage`、`plugin_onevent`、`plugin_cleanup` 等）。

类型定义位于宿主源码 `src/plugin/plugin.types.ts`。等你熟悉之后，可以直接引入真实类型替代这里的 `Ctx`，编辑器就能补全 `ctx` 上的所有能力——包括 `dataPath`（插件专属数据目录）、`router`（插件 HTTP 路由与后台页面）、`configPath`、`pluginManager` 等本教程没讲的字段。

> 顺带一提：`logger`、`actions.call` 等字段名与真实类型**完全一致**，示例代码可以直接搬进正式插件。

### `MsgEvent` 也只声明了 4 个字段

真实事件里还有 `message_id`（撤回 / 引用要用）、`sender`（昵称、群名片、`owner` / `admin` / `member` 角色）、`self_id`、`time` 等。**完整字段表见「总览」第五节**；用到时把它们补进 `MsgEvent` 就行。

## 五、代码窗怎么读

> **分步 ①～⑥ 都是片段，不能单独运行**：它们是拆开的零件（① 假设已有 `event`，③④⑤ 依赖 ① 和 ②）。真正装载进 `plugins/` 的，是构建出来的产物夹。

1. **分步 ①～⑥** —— ①取出文字 → ②怎么发回复 → ③你好 → ④帮助 → ⑤ping → ⑥调接口（禁言）；
2. **源码配置** —— `package.json` / `plugin.json` / `tsconfig.json` / `vite.config.ts`（照抄即可）；
3. **完整源码 `src/index.ts`** —— 可运行的整份，改完要 build；
4. **产物三件套** —— 构建生成，一般不用手改；真正装进 `plugins/` 的就是这一夹。

### 读代码时请特别注意这两点

**① `getText` 只认 `event.message` 数组**

它用 `Array.isArray(event.message) ? event.message : []` 兜底。好处是不报错，坏处是：**万一协议端上报的是 CQ 字符串，它会安静地返回空串，所有指令全部失效**，你只会看到「机器人不理我」。

所以完整源码里加了一行自检：

```ts
if (typeof event.message === 'string') {
  ctx.logger.warn('当前连接上报的是 CQ 字符串，请在协议端把消息上报格式改成数组（array）');
}
```

**② `ctx.actions.call` 成功给数据，失败直接抛错**

- 成功：返回接口的 `data`（`send_group_msg` 里通常是 `{ message_id }`）；
- 失败：**抛异常**（机器人不是管理员、接口名写错、连接断开、超时都会抛）。

所以调用接口要包一层 `try / catch`：

```ts
try {
  await ctx.actions.call('set_group_ban', {
    group_id: event.group_id,
    user_id: qq,
    duration: seconds,
  });
  await sendReply(ctx, event, `已禁言 ${qq} ${seconds} 秒`);
} catch (err) {
  const msg = err instanceof Error ? err.message : String(err);
  await sendReply(ctx, event, `操作失败：${msg}`);
}
```

## 六、收尾：别忘了 `plugin_cleanup`

只要在 `plugin_init` 里挂了定时器、开了连接、订阅了事件，就应该在 `plugin_cleanup` 里收掉。它在插件**关闭或重载**时被调用：

```ts
let timer: ReturnType<typeof setInterval> | null = null;

export async function plugin_init(ctx: Ctx) {
  ctx.logger.info('插件已加载');
  timer = setInterval(() => {
    // 定时要做的事
  }, 60 * 60 * 1000);
}

export async function plugin_cleanup(ctx: Ctx) {
  ctx.logger.info('插件正在卸载 / 重载，开始收尾');
  if (timer) {
    clearInterval(timer);
    timer = null;
  }
}
```

> **不写会怎样**：插件每次重载都会再挂一个定时器，越跑越多，最后连日志都刷不动。

## 七、装好怎么测

1. 拷**产物夹**到 `plugins/` → 打开插件的**总开关**；
2. 打开**连接**里的该插件开关；
3. 逐条发：`你好`、`帮助`、`ping`；
4. 群里试 `禁言 <QQ> 10`（需管权限）；
5. 到「日志」页确认没有报错。

## 八、学会之后，改哪里？

- **改触发词或回复**：改 `src/index.ts` 里的 `if (text === '…')` 与 `sendReply(…, '…')`，然后重新 build；
- **调别的协议接口**：照分步 ⑥，换接口名与参数对象——**常用接口名与必需参数见「总览」第六节**；
- **想 @ 人 / 引用回复 / 发图片**：把 `message` 数组里多加几个消息段，段类型和字段见「总览」第六节；
- **加类型提示**：把 `Ctx` 换成宿主的 `NapCatPluginContext`（见第四节）；
- **想区分群聊 / 私聊**：看 `event.message_type`；
- **想拿昵称、群名片、是不是管理员**：看 `event.sender`；想撤回消息用 `event.message_id`——**完整事件字段见「总览」第五节**；
- **想存数据**：写到 `ctx.dataPath` 目录，别写死在插件目录里（重装插件会被覆盖）；
- **想给用户写用法说明**：在产物夹里放 `插件文档.md`，控制台插件列表会出现「查看说明」；
- **想做配置项和网页后台**：本教程不涉及，可对照「其他插件源码」里的真实插件（如 `MK_AI`）来写，类型见 `src/plugin/plugin.types.ts`。
