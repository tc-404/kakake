# QQ 官方机器人（GF-）插件开发手册

> **先看这一句**：`GF-` 是 **QQ 官方机器人**（QQ 开放平台，`bot.q.qq.com` API v2）的插件，
> **和 OneBot11 / NapCat 插件（`kakake-`）是两套完全不同的东西**。
> 事件结构不一样、调接口的方式不一样、能用的能力也不一样。
> **禁止**把 `kakake-` 那套（`send_group_msg`、消息段数组、`event.user_id`）套到 `GF-` 插件上。
>
> 只写 OneBot 插件的话，去读 `前言.md`；**这里只讲 GF-**。
>
> 本手册对齐两份来源：
> ① 官方文档 <https://bot.q.qq.com/wiki/develop/api-v2/>；
> ② 本宿主的真实实现（`src/connection/qq-official-ws.client.ts`、`src/plugin/gf-plugin.manager.ts`）。
> 二者若冲突，以宿主实际行为为准（宿主是「事件原样透传 + REST 直通」）。

## 一、目录与命名（硬规则）

1. 文件夹**必须以 `GF-` 开头**，且**大小写敏感**（是 `GF-`，不是 `gf-`）。例如 `GF-plugin-checkin`。
   - 写成 `gf-checkin` / `Gf-xxx` 都不会被当成 GF 插件，宿主**根本不会加载**它。
2. 安装源在 `plugins/`，按机器人账号隔离的运行副本在 `plugins_two/<AppID>/`。
3. 入口导出与 OneBot 插件同名：`plugin_init` / `plugin_onmessage` / `plugin_onevent` / `plugin_cleanup`。
   - **名字一样，但 `event` 的结构完全不一样**，见下节。
4. `package.json` / `plugin.json` 的字段同 `前言.md`（`main`/`entry`、`plugin`/`displayName`、`description`），
   CJS（`require` + `module.exports`）和 ESM 都支持。

## 二、插件被调用了几次、按什么顺序

宿主收到一条官方 Gateway 事件后，会做两件事：

```text
Gateway payload { id, op:0, s, t, d }
        │  宿主只取 d，并把 t 补回事件对象
        ▼
event = { ...d, t: 'GROUP_AT_MESSAGE_CREATE', qq_official: true }
// 若机器人开了「接收所有消息」，群内普通消息的 t 是 'GROUP_MESSAGE_CREATE'（见 §3.1）
        │
        ├─► plugin_onevent(ctx, event)      // 每一类事件都会调用
        └─► plugin_onmessage(ctx, event)    // 也是每一类事件都会调用！
```

**两个重点（和 OneBot 不同）**：

1. **字段是「平铺」的**：`content` / `group_openid` / `author` 直接挂在事件对象顶层，
   不是包在 `event.d` 里，也没有 `event.message` 消息段数组。
2. **`plugin_onmessage` 会收到所有事件**（包括 `GROUP_ADD_ROBOT`、`INTERACTION_CREATE` 等），
   不只是消息。所以 `plugin_onmessage` 里**第一件事就是按 `event.t` 过滤**，否则进群事件也会被你当成消息处理。

宿主还会额外补一个 `event.qq_official = true` 标记，方便插件判断来源（一般不直接用，用 `event.t` 更准确）。

> 同一会话（同一个 `group_openid` / `user_openid`）的事件是**串行**派发的，
> 跨会话才并发——这样才能保证被动回复的先后顺序。

## 三、事件总表

事件名在 `event.t` 里。下表按 intent 分组，`✅` 表示宿主默认订阅、开箱即用。

### 3.1 群聊 / 单聊（`GROUP_AND_C2C_EVENT` = 1<<25）✅

| `event.t` | 触发时机 | 取「会话 id」用什么 | 备注 |
| --- | --- | --- | --- |
| `C2C_MESSAGE_CREATE` | 用户在**单聊**里发消息 | `event.author.user_openid` | **最常用**；`content` 是纯文本 |
| `GROUP_AT_MESSAGE_CREATE` | 用户在群里 **@机器人** 发消息 | `event.group_openid` | **最常用**；`content` 已去掉 @ 前缀 |
| `GROUP_MESSAGE_CREATE` | 群里**普通消息**（不 @ 机器人） | `event.group_openid` | **仅在机器人开启「接收所有消息」后才会推送**；字段与 `GROUP_AT_MESSAGE_CREATE` **完全一致**，只是不需要 @ |
| `GROUP_ADD_ROBOT` | 机器人**被拉进群** | `event.group_openid` | 字段见 §4.6 |
| `GROUP_DEL_ROBOT` | 机器人**被移出群** | `event.group_openid` | 字段见 §4.6 |
| `GROUP_MSG_REJECT` | 群管理员在机器人资料页**关闭**通知 | `event.group_openid` | 收到后该群不能再主动推送 |
| `GROUP_MSG_RECEIVE` | 群管理员在机器人资料页**开启**通知 | `event.group_openid` | 可用 `event_id` 做被动回复 |
| `FRIEND_ADD` | 用户添加机器人为好友 | `event.openid` | 可用 `event_id` 做被动回复 |
| `FRIEND_DEL` | 用户删除机器人 | `event.openid` | — |
| `C2C_MSG_REJECT` | 用户关闭「主动消息」推送 | `event.openid` | — |
| `C2C_MSG_RECEIVE` | 用户开启「主动消息」推送 | `event.openid` | 可用 `event_id` 做被动回复 |

> 🔴 **必须同时接受两个群消息事件名**：`GROUP_AT_MESSAGE_CREATE` **和** `GROUP_MESSAGE_CREATE`。
>
> 只要机器人在群设置里开了「机器人可获取的群聊消息范围 → 获取群内全部消息」，
> 群里的**每一条**消息（含 @ 机器人的）就都会以 `GROUP_MESSAGE_CREATE` 推送，
> **而不再推 `GROUP_AT_MESSAGE_CREATE`**。两个事件的字段一字不差，处理逻辑可以共用。
>
> 因此过滤条件必须写成：
>
> ```js
> const GROUP_TYPES = ['GROUP_AT_MESSAGE_CREATE', 'GROUP_MESSAGE_CREATE'];
> if (!GROUP_TYPES.includes(event.t) && event.t !== 'C2C_MESSAGE_CREATE') return;
> ```
>
> ⚠️ 只判 `GROUP_AT_MESSAGE_CREATE` 的插件在这种机器人上会**对群消息完全没反应**
> （日志里能看到事件进了框架，插件却一行都没执行）——这是「插件写出来不工作」最常见的坑，
> 排查时**第一件事就是去日志里确认 `event.t` 到底叫什么**。

### 3.2 群成员变更（`GROUP_MEMBER` = 1<<24）✅

| `event.t` | 触发时机 | 字段 |
| --- | --- | --- |
| `GROUP_MEMBER_ADD` | 群成员加入 | `group_openid` / `member_openid` / `op_member_openid` |
| `GROUP_MEMBER_REMOVE` | 群成员退出 | 同上 |

> ⚠️ `GROUP_MEMBER` 的位值是 `1<<24`。历史上不少代码把它错写成频道消息，宿主里已经修正并注释过。

### 3.3 互动/按钮回调（`INTERACTION` = 1<<26）✅

| `event.t` | 触发时机 | 备注 |
| --- | --- | --- |
| `INTERACTION_CREATE` | 用户点击**内联键盘按钮**、快捷菜单、消息反馈、授权等 | 详细见 [§十](#十互动事件与按钮回调)；`type=11/12` **必须回 ACK** |

### 3.4 频道类（**默认不订阅**，需要时在连接配置里显式填 intents）

| intent | 位值 | 事件 |
| --- | --- | --- |
| `GUILDS` | 1<<0 | `GUILD_CREATE` / `GUILD_UPDATE` / `GUILD_DELETE` / `CHANNEL_CREATE` / `CHANNEL_UPDATE` / `CHANNEL_DELETE` |
| `GUILD_MEMBERS` | 1<<1 | `GUILD_MEMBER_ADD` / `GUILD_MEMBER_UPDATE` / `GUILD_MEMBER_REMOVE` |
| `GUILD_MESSAGES` | 1<<9 | `MESSAGE_CREATE` / `MESSAGE_DELETE`（仅**私域**机器人） |
| `GUILD_MESSAGE_REACTIONS` | 1<<10 | `MESSAGE_REACTION_ADD` / `MESSAGE_REACTION_REMOVE` |
| `DIRECT_MESSAGE` | 1<<12 | `DIRECT_MESSAGE_CREATE` / `DIRECT_MESSAGE_DELETE`（频道私信） |
| `PUBLIC_GUILD_MESSAGES` | 1<<30 | `AT_MESSAGE_CREATE` / `PUBLIC_MESSAGE_DELETE`（**公域**频道 @ 消息） |
| `MESSAGE_AUDIT` | 1<<27 | `MESSAGE_AUDIT_PASS` / `MESSAGE_AUDIT_REJECT` |
| `FORUMS_EVENT` | 1<<28 | `FORUM_THREAD_*` / `FORUM_POST_*` / `FORUM_REPLY_*`（仅**私域**） |
| `AUDIO_ACTION` | 1<<29 | `AUDIO_START` / `AUDIO_FINISH` / `AUDIO_ON_MIC` / `AUDIO_OFF_MIC` |

> **为什么默认不带频道**：频道类事件需要机器人额外开通频道权限，没开通时平台会以
> `4014`（intents 未获授权）**直接关闭连接**。宿主默认只订阅
> `GROUP_AND_C2C_EVENT | GROUP_MEMBER | INTERACTION`，并在被 4014 拒绝时逐级降级（先摘 INTERACTION、再摘 GROUP_MEMBER），
> 尽量不因一个未授权位丢掉其它事件。
> 需要用频道，就在连接配置里显式填 `intents`，按上表把对应位一起 `|` 进去。

**频道消息的字段取法与群/单聊不同**：`event.channel_id` 是子频道 id，`event.guild_id` 是频道 id，
发送路径是 `/channels/{channel_id}/messages`，用户标识是 `event.author.id`（频道内用户 id，不是 openid）。

## 四、接收事件取值：字段全表

### 4.1 消息事件通用结构（`GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` / `C2C_MESSAGE_CREATE`）

```json
{
  "id": "ROBOT1.0_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "author": {
    "id": "A1B2C3D4E5F6A1B2C3D4E5F6A1B2C3D4",
    "member_openid": "A1B2C3D4E5F6A1B2C3D4E5F6A1B2C3D4",
    "member_role": "member",
    "username": "小明",
    "bot": false
  },
  "content": " /今日天气 ",
  "group_openid": "B2C3D4E5F6A1B2C3D4E5F6A1B2C3D4E5",
  "message_type": 0,
  "timestamp": "2026-07-21T10:00:00+08:00",
  "message_scene": {
    "source": "default",
    "ext": [
      "msg_idx=REFIDX_xxxxxxxxxxxxxxx==",
      "auth_token=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
    ]
  },
  "attachments": [],
  "t": "GROUP_AT_MESSAGE_CREATE",
  "qq_official": true
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | **消息 ID**。被动回复用它当 `msg_id`；撤回也用它。 |
| `content` | string | **消息文本**。群聊事件里 @机器人的前缀**已被平台去掉**。 |
| `group_openid` | string | 群 id（**只有群聊事件有**；单聊没有这个字段） |
| `author` | User | 发送者，见 §4.2 |
| `message_type` | integer | 消息内容类型，见 §4.3 |
| `message_scene` | MessageScene | 消息场景（引用索引、去重索引、鉴权令牌），见 §4.4 |
| `attachments` | MessageAttachment[] | 附件（图片/视频/语音/文件），见 §4.5 |
| `mentions` | User[] | 消息里 @ 的其它人（**不含 @机器人 自己**，群聊事件有） |
| `ark_data` | ARKData | 结构化卡片数据（`message_type=3` 时有值） |
| `msg_elements` | MsgElement[] | 消息元素列表（`message_type=103` 引用消息时含被引用内容） |
| `timestamp` | string | RFC3339 时间 |
| `t` | string | 事件类型（宿主补的） |

> **`content` 不一定是唯一内容来源**：只用 `content` 会漏掉卡片、引用、附件里的信息。
> 想完整处理，按 `message_type` 分流（§4.3），再合并 `attachments` / `ark_data` / `msg_elements`。

### 4.2 User（`event.author` / `event.mentions[]`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 用户唯一标识（OpenID 格式）；频道场景是频道内用户 id |
| `username` | string | 昵称（**可能为空字符串**，别假设一定有） |
| `bot` | boolean | 是否为机器人 |
| `union_openid` | string | 跨应用统一 OpenID（可能为空） |
| `union_user_account` | string | 跨应用统一账号（可能为空） |
| `user_openid` | string | 用户 OpenID，**单聊场景（`C2C_MESSAGE_CREATE`）用这个** |
| `member_openid` | string | 群成员 OpenID，**群聊场景（`GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE`）用这个** |
| `member_role` | string | 群内角色：`member`=普通成员 / `admin`=管理员 / `owner`=群主 |

**取发送者 openid 的标准写法**（群、单聊都能用）：

```js
function getUserOpenid(event) {
  const a = (event && event.author) || {};
  return String(a.user_openid || a.member_openid || a.union_openid || '');
}
```

> ⚠️ **openid 与 AppID 绑定**：A 机器人的 `user_openid` 拿给 B 机器人用会报错。
> 多账号时必须各存各的，不要互相串。也**拿不到真实 QQ 号**。
>
> ⚠️ 判断「是不是群主/管理员」用 `author.member_role`，**不是** `member_role === 'group_owner'` 之类的猜测值。

### 4.3 `message_type`（**收到**消息的类型）

| `message_type` | 含义 | 内容在哪个字段 |
| --- | --- | --- |
| `0` | 普通文本 | `content` |
| `3` | 结构化卡片（小程序/图文/位置/名片/视频分享等） | `ark_data`（`content` 里一般是 `[卡片消息] xxx` 摘要） |
| `101` | 并行消息 | 多条消息合并 |
| `102` | 聊天记录 | 转发的聊天记录 |
| `103` | 引用消息 | `msg_elements[]`（含被引用内容）；`message_scene.ext` 里有 `ref_msg_idx` |

**注意**：图片 / 视频 / 语音 / 文件**不在 `message_type` 里**，它们走 `attachments[]`，
用 `content_type` 区分（见 §4.5）。所以一条消息可能同时是 `message_type=0` + 带 1 张图。

### 4.4 MessageScene（`event.message_scene`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source` | string | 场景来源，`default`=默认聊天窗口 |
| `ext` | string[] | 扩展数据，元素是 `key=value` 字符串，常见键： |

`ext` 里的键：

| key | 含义 | 用途 |
| --- | --- | --- |
| `msg_idx` | **本条消息**的索引（`REFIDX_xxx==`） | **去重**：相同 `msg_id` 可能重复推送，用 `msg_idx` 去重最可靠 |
| `ref_msg_idx` | **本条消息所引用**的那条消息的索引 | 用户「引用回复」时会带；配合引用发送用 |
| `auth_token` | 鉴权令牌 | 平台内部用，一般忽略 |

解析示例：

```js
function readExt(event, key) {
  const ext = (event && event.message_scene && event.message_scene.ext) || [];
  for (const item of ext) {
    const s = String(item);
    const i = s.indexOf('=');
    if (i > 0 && s.slice(0, i) === key) return s.slice(i + 1);
  }
  return '';
}

const dedupKey = readExt(event, 'msg_idx');   // 去重用
const refIdx   = readExt(event, 'ref_msg_idx'); // 用户引用的那条消息索引
```

> **必须去重**：官方为保证可达性，同一条消息可能重复推送。
> 简单的做法是用 `msg_idx`（或 `id`）在内存 / 文件里做短期去重表。

### 4.5 MessageAttachment（`event.attachments[]`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `url` | string | 附件下载 URL（**有时效**，尽快下载） |
| `filename` | string | 文件名 |
| `width` / `height` | integer | 图片宽高（**非图片没有这两个字段**） |
| `size` | integer | 字节数 |
| `content_type` | string | 见下表 |
| `voice_wav_url` | string | **语音**附带的 WAV 地址（省得自己转 silk） |
| `asr_refer_text` | string | **语音**自带的 ASR 文本（平台识别结果） |

`content_type` 取值：

| 值 | 含义 |
| --- | --- |
| `voice` | 语音消息 |
| `image/jpeg` | JPEG 图片 |
| `image/png` | PNG 图片 |
| `image/gif` | GIF 图片 |
| `video/mp4` | MP4 视频 |
| `file` | 文件 |

**判断附件类型的标准写法**：

```js
function pickAttachments(event) {
  const list = Array.isArray(event.attachments) ? event.attachments : [];
  const out = { images: [], videos: [], voices: [], files: [] };
  for (const a of list) {
    const ct = String(a.content_type || '');
    if (ct.startsWith('image/')) out.images.push(a);
    else if (ct.startsWith('video/')) out.videos.push(a);
    else if (ct === 'voice') out.voices.push(a);
    else out.files.push(a);
  }
  return out;
}
```

> ⚠️ 不要用 `a.content_type === 'image'` 判断图片——图片实际是 `image/jpeg` / `image/png` / `image/gif`。
> 模拟器造的假事件里可能写成简写 `image`，所以稳妥写法是 `ct.startsWith('image')` 或 `ct.startsWith('image/')`。

### 4.6 生命周期 / notice 事件字段

| 事件 | 字段 |
| --- | --- |
| `GROUP_ADD_ROBOT` | `timestamp`（**Unix 秒**）、`group_openid`、`op_member_openid`（操作人） |
| `GROUP_DEL_ROBOT` | `timestamp`、`group_openid`、`op_member_openid` |
| `GROUP_MEMBER_ADD` | `timestamp`、`group_openid`、`member_openid`、`op_member_openid` |
| `GROUP_MEMBER_REMOVE` | 同上 |
| `GROUP_MSG_REJECT` / `GROUP_MSG_RECEIVE` | `timestamp`、`group_openid`、`op_member_openid` |
| `FRIEND_ADD` / `FRIEND_DEL` | `timestamp`、`openid` |
| `C2C_MSG_REJECT` / `C2C_MSG_RECEIVE` | `timestamp`、`openid` |

示例（`GROUP_ADD_ROBOT`）：

```json
{
  "group_openid": "A1B2C3D4E5F6A1B2C3D4E5F6A1B2C3D4",
  "op_member_openid": "A1B2C3D4E5F6A1B2C3D4E5F6A1B2C3D4",
  "timestamp": 1784570534,
  "t": "GROUP_ADD_ROBOT"
}
```

> `GROUP_ADD_ROBOT` / `GROUP_MSG_RECEIVE` / `FRIEND_ADD` / `C2C_MSG_RECEIVE` 这几个事件
> 可以用**事件最外层的 `id`** 作为 `event_id` 做被动回复（见 §6.4）。

### 4.7 ARKData（`message_type=3` 的结构化卡片）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `prompt` | string | 用户操作提示文本 |
| `ark_type` | string | 卡片类型：`tuwen`(图文H5) / `feed`(图文卡片) / `miniapp`(小程序) / `map`(位置) / `contact_card`(名片) / `video_share`(视频分享) / `music_together`(一起听歌) / `picture`(图片) |

| `fields` | object | 卡片字段，常见键：`tag`/`tags`(来源标签)、`title`(标题)、`desc`(描述)、`jump_url`(跳转链接)、`preview`(预览图)、`source`(来源)、`source_logo`、`tag_icon`、`nickname`、`avatar`、`address` |

const ark = event.ark_data;
if (ark) {

## 五、判断与分发：常见「怎么判断」速查

| 你想知道 | 判断写法 |
| --- | --- |
| 是不是群聊消息 | `event.t === 'GROUP_AT_MESSAGE_CREATE' \|\| event.t === 'GROUP_MESSAGE_CREATE'`（或 `!!event.group_openid`） |
| 是不是单聊消息 | `event.t === 'C2C_MESSAGE_CREATE'` |
| 是不是频道消息 | `event.t === 'AT_MESSAGE_CREATE' \|\| event.t === 'MESSAGE_CREATE'` |
| 是不是机器人发的 | `event.author && event.author.bot === true` |
| 发送者 openid | `event.author.user_openid \|\| event.author.member_openid` |
| 群 id | `event.group_openid` |
| 是不是群里 @ 了机器人 | 群聊事件本身就是「@了才推送」，无需再判断；`content` 已经去掉 @ 前缀 |
| 有没有图片 / 语音 / 文件 | 遍历 `event.attachments`，看 `content_type`（§4.5） |
| 是不是卡片消息 | `event.message_type === 3`（看 `ark_data`） |
| 是不是引用消息 | `event.message_type === 103`（看 `msg_elements`） |
| 用户是不是群管理员 | `event.author.member_role === 'admin' \|\| 'owner'` |
| 是不是按钮被点了 | `event.t === 'INTERACTION_CREATE' && event.type === 11` |
| 按钮点的哪个、带的什么数据 | `event.data.resolved.button_id` / `event.data.resolved.button_data` |
| 这条消息的 id（回消息用） | `event.id` |
| 事件最外层 id（做 event_id 用） | `event.id`（注意：消息事件与生命周期事件的 `id` 位置一致，都在顶层） |

**一条消息「文字 + 图片」都要处理**的完整写法：

```js
// 剥掉 @ 前缀：官方文档说 content 里 @ 前缀已去掉，但实测「接收所有消息」模式下
// 群消息的 content 可能是 `<@机器人openid> 签到` 这种带尖括号的形式，必须自己剥。
// 不剥的后果就是指令死活匹配不上（插件「看起来加载了但没反应」的常见原因）。
function stripMention(s) {
  return String(s || '')
    .replace(/^(?:<@!?[^>]*>\s*)+/, '') // <@openid> / <@!openid>
    .replace(/^(?:@\S+\s*)+/, '')        // @openid / @昵称
    .trim();
}

function normalize(event) {
  const text = stripMention(event.content);
  const segs = [];
  if (text) segs.push({ kind: 'text', text });
  for (const a of (Array.isArray(event.attachments) ? event.attachments : [])) {
    const ct = String(a.content_type || '');
    if (ct.startsWith('image')) segs.push({ kind: 'image', url: a.url });
    else if (ct === 'voice') segs.push({ kind: 'voice', text: a.asr_refer_text || '', wav: a.voice_wav_url || a.url });
    else if (ct.startsWith('video')) segs.push({ kind: 'video', url: a.url });
    else segs.push({ kind: 'file', name: a.filename || '', url: a.url });
  }
  const quoted = (event.message_type === 103)
    ? (event.msg_elements || []).map((e) => String(e.content || '')).join('\n')
    : '';
  return { text, segs, quoted };
}
```

## 六、发送消息：`ctx.actions.call` 全形态

### 6.1 基本形态

```js
await ctx.actions.call(接口路径, 请求体);
```

- 第一个参数是 **REST 接口路径**（以 `/` 开头），**不是** `send_group_msg` 这种接口名。
- 第二个参数是**请求体本身**（JSON），不是 `{ group_id, message }` 的包装。
- 默认 HTTP 方法是 **POST**；要在参数里显式改方法，加 `__method`。
- 路径会自动拼到官方 API 域：沙箱 `https://sandbox.api.sgroup.qq.com`、正式 `https://api.sgroup.qq.com`。

```js
// 群聊：发一条文本
await ctx.actions.call(`/v2/groups/${event.group_openid}/messages`, {
  content: '你好呀',
  msg_type: 0,
  msg_id: event.id,   // 被动回复必须带
  msg_seq: 1,
});

// 单聊
await ctx.actions.call(`/v2/users/${event.author.user_openid}/messages`, {
  content: '你好呀', msg_type: 0, msg_id: event.id, msg_seq: 1,
});

// 频道子频道
await ctx.actions.call(`/channels/${event.channel_id}/messages`, {
  content: '你好呀', msg_id: event.id,
});
```

### 6.2 改 HTTP 方法：`__method`

```js
// GET（只读接口）：params 会被丢弃，不带请求体
await ctx.actions.call('/users/@me', { __method: 'GET' });

// PUT：互动事件回 ACK
await ctx.actions.call(`/interactions/${event.id}`, { __method: 'PUT', code: 0 });

// DELETE：撤回消息
await ctx.actions.call(`/v2/groups/${group}/messages/${msgId}`, { __method: 'DELETE' });
```

规则：`method = params.__method || 'POST'`；`__method` 本身不会进入请求体。
`GET` 或**参数为空**时不带请求体。

### 6.3 返回值

成功时返回官方响应 JSON（对象），例如发送消息返回：

```json
{
  "id": "ROBOT1.0_xxxx",
  "timestamp": "2026-07-21T10:30:00+08:00",
  "ext_info": { "ref_idx": "REFIDX_xxxxxxxxxxxxxxxxxxxx==" }
}
```

`ext_info.ref_idx` 是**这条机器人消息自己的引用索引**，以后要引用它，就用这个值当 `message_reference.message_id`。

失败时**抛异常**，`err.message` 形如
`HTTP 400 [沙箱] https://sandbox.api.sgroup.qq.com/v2/groups/xxx/messages 回复消息msg_id已过期 ...`。
所以发送一定要 `try / catch`，并把 `err.message` 打到日志里，不然只能看到“没反应”。

### 6.4 两个「被动回复凭证」：`msg_id` 与 `event_id`

| 参数 | 取值 | 适用 |
| --- | --- | --- |
| `msg_id` | **消息事件**的 `event.id`（`C2C_MESSAGE_CREATE` / `GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` …） | 最常见 |
| `event_id` | **事件最外层**的 `id` | 仅这几个事件支持：<br>群：`INTERACTION_CREATE`、`GROUP_ADD_ROBOT`、`GROUP_MSG_RECEIVE`<br>单聊：`INTERACTION_CREATE`、`C2C_MSG_RECEIVE`、`FRIEND_ADD` |

二者**互斥**，带一个就行。带上才算「被动消息」，才有免频控的回复窗口（时效见 §八）。

## 七、发送消息各类型详解

### 7.1 发送侧 `msg_type` 取值表

| `msg_type` | 类型 | 内容字段 | 单聊 | 群聊 | 频道 |
| --- | --- | --- | --- | --- | --- |
| `0` | 文本 | `content` | ✅ | ✅ | ✅ |
| `2` | Markdown | `markdown` | ✅ | ✅ | ✅ |
| `6` | **输入中状态** | `input_notify` | ✅（**仅单聊**） | ❌ | ❌ |
| `7` | 富媒体 | `media` | ✅ | ✅ | ✅ |
| （频道另有 `ark` / `embed` / `image`） | | | ❌ | ❌ | ✅ |

> **收到**（`message_type`）与**发送**（`msg_type`）是两套编号，别混：发送只有 `0/2/6/7`（+频道专属）。

### 7.2 单聊发送接口

```text
POST /v2/users/{user_openid}/messages      # 频限 100 QPS
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `msg_type` | integer | 否 | `0`=文本 / `2`=Markdown / `6`=输入中 / `7`=富媒体 |
| `content` | string | 否 | 文本内容，`msg_type=0` 时填（**传了 `markdown` 就必须为空**） |
| `markdown` | object | 否 | `msg_type=2` 必填；对象见 §7.4 |
| `keyboard` | object | 否 | 内嵌键盘（短形式 `{id}` / 长形式 `{content:{rows:[…]}}`），见 §7.5；**仅 Markdown 消息支持** |
| `msg_id` | string | 否 | 被动回复的触发消息 id（5 分钟内有效） |
| `event_id` | string | 否 | 被动回复的事件 id（与 `msg_id` 二选一） |
| `msg_seq` | integer | 否 | 回复序号，默认 `1`；**相同 `msg_id`+`msg_seq` 重复发送会失败** |
| `media` | object | 否 | `msg_type=7` 时填 `{ file_info }`，`file_info` 来自上传接口 |
| `message_reference` | object | 否 | 引用回复，见 §7.6 |
| `is_wakeup` | boolean | 否 | **互动召回消息**（与 `msg_id`/`event_id` 互斥），见 §8.4 |
| `input_notify` | object | 否 | `msg_type=6` 时填 `{ input_type:1, input_second:60 }` |

单聊独有：`is_wakeup`、`input_notify`（`msg_type=6`）。

### 7.3 群聊发送接口

```text
POST /v2/groups/{group_openid}/messages     # 频限 100 QPS
```

请求体：**与单聊完全一致**，但没有 `is_wakeup` / `input_notify` / `msg_type=6`（**群消息不支持流式与输入中状态**）。
`media.file_info` 必须来自**群聊上传接口**（`/v2/groups/{group_openid}/files`），不能拿单聊的来用。

**最小发送封装（群 / 单聊通吃）**：

```js
async function sendReply(ctx, event, text) {
  const body = { content: text, msg_type: 0, msg_id: event.id, msg_seq: 1 };
  if (event.group_openid) {
    return ctx.actions.call(`/v2/groups/${event.group_openid}/messages`, body);
  }
  const openid = event.author && (event.author.user_openid || event.author.member_openid);
  if (openid) {
    return ctx.actions.call(`/v2/users/${openid}/messages`, body);
  }
  throw new Error('既不是群聊也不是单聊事件，无法回复');
}
```

### 7.4 Markdown 消息（`msg_type=2`）

**开放范围**：单聊、群聊**已对所有机器人开放**（无需申请模板）；频道需内邀。

```js
await ctx.actions.call(`/v2/groups/${event.group_openid}/messages`, {
  msg_type: 2,
  markdown: {
    content: '## 每日签到\n\n今日签到成功！获得 **50** 积分\n连续签到 **7** 天',
  },
  msg_id: event.id,
  msg_seq: 1,
});
```

**支持的语法**：

| 语法 | 写法 |
| --- | --- |
| 标题 | `# 一级` / `## 二级` |
| 加粗 | `**文字**` 或 `__文字__` |
| 斜体 | `_文字_` 或 `*文字*` |
| 加粗斜体 | `***文字***` |
| 删除线 | `~~文字~~` |
| 链接 | `[文字](https://…)` 或 `<https://…>` |
| 图片 | `![描述 #208px #320px](https://…)`（**必须公网可访问**，平台会下载转存） |
| 有序列表 | `1. xxx` |
| 无序列表 | `- xxx` |
| 列表嵌套 | 二级前空 4 空格；前一条若是普通文本，需用空行隔开 |
| 块引用 | `> xxx` |
| 水平线 | `***` |
| 换多行 | 需要连续空行时用 `\u200B`（零宽空格）撑一下 |

**限制**：
- `markdown.content` 与 `content` **互斥**，传了 markdown 时 `content` 必须为空。
- 模板方式（`template_id` / `custom_template_id` / `params`）在 v2 已标注**已废弃**，优先用 `content` 原生语法。
- `force_verify_image_resource: true` 时，图片转存失败会直接报错、消息不发。

**`markdown` 对象字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `content` | string | 原生 markdown 内容（**推荐**） |
| `template_id` | integer | 【已废弃】平台模板 ID |
| `custom_template_id` | string | 【已废弃】自定义模板 ID，与 `template_id` 二选一 |
| `params` | array | 【已废弃】模板变量 `{ key, values: [] }` |
| `force_verify_image_resource` | boolean | 是否校验图片转存结果，默认 `false` |

### 7.5 内嵌键盘（按钮）

`keyboard` 有两种写法，**二选一**：

```js
// 短形式：用平台预设模板
keyboard: { id: '1070001' }

// 长形式：自定义布局
keyboard: {
  content: {
    rows: [
      {
        buttons: [
          {
            id: 'btn_signin',                       // 同一键盘内唯一
            render_data: { label: '签到', visited_label: '已签到', style: 1 },
            action: {
              type: 2,                              // 0=跳转 1=回调 2=指令
              permission: { type: 2 },              // 0=指定用户 1=管理员 2=所有人
              data: '/签到',                        // type=1/2 时必填
              enter: true,                          // 指令按钮：点击后直接发送（仅单聊）
            },
          },
        ],
      },
    ],
  },
}
```

字段说明：

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| `Button` | `id` | 按钮 ID，同一键盘内唯一 |
| | `render_data.label` | 按钮文字，**最多 10 字符** |
| | `render_data.visited_label` | 点击后文字，不传则不变 |
| | `render_data.style` | `0`=灰色线框 / `1`=蓝色线框 / `3`=白底红字 / `4`=蓝底白字 |
| | `action.type` | `0`=跳转（http/小程序）/ `1`=回调（后台收到 `INTERACTION_CREATE`）/ `2`=指令（在输入框插入 @bot + data） |
| | `action.permission.type` | `0`=指定用户 / `1`=管理员 / `2`=所有人 |
| | `action.permission.specify_user_ids` | type=0 时的用户 id 列表 |
| | `action.data` | 回调/指令数据，type=1/2 必填 |
| | `action.enter` | 指令按钮，点击后直接自动发送（**仅单聊**） |
| | `action.reply` | 指令是否带引用回复本消息 |
| | `action.unsupport_tips` | 版本过低提示文案 |
| | `action.modal` | 二次确认：`{ content, confirm_text, cancel_text }`（content ≤40 字且不能含 URL） |
| | `group_id` | 分组 id；同组内点了一个，其它变灰（**仅 `action.type=1` 有效**） |

> ⚠️ **只有 Markdown 消息（`msg_type=2`）支持 `keyboard`**。纯文本消息带 keyboard 不会显示按钮。
> ⚠️ 用户点击 `type=1`（回调）按钮后，平台会推送 `INTERACTION_CREATE`，**必须在 3 秒内 ACK**（见 §十）。
> ⚠️ 行/列数超限会报 `40034029`。

### 7.6 引用回复（`message_reference`）

```js
await ctx.actions.call(`/v2/groups/${event.group_openid}/messages`, {
  msg_type: 7,
  media: { file_info: fileInfo },
  message_reference: { message_id: 'REFIDX_xxxxxxxxxxxxxxxxxxxx==' },
  msg_id: event.id,
  msg_seq: 2,
});
```

`message_reference.message_id` 的两种来源：

| 引用的对象 | 从哪里拿 |
| --- | --- |
| **用户（非机器人）发的消息** | 该消息事件的 `message_scene.ext` 里 `msg_idx=…` 的值 |
| **机器人自己发的消息** | 发送成功响应的 `ext_info.ref_idx` |

```js
// 引用「用户刚发的这条」
const refIdx = readExt(event, 'msg_idx');

// 或：引用「机器人刚刚发的那条」
const resp = await ctx.actions.call(`/v2/groups/${g}/messages`, { content: '第一条', msg_id: event.id, msg_seq: 1 });
const selfRef = resp && resp.ext_info && resp.ext_info.ref_idx;
```

### 7.7 富媒体（图片 / 视频 / 语音 / 文件）

两步：**先上传拿 `file_info`，再发送 `msg_type=7`**。

#### 上传

| 场景 | 接口 | 频限 |
| --- | --- | --- |
| 单聊 | `POST /v2/users/{user_openid}/files` | 50 QPS |
| 群聊 | `POST /v2/groups/{group_openid}/files` | 50 QPS |

> ⚠️ **两套接口不互通**：单聊上传的 `file_info` 只能发到单聊，群聊同理。

请求体：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file_type` | integer | `1`=图片(`png`/`jpg`) / `2`=视频(`mp4`) / `3`=语音(`silk`) / `4`=文件 |
| `url` | string | 媒体 URL（http 开头），平台下载转存；分片合并路径可为空 |
| `srv_send_msg` | boolean | `true`=上传即发送（**占用主动消息频次**，返回里带消息 id）；`false`=只返回 `file_info` |
| `file_name` | string | 文件名（可选） |
| `upload_id` | string | 分片上传任务 id，传了就走「分片合并」路径 |

大小限制：

| `file_type` | 格式 | 软限制 | 硬限制 |
| --- | --- | --- | --- |
| `1` 图片 | png / jpg | 20 MB | 200 MB |
| `2` 视频 | mp4 | 30 MB | 200 MB |
| `3` 语音 | silk | 20 MB | 200 MB |
| `4` 文件 | 任意 | 200 MB | 200 MB |

> **超过软限制**会自动降级成「文件」类型上传；**超过硬限制**直接报错。

响应：

| 字段 | 说明 |
| --- | --- |
| `file_uuid` | 文件唯一 id |
| `file_info` | **发给 `media.file_info` 用**（序列化二进制，原样透传，不要解析） |
| `ttl` | `file_info` 有效期（秒）；`0` 表示长期有效；**过期要重新上传** |
| `id` | 消息 id（仅 `srv_send_msg=true` 时返回） |
| `raw_url` | 下载链接（仅分片合并 + 图片/视频/语音时返回） |

**URL 直传发图（最简单）**：

```js
async function sendImage(ctx, event, imageUrl) {
  const isGroup = !!event.group_openid;
  const openid = isGroup ? event.group_openid : (event.author.user_openid || '');
  const uploadPath = isGroup
    ? `/v2/groups/${openid}/files`
    : `/v2/users/${openid}/files`;
  const sendPath = isGroup
    ? `/v2/groups/${openid}/messages`
    : `/v2/users/${openid}/messages`;

  const up = await ctx.actions.call(uploadPath, {
    file_type: 1,
    url: imageUrl,
    srv_send_msg: false,
  });
  await ctx.actions.call(sendPath, {
    msg_type: 7,
    media: { file_info: up.file_info },
    msg_id: event.id,
    msg_seq: 2,
  });
}
```

**大文件分片上传流程**：

1. 调 `upload_prepare` 拿 `upload_id`、`block_size`、各分片预签名 URL；
2. 按 `block_size` 把文件切片，逐片 `HTTP PUT` 到对应预签名 URL；
3. 每片 PUT 成功后调 `upload_part_finish` 通知服务端；
4. 全部分片完成后，带 `upload_id` 调上传接口完成合并，返回 `file_info`。

> 注意：分片的上传/合并请求走的是**平台给的预签名 URL**，不是 `ctx.actions.call` 的接口路径。
> 插件里要么用 `fetch` 直连，要么改用内置 `srv_send_msg` / URL 直传的简单路径。

### 7.8 输入中状态（`msg_type=6`，**仅单聊**）

```js
await ctx.actions.call(`/v2/users/${openid}/messages`, {
  msg_type: 6,
  input_notify: { input_type: 1, input_second: 60 },  // 1=正在输入，最长 60s
  msg_id: event.id,
  msg_seq: 1,
});
```

适合「AI 要算一会儿」时给用户一个「对方正在输入…」的反馈。**群聊不支持**。

## 八、被动消息与主动消息

### 8.1 区别

| | 被动消息 | 主动消息 |
| --- | --- | --- |
| 怎么发 | 带 `msg_id` 或 `event_id` | 不带任何触发凭证 |
| 时效 | 有窗口（见下表） | 无窗口，但受频控 |
| 频控 | 窗口内基本免频控 | 严格频控 |

### 8.2 被动回复时效与次数

| 场景 | 有效时间 | 每条触发消息最多回复 |
| --- | --- | --- |
| **单聊** | **60 分钟** | **4 次** |
| **群聊** | **5 分钟** | **5 次** |
| 频道 | 5 分钟 | — |

> 超时或超次数 → `40034005`（`msg_id` 已过期）/ `40034128`（时效或次数超限）。
> **所以不要在收到消息很久以后才回复**（例如排队几十分钟的任务）。

### 8.3 主动消息频控

| 场景 | Bot 维度（发送方） | 单关系维度（接收方） |
| --- | --- | --- |
| 单聊 | 企业认证/个人身份证认证 **10/qps**；未认证 **5/qps 且 30/qpm** | **20/qpm**，每好友 1 天最多接收 1000 条 |
| 群聊 | 企业认证/个人身份证认证 **60/qpm**；未认证 **30/qpm** | **20/qpm**，每群 1 天最多接收 1000 条 |

超频控 → `40034100`；无权限发主动消息 → `40034105`。

### 8.4 互动召回消息（`is_wakeup`）

用户在某个时间点主动跟机器人对话过，之后 **30 天内**可以给他发**互动召回消息**，
分 4 个周期（当天 / 1-3 天 / 3-7 天 / 7-30 天），**每个周期最多 1 条**：

```js
await ctx.actions.call(`/v2/users/${openid}/messages`, {
  content: '好久不见，要不要看看今天的推荐？',
  msg_type: 0,
  is_wakeup: true,     // 与 msg_id / event_id 互斥
});
```

超上限 → `40034122`；不支持 → `40034123`。

### 8.5 `msg_seq` 去重机制（**必读**）

同一个 `msg_id` 要回复多条时，`msg_seq` 必须**递增**：`1`、`2`、`3`…

- 相同 `msg_id` + `msg_seq` **重复发送会失败**（错误码 `40054005 消息被去重`）。
- 不填默认 `1`，所以**「连发两条都不带 msg_seq」第二条一定失败**。

```js
let seq = 1;
async function say(ctx, event, text) {
  const body = { content: text, msg_type: 0, msg_id: event.id, msg_seq: seq++ };
  // …按群/单聊发出去
}
```

## 九、撤回消息

官方**支持撤回**（这点常被误传为「不支持」）：

| 场景 | 接口 | 频限 |
| --- | --- | --- |
| 单聊 | `DELETE /v2/users/{user_openid}/messages/{message_id}` | — |
| 群聊 | `DELETE /v2/groups/{group_openid}/messages/{message_id}` | 10 QPS |

```js
// 撤回机器人自己刚发的一条（message_id 来自发送响应 id）
await ctx.actions.call(`/v2/groups/${event.group_openid}/messages/${sentId}`, {
  __method: 'DELETE',
});
```

规则：

- **发送超过 2 分钟的消息不可撤回**（`40064004`）。
- 机器人是**普通群成员**：只能撤回**自己**发的消息。
- 机器人是**群管理员**：可以撤回自己的消息 + **普通群成员**的消息
  （成员消息 id 从 `GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` 的 `event.id` 取）。
- 成功返回 HTTP 200，无响应体（`ctx.actions.call` 返回 `{}`）。

> 官方**不提供**：禁言、踢人、改群名片、改群名这类群管理接口——那是 OneBot/协议端才有的能力，别硬写。

## 十、互动事件与按钮回调

`INTERACTION_CREATE`（intent `INTERACTION` = 1<<26，宿主默认已订阅）。

### 10.1 `type` 取值表

| `type` | 含义 | 需要 ACK？ |
| --- | --- | --- |
| `11` | 消息按钮回调（内联键盘点击） | ✅ **必须** |
| `12` | 单聊快捷菜单回调 | ✅ **必须** |
| `13` | 消息反馈（点赞 / 点踩） | ❌ |
| `14` | 清空会话 | ❌ |
| `15` | 进出故事集 | ❌ |
| `16` | 切换模型 | ❌ |
| `18` | 用户授权 | ❌ |
| `19` | 群授权 | ❌ |
| `20` | 群授权状态变更 | ❌ |

> 只对 `type=11/12` 需要 ACK；**同一个 `interaction_id` 只能 ACK 一次**，超时失效。
> 不 ACK 时，客户端会一直 loading 到超时。

### 10.2 事件体

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 事件 id（**同时也是 ACK 路径里的 interaction_id**，也可用于被动回复的 `event_id`） |
| `type` | integer | 互动类型，见上表 |
| `scene` | string | `c2c`=单聊 / `group`=群聊 / `guild`=频道 |
| `chat_type` | integer | `0`=频道 / `1`=群聊 / `2`=单聊 |
| `user_openid` | string | 用户 openid（**仅单聊场景**） |
| `group_openid` | string | 群 openid（**仅群聊场景**） |
| `group_member_openid` | string | 群成员 openid（仅群聊场景） |
| `guild_id` / `channel_id` | string | 频道 / 子频道（仅频道场景） |
| `data` | object | `{ type, resolved }`，见 §10.3 |
| `version` | integer | 版本号，默认 1 |
| `application_id` | string | 机器人 AppID |
| `timestamp` | string | RFC3339 |

### 10.3 `data.resolved` 关键字段

| 字段 | 说明 |
| --- | --- |
| `button_id` | 被点按钮的 `id`（发送时你设的那个） |
| `button_data` | 被点按钮的 `action.data`（**回调按钮的 payload 在这里**） |
| `message_id` | 被操作的消息 id |
| `user_id` | 操作用户 id（仅频道） |
| `feature_id` | 功能 id（仅快捷菜单） |
| `feedback_opt` / `checked` | 点赞/点踩 与 是否选中（仅 `type=13`） |
| `action` | 操作类型（`type=15` 故事集：`ENTER_STORY`/`QUIT_STORY`） |
| `authorize_data` | `{ opt_scene, scope }`（仅 `type=18/19` 授权） |

### 10.4 处理 + ACK 的标准写法

```js
async function handleInteraction(ctx, event) {
  // 只处理按钮点击 / 快捷菜单
  if (event.type !== 11 && event.type !== 12) return;

  const resolved = (event.data && event.data.resolved) || {};
  const data = String(resolved.button_data || '');
  const buttonId = String(resolved.button_id || '');

  // 1) 先 ACK，避免客户端一直 loading（3 秒内）
  try {
    if (event.type === 11 || event.type === 12) {
      await ctx.actions.call(`/interactions/${event.id}`, { __method: 'PUT', code: 0 });
    }
  } catch (e) {
    ctx.logger?.warn?.('[interaction] ACK 失败：' + (e && e.message));
  }

  // 2) 再按 data 做业务；回复时用 event.id 当 event_id（被动回复）
  const isGroup = !!event.group_openid;
  const target = isGroup ? event.group_openid : event.user_openid;
  const path = isGroup
    ? `/v2/groups/${target}/messages`
    : `/v2/users/${target}/messages`;

  await ctx.actions.call(path, {
    content: '你点了按钮：' + (data || buttonId),
    msg_type: 0,
    event_id: event.id,   // 注意：这里用 event_id，不是 msg_id
    msg_seq: 1,
  });
}
```

## 十一、常见错误码速查

### 11.1 发送 / 被动回复

| 错误码 | 含义 | 怎么办 |
| --- | --- | --- |
| `40034005` | 回复消息 `msg_id` 已过期 | 收到消息后尽快回（群 5 分钟 / 单聊 60 分钟） |
| `40034024` | `msg_id` 无效或越权 | 检查是否拿了别的账号/会话的 id |
| `40034025` | `event_id` 无效 | 检查事件类型是否在支持列表 |
| `40034026` | `event_id` 已过期 | 尽快回 |
| `40034027` | 该事件不支持回复 | 换 `msg_id` 或不带凭证（转主动消息） |
| `40034128` | 被动回复时间或次数超限 | 群 5 次 / 单聊 4 次 |
| `40054005` | 消息被去重 | **换 `msg_seq`** |
| `40034100` | 主动消息超频控 | 降频或等配额恢复 |
| `40034105` | 主动消息无权限 | 让用户开启「主动消息」推送 |
| `40034006` | 消息内容违规 | 改内容 |
| `40054013` | 用户拒收消息 | 无解 |
| `40054016` | 机器人已下线 | 检查机器人状态 |
| `40054007` / `40054018` | 消息过长 | 缩短内容 |
| `40034101` / `40054003` | 机器人不是群成员 | 先把机器人拉进群 |
| `40054002` | 机器人被禁言 | 等解禁 |

### 11.2 Markdown / 键盘

| 错误码 | 含义 |
| --- | --- |
| `22006` | `msg_type` 与内容不匹配（比如 `msg_type=2` 却没给 `markdown`） |
| `40034011` / `40034124` | 无效的 Markdown 内容 / 参数错误 |
| `40034008` | Markdown 参数有空值 |
| `40034127` / `304036` | 无 Markdown 模板权限（已废弃的模板方式才会遇到） |
| `40034029` | 内联键盘行/列超限 |
| `305007` | 键盘样式参数错误 |
| `40034106` / `40034108` / `40034109` | 指令类型不支持 / 参数超长 / 参数解析失败 |

### 11.3 富媒体上传

| 错误码 | 含义 |
| --- | --- |
| `850019` | 不支持的文件格式（检查 `file_type`） |
| `850031` | 超过大小限制 |
| `850026` | 下载原始文件失败（URL 不可访问） |
| `40034004` | 富媒体信息转存失败（重试） |
| `40093001` | 文件上传失败（大文件分片异常，重试） |
| `40093002` | 超过当天发送文件容量上限 |
| `304080` | `file_info` 无效 |
| `850018` | 群/机器人被禁言 |

### 11.4 撤回

| 错误码 | 含义 |
| --- | --- |
| `40064004` | 已超出撤回时限（>2 分钟） |
| `40062003` | 无操作权限（机器人不是管理员、且撤回的是别人的消息） |

### 11.5 连接 / 鉴权

| 现象 | 含义 |
| --- | --- |
| Gateway 连接被 `4014` 关闭 | 传了**无权限的 intents**；宿主会按降级阶梯重连 |
| 正式环境鉴权失败 | 检查开放平台 **IP 白名单**（只限制正式，沙箱不受影响） |
| 网关返回 `shards > 1` | 宿主只订阅 `shard 0`，会**静默丢**部分事件；多分片需多实例部署 |

## 十三、最小可运行示例

整夹放进 `plugins/GF-plugin-echo/`。

`package.json`

```json
{ "name": "GF-plugin-echo", "plugin": "官方回声", "version": "1.0.0", "main": "index.js", "type": "commonjs" }
```

`plugin.json`

```json
{ "name": "GF-plugin-echo", "displayName": "官方回声", "entry": "index.js", "version": "1.0.0", "description": "QQ 官方机器人：收到什么就回什么" }
```

`index.js`

```js
async function plugin_init(ctx) {
  ctx.logger?.info?.('[GF-plugin-echo] 已加载，数据目录：' + (ctx.dataPath || __dirname));
}

/** 取发送者 openid（群 / 单聊通用） */
function getUserOpenid(event) {
  const a = (event && event.author) || {};
  return String(a.user_openid || a.member_openid || a.union_openid || '');
}

/** 发一条文本：群 → /v2/groups/…；单聊 → /v2/users/… */
async function sendReply(ctx, event, text, seq) {
  const body = { content: text, msg_type: 0, msg_id: event.id, msg_seq: seq || 1 };
  if (event.group_openid) {
    return ctx.actions.call(`/v2/groups/${event.group_openid}/messages`, body);
  }
  const openid = getUserOpenid(event);
  if (openid) return ctx.actions.call(`/v2/users/${openid}/messages`, body);
}

async function plugin_onmessage(ctx, event) {
  if (!event) return;
  // ⚠️ onmessage 会收到所有事件，必须按 t 过滤。
  // ⚠️ 群消息有两个事件名，都要接（见 §3.1）：@机器人 → GROUP_AT_MESSAGE_CREATE；
  //    开了「接收所有消息」后 → GROUP_MESSAGE_CREATE。
  const isGroup = event.t === 'GROUP_AT_MESSAGE_CREATE' || event.t === 'GROUP_MESSAGE_CREATE';
  const isC2C = event.t === 'C2C_MESSAGE_CREATE';
  if (!isGroup && !isC2C) return;

  // 剥掉 @ 前缀（群消息的 content 可能是 `<@机器人openid> 帮助`，见 §4.2）
  const text = String(event.content || '')
    .replace(/^(?:<@!?[^>]*>\s*)+/, '')
    .replace(/^(?:@\S+\s*)+/, '')
    .trim();
  if (!text) return;

  try {
    await sendReply(ctx, event, '你说了：' + text);
  } catch (e) {
    ctx.logger?.error?.('[GF-plugin-echo] 回复失败：' + (e && e.message));
  }
}

// 想处理进群、按钮回调等，用 plugin_onevent（同样会收到所有事件）
async function plugin_onevent(ctx, event) {
  if (event.t === 'GROUP_ADD_ROBOT') {
    ctx.logger?.info?.('[GF-plugin-echo] 被拉进群：' + event.group_openid);
  }
}

module.exports = { plugin_init, plugin_onmessage, plugin_onevent };
```

## 十四、排错速查

| 现象 | 原因 / 怎么办 |
| --- | --- |
| **插件在模拟器里好使，接真机器人就毫无反应** | 机器人开了「接收所有消息」→ 群消息事件名是 `GROUP_MESSAGE_CREATE`，而内置模拟器发的是 `GROUP_AT_MESSAGE_CREATE`。**过滤条件必须两个都接**（见 §3.1） |
| 日志里明明有群消息事件，插件却一行没执行 | 同上：过滤只判了 `GROUP_AT_MESSAGE_CREATE`。**排查第一件事就是去日志里看 `event.t` 究竟是什么** |
| 指令死活匹配不上（插件有反应但走「未匹配」分支） | 群消息 `content` 可能带 `<@机器人openid> ` 前缀（实测并不总被平台剥掉）。比较指令前先剥掉 `@` 前缀 |
| 插件列表里根本没有它 | 文件夹名没以 `GF-` 开头（大小写敏感），或没放在 `plugins/` 下 |
| 日志报「缺少 plugin_init」 | 入口没导出 `plugin_init`；CJS 用 `module.exports = { … }`，**不要** `exports = { … }` |
| 收到消息但 `event.message` 是 `undefined` | 你按 OneBot 写了。官方取文字用 `event.content` |
| 事件字段全是 `undefined` | 你把事件当成 `{ d: {...} }` 了。官方字段是**平铺**的，直接 `event.xxx` |
| 进群事件被当成消息处理了 | `plugin_onmessage` 没按 `event.t` 过滤（它对所有事件都会调用） |
| `content` 是空的，但对方明明发了东西 | 对方发的是**卡片/图片/引用**：看 `message_type`、`attachments`、`ark_data`、`msg_elements` |
| 图片判断不出来 | `content_type` 是 `image/jpeg` 这种，不是 `image`；用 `startsWith('image')` |
| 发送报错 / 消息发不出去 | 没带 `msg_id`（或 `event_id`）；或超过被动回复时效窗口 |
| 连发两条，第二条失败 | 没递增 `msg_seq`（相同 `msg_id`+`msg_seq` 会被去重） |
| 调 `send_group_msg` 报错 | 官方没有这个接口。用 `/v2/groups/{group_openid}/messages` |
| 拿 `event.user_id` 是 `undefined` | 官方是 `author.user_openid` / `author.member_openid` |
| 按钮点了没有任何反应 | ①连接没订阅 `INTERACTION`；②没在 3 秒内 `PUT /interactions/{id}` ACK |
| 按钮根本不显示 | `keyboard` 只在 **Markdown 消息（`msg_type=2`）** 下生效 |
| 发图片报 `304080` / `850019` | `file_info` 失效或类型不对；单聊/群聊上传接口不互通 |
| 想禁言 / 踢人 / 改群名片 | 官方不提供这些能力（撤回是支持的，见 §九） |
| 消息偶发重复处理 | 官方会重复推送；用 `message_scene.ext` 的 `msg_idx` 去重 |
