# Telegram Bot 插件（TG-plugin-）开发手册

> **先看这一句**：`TG-plugin-` 插件只挂在 **Telegram Bot** 连接（`type: 'telegram'`）上。它和 OneBot（`kakake-`）、QQ 官方（`GF-`）、KOOK（`ss-plugin-`）、微信（`WX-`）是**完全不同的事件结构与发送接口**——别把 OneBot 的 `message` 段数组、`send_group_msg` 抄过来。
>
> Telegram 侧的核心就三件事：
> ① 事件对象带 `telegram: true` 标记；
> ② 发消息用 `ctx.actions.call('sendMessage', { chat_id, text })`（Bot API 原生参数）；
> ③ `actions.call` 的第一个参数可以是**任意 Bot API 方法名**，框架原样透传。
>
> 完整接入（BotFather、长轮询 / Webhook / 本地服务器、限频、排错）见 [`使用教程/Telegram Bot 接入教程.md`](<../../Telegram Bot 接入教程.md>)。

## 一、命名与目录（硬规则）

| 项 | 值 |
| --- | --- |
| 目录前缀 | **`TG-plugin-`**（大小写敏感，`tg-plugin-hello` 不会被识别） |
| 插件 kind | `'tg'` |
| 归属协议 | Telegram Bot |
| 入口 | `plugin_init`（**必须**）、`plugin_onmessage`、`plugin_onevent`、`plugin_cleanup`（推荐） |
| 事件通道 | `telegram/event`；动作回执 `telegram/action_result` |
| 账号隔离键 | `telegramBotUserId`（`getMe` 拿到的机器人 ID） |

```
plugins/
└── TG-plugin-hello/            ← 整个文件夹放进 plugins/（整夹拷）
    ├── package.json            ← name / version / type:"module" / main
    ├── plugin.json             ← displayName / entry / description
    ├── index.mjs               ← 入口，导出钩子
    └── 插件文档.md              ← 控制台「查看说明」渲染它
plugins_two/
└── <telegramBotUserId>/
    └── TG-plugin-hello/        ← 按账号跑的运行副本（别往里写数据）
```

两个 JSON 与 `插件文档.md` 是**必交物**：缺了插件虽能跑，但控制台只显示文件夹名，没有中文名、简介、版本号，也没有「查看说明」按钮。

## 二、归属协议与框架标识

| 标识 | Telegram 连接下的值 |
| --- | --- |
| `frameworkEnv.protocol` | `'telegram'` |
| `frameworkEnv.ob11Mode` | `'telegram-bot-api'` |
| `event.telegram` | `true` |
| 连接显示名 | `Telegram Bot` |
| 连接 `mode` | `polling`（长轮询） / `webhook`（HTTPS 回调） |

判协议优先用 `frameworkEnv.protocol`，事件上的 `event.telegram === true` 作互补标记，**挑一种读法，别两套分支打架**：

```js
export async function plugin_init(ctx) {
  ctx.logger.info(`协议=${ctx.frameworkEnv?.protocol} · 模式=${ctx.frameworkEnv?.ob11Mode}`);
}

export async function plugin_onmessage(ctx, event) {
  if (event.telegram !== true) return;
  // …
}
```

## 三、事件形状

框架把 Telegram **Update** 规范化成 **OneBot v11 风格**事件对象后分发，同时把整个原生 Update 原样保留在 `raw` 里：

- **`plugin_onevent`**：所有 Update 都进（消息、回调、内联查询、成员变动、反应、动作回执…）；
- **`plugin_onmessage`**：只收消息类事件（`post_type === 'message'`）；
- **动作回执**（`telegram/action_result`）**不进** `plugin_onmessage`，只在 `plugin_onevent` 里看得到；
- 事件对象带 `telegram: true` 标记，字段名与 OneBot 插件基本一致，便于平滑迁移。

规范化后常见字段（**以框架实际透传为准**）：

| 字段 | 说明 |
| --- | --- |
| `telegram` / `platform` / `protocol` | 恒为 `true` / `'telegram'` / `'telegram'` |
| `post_type` | `message`（消息）/ `notice`（回调、成员变动、反应等）/ `request`（内联查询、入群申请） |
| `update_type` / `t` | 原始 Update 类型：`message` / `callback_query` / `inline_query` … |
| `update_id` | 原始 Update ID（`offset` 确认靠它） |
| `message_type` | `private` / `group` / `channel`（由 `chat.type` 映射） |
| `chat_id` | 会话 ID，发消息要用；部分非消息事件可能没有 |
| `message_id` | 消息 ID（引用 / 撤回 / 编辑用） |
| `user_id` / `group_id` | 发送者 / 群 ID（私聊时 `group_id` 为 undefined） |
| `raw_message` | **纯文本字符串**（`text` 或 `caption` 归一化结果） |
| `message` | **OneBot 风格消息段数组** `[{ type, data }]`，不是原生 Message 对象 |
| `sender` / `chat` | 发送者（= 原生 `from`）/ 会话对象；`sender.is_bot` 用于防循环 |
| `command` / `command_args` / `command_target` | 命令解析结果（含剥掉 `/cmd@bot` 后缀） |
| `notice_type` / `callback_query_id` / `callback_data` | 回调事件的拍平字段 |
| `request_type` / `query_id` / `query` | 内联查询的拍平字段 |
| `raw` | **整个原生 Telegram Update**，含 `raw.message` / `raw.callback_query` / `raw.inline_query` |

> **实操第一步**：在 `plugin_onevent` 里 `ctx.logger.info(JSON.stringify(event))` 打一条真实事件，对照上表确认字段名与层级，再写业务逻辑。

**取字段用兼容写法**（既认框架拍平的字段，也能回退到 `raw` 原生结构）：

```js
const chatId = event.chat_id
  ?? event.raw?.message?.chat?.id
  ?? event.raw?.callback_query?.message?.chat?.id;
const text = String(
  event.raw_message ?? event.raw?.message?.text ?? event.raw?.message?.caption ?? '',
).trim();
const isBot = Boolean(event.sender?.is_bot ?? event.raw?.message?.from?.is_bot);
```

> 注意：**没有** `event.text`、`event.callback_query`、`event.inline_query` 这类顶层字段；文本读 `raw_message`，回调读 `callback_query_id` / `callback_data`（或 `raw.callback_query`），内联查询读 `query_id` / `query`（或 `raw.inline_query`）。

常见 Update 类型：`message`、`edited_message`、`channel_post`、`callback_query`、`inline_query`、`chosen_inline_result`、`my_chat_member`、`chat_member`、`message_reaction`、`poll`、`poll_answer`、`pre_checkout_query`、`shipping_query`、`chat_join_request` …（全表见接入教程 §8）。其中 `chat_member`、`message_reaction`、`chat_boost` 等**默认不下发**，要在连接里配 `telegramAllowedUpdates` 才会推。

## 四、发消息：actions.call

**标准写法**：

```js
await ctx.actions.call('sendMessage', { chat_id, text: '你好呀 👋' });
```

与 OneBot 对照（**别混用**）：

| | action | 参数 |
| --- | --- | --- |
| OneBot | `send_group_msg` | `{ group_id, message: [段数组] }` |
| Telegram | `sendMessage` | `{ chat_id, text }`（原生参数，下划线命名） |

要点：

- `chat_id` 可以是数字（私聊 / 群）或 `@channelusername`（频道）；
- **失败会 throw**，必须 `try/catch`（429 限频、400 参数错、401 token 失效、连接断开）；
- 任意 Bot API 方法都能直接传方法名：`sendPhoto`、`answerCallbackQuery`、`getFile`、`answerInlineQuery`、`sendMessageDraft`、`editMessageText`、`sendInvoice` …；
- 也支持 `api` 透传：`ctx.actions.call('api', { method: 'sendMessage', chat_id, text })`；
- 框架**不做白名单、不做协议翻译**：方法名与参数字段要与 [官方 Bot API 文档](https://core.telegram.org/bots/api) 一致，拼错会在 Telegram 侧报 400。

## 六、数据、配置与账号隔离

```
plugins_two/<telegramBotUserId>/<插件id>/
```

- 多个 Telegram 机器人各跑各的实例、各存各的数据，**天然不互通**；
- 数据只写 `ctx.dataPath`，**别写 `ctx.pluginPath`**（运行副本，重载会被覆盖）；
- 配置在 `ctx.configPath`（`<dataPath>/config.json`）；
- 要跨机器人打通状态，自己做一层外部存储，框架不代劳。

## 八、完整可运行示例

[`TG-plugin-hello/`](<./TG-plugin-hello/>) 是一份可直接装进 `plugins/` 的最小插件：

- `plugin_init` 打日志（协议 / 模式 / 数据目录）；
- `plugin_onmessage` 认协议、防循环、处理 `/start` `/help` `/ping` `/photo`、回声「你好」；
- `plugin_onevent` 处理 `callback_query`（先 ACK）与 `inline_query`；
- `plugin_cleanup` 收尾。

装好后在控制台打开**总开关** + 该 Telegram 连接的**连接开关**（两个都要开），私聊发 `/start` 验证。

## 九、高频坑与排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 插件完全不触发 | 目录名不是 `TG-plugin-` 前缀 / 两个开关没都开 / 没认 `telegram: true` | 核对前缀与开关；`plugin_onevent` 打一条 `JSON.stringify(event)` |
| 群里收不到普通消息 | **隐私模式默认开启** | @BotFather `/setprivacy` 关闭 → **移出群再重新拉入**；检查 `telegramAllowedUpdates` |
| 按钮点了转圈 | `callback_query` 没 ACK，或写在 `plugin_onmessage` 里（收不到） | 放 `plugin_onevent`，先 `answerCallbackQuery` |
| `can't parse entities` | 用户文本直接拼进 `MarkdownV2` | 用 `escapeMarkdownV2`，或连接里把 `telegramParseMode` 设为 `HTML` |
| 429 / Too Many Requests | 限频（单聊 ~1 条/秒、群 20 条/分钟、广播 ~30 条/秒） | 按响应 `retry_after` 秒数退避；批量发送排队限速 |
| 401 Unauthorized | token 错 / 被吊销 / 测试 token 打生产地址 | 到 BotFather `/token` 重签；核对 `telegramTestEnv` |
| 409 Conflict | webhook 与 polling 同时用 | `deleteWebhook` 后切 `mode`（见接入教程 §4.9） |
| 两个机器人互刷 | 开了 Bot-to-Bot 没防循环 | `if (from?.is_bot) return;` |
| `method not found` | 本地 Bot API Server 版本太旧 | 升级服务器，或临时把 `telegramApiBase` 留空走官方 |

## 十、10.x 新能力怎么调

当前 Bot API **10.4（2026-11-09）**：Rich Messages、Ephemeral Messages、Widgets、`sendMessageDraft` 流式草稿、Guest Mode / Managed Bots 等。

因为 `actions.call` 不做白名单，**新方法直接传方法名即可**，不用等框架升级：

```js
// 流式草稿（AI 边生成边推）
await ctx.actions.call('sendMessageDraft', { chat_id, text: '正在生成…' });
await ctx.actions.call('sendMessage', { chat_id, text: finalText });
```

富文本把连接的 `telegramParseMode` 设为 `'Rich'`；Guest Mode / Managed Bots 属于 **BotFather 账号级开关**，代码里硬开不了。新 Update 类型记得同步加进 `telegramAllowedUpdates`。参数细节以官方 Bot API 文档为准，详见接入教程 §15。
