# 扩展插件（kz-plugin-）

> **一句话**：扩展插件**不绑任何连接、不接消息、不收上报**，只提供一个本机页面 / 本机服务 / 定时任务。
> 它没有连接级子开关，插件列表上的**总开关**就是它唯一的开关；数据目录直接是 `data/<插件ID>`。

如果你要写的是「群里发指令 → 回消息」这种机器人插件，**这一页不适用**，请回 [前言.md](../前言.md) 走 OneBot / GF- / 双生那几条轨。
如果你要写的是「给框架挂一个管理面板 / 定时清理 / 对接外部接口的小工具」，那就是这一页。

---

## 一、它和另外五类有什么不同

| | 其它五类（kakake- / GF- / sssx-plugin- / WX- / ss-plugin-） | 扩展（kz-plugin-） |
| --- | --- | --- |
| 挂在哪 | 必须挂在某条连接上，按账号隔离运行副本 `plugins_two/<账号>/` | 不挂连接，直接跑 `plugins/<插件ID>` |
| 开关 | 总开关 + 每个连接一个子开关（两个都要开） | **只有总开关**，列表上一点就生效 |
| 事件 | `plugin_onevent` / `plugin_onmessage` | **永不调用**（写了也不会跑） |
| 数据目录 | `data/<账号>/<插件ID>/` | `data/<插件ID>/`（没有账号层） |
| 发消息 | `ctx.actions.call` / `ctx.kakake_api` | **不提供**，`actions.call` 会直接抛错 |
| 多实例 | 每个账号各一份实例 | 全局只有一份实例 |

> 为什么不让它发消息：扩展插件不属于任何连接，没有「用哪个机器人发」这件事。真需要发消息，请写成双生或单协议插件。

---

## 二、目录与清单

目录名必须以 `kz-plugin-` 开头（大小写敏感）：

```text
plugins/kz-plugin-hello/
  package.json      ← 名字、入口（main）、type: module
  plugin.json       ← 显示名、入口（entry）、简介
  index.mjs         ← 你的代码
  webui/admin.html  ← 可选：网页后台
  插件文档.md        ← 可选：控制台「查看说明」读它
```

两个 JSON 里最重要的字段和其它插件完全一样：

```json
// package.json
{
  "name": "kz-plugin-hello",
  "version": "0.1.0",
  "type": "module",
  "main": "index.mjs",
  "plugin": "本地便签板",
  "description": "示例扩展插件：网页便签 + 配置项"
}
```

```json
// plugin.json
{
  "name": "kz-plugin-hello",
  "displayName": "本地便签板",
  "author": "教程",
  "version": "0.1.0",
  "entry": "index.mjs",
  "description": "示例扩展插件：网页便签 + 配置项"
}
```

> 入口查找顺序与其它插件一致：`plugin.json.entry` → `package.json.main` → `index.mjs` → `index.js` → `index.cjs` → `main.mjs` → `main.js` → `main.cjs`。
> CJS 写法（`require` + `module.exports`）照样能跑，兼容层是一样的。
> zip 导入 / 插件商店安装时，宿主按包名前缀自动识别成「扩展」，不需要额外声明。

## 三、`ctx` 里能用什么

| 成员 | 是否可用 | 说明 |
| --- | --- | --- |
| `ctx.logger` | ✅ | 写控制台「日志」页 |
| `ctx.dataPath` | ✅ | **`data/<插件ID>`**，插件专属，覆盖插件目录不会丢 |
| `ctx.configPath` | ✅ | `data/<插件ID>/config.json` |
| `ctx.pluginPath` / `ctx.pluginName` | ✅ | 插件目录 / 插件 ID |
| `ctx.router` | ✅ | 页面、静态资源、HTTP 接口（见第七节） |
| `ctx.NapCatConfig` | ✅ | 配置项构建器 |
| `ctx.getPluginExports(id)` | ✅ | 但只能拿到**同样是扩展**的插件导出（不跨协议管理器） |
| `ctx.pluginManager` | ✅ | 查插件信息、读写启停状态 |
| `ctx.frameworkEnv.ob11Mode` | ✅ | 固定 `'none'`（不绑连接） |
| `ctx.actions.call` | ❌ | 调用直接抛错，错误信息会说明「不绑定任何连接」 |
| `ctx.kakake_api` | ❌ | 不注入（`undefined`），用之前请先判断 |
| `ctx.connectionId` / `frameworkEnv.protocol` | ❌ | 没有连接，自然没有这两项 |

```js
export async function plugin_init(ctx) {
  ctx.logger.info('数据目录：', ctx.dataPath);
  // 需要发消息？这里会抛错，别写这种代码
  // await ctx.actions.call('send_group_msg', { group_id: 1, message: [] });
}
```

## 四、生命周期

```js
export async function plugin_init(ctx) { /* 加载时执行一次 */ }
export async function plugin_cleanup(ctx) { /* 卸载 / 重载 / 进程退出前执行 */ }
```

- `plugin_init` 在「总开关打开」或「框架启动且总开关为开」时执行一次。
- `plugin_cleanup` 在「总开关关闭」「重载插件」「框架退出」时执行。
- `plugin_onevent` / `plugin_onmessage` **不会被调用**，别把逻辑写在这里。
- **定时器、文件监听、WebSocket 连接一律在 `plugin_cleanup` 里清掉**，否则关了开关它还在后台跑。

```js
let timer = null;

export async function plugin_init(ctx) {
  timer = setInterval(() => ctx.logger.info('心跳'), 60_000);
}

export async function plugin_cleanup() {
  if (timer) clearInterval(timer);
  timer = null;
}
```

## 五、数据目录

- 路径：`data/<插件ID>/`，由框架在 `plugin_init` 前创建好。
- 配置：`data/<插件ID>/config.json`（`ctx.configPath`）。
- 你自己的文件随便放这里，例如 `data/kz-plugin-hello/notes.json`。
- **不要**往 `data/tmp/` 或别的账号目录写——那是其它插件/其它账号的地盘。
- 另外宿主会把 `config/plugins/<插件ID>` 做成指向该目录的联接，供老插件用相对路径 `../../config/plugins/<id>` 访问。

> 扩展插件没有账号层，所以**全局只有一份数据**。想按「用户/群」区分，自己在数据里加字段，而不是指望框架分目录。

## 六、配置项（控制台弹窗里的表单）

配置项机制与其它插件完全一致，**唯一的区别是多了一个入口**：插件列表卡片右下角的齿轮按钮（只有确实有配置项的插件才会出现），点开就是配置弹窗。

两种写法，选一种：

**写法 A：静态导出（最简单）**

```js
export const plugin_config_schema = [
  { key: 'title', type: 'string', label: '面板标题', default: '便签板', description: '只有文本框会把说明文字显示出来' },
  { key: 'maxNotes', type: 'number', label: '最多保留条数', default: 50 },
];
```

**写法 B：`plugin_init` 里用 `ctx.NapCatConfig` 构建（推荐，能拿到 `ctx`）**

```js
const plugin_config_ui = [];

export async function plugin_init(ctx) {
  const C = ctx.NapCatConfig;
  plugin_config_ui.length = 0;          // 保持导出引用不变，只换内容
  plugin_config_ui.push(...C.combine(
    C.text('title', '面板标题', '便签板'),
    C.number('maxNotes', '最多保留条数', 50),
    C.boolean('allowPublicRead', '允许免登录只读', false),
  ));
}

export { plugin_config_ui };
```

保存行为：

| 你导出了什么 | 点「保存」后发生什么 |
| --- | --- |
| 只有 schema | 写 `config.json`，然后**重载一次插件**（`plugin_cleanup` → `plugin_init`） |
| 同时导出 `plugin_get_config(ctx)` + `plugin_set_config(ctx, next)` | 交给你的函数处理，**不重载**，可做到即时生效 |

```js
import fs from 'node:fs';

let config = { title: '便签板', maxNotes: 50 };

// init 里先把已保存的配置读回来（config.json 可能还不存在）
export async function plugin_init(ctx) {
  try {
    const saved = JSON.parse(fs.readFileSync(ctx.configPath, 'utf-8'));
    config = { ...config, ...(saved && typeof saved === 'object' ? saved : {}) };
  } catch { /* 首次运行没有文件，用默认值 */ }
}

export function plugin_get_config() {
  return config;
}

export async function plugin_set_config(ctx, next) {
  config = { ...config, ...next };      // 合并式保存，别整体覆盖
  // 重要：实现了这个钩子，宿主就不再代写 config.json，必须自己落盘，否则重启就丢
  fs.writeFileSync(ctx.configPath, JSON.stringify(config, null, 2), 'utf-8');
}
```

> 实测坑（与其它插件相同）：只有 `string` / `multi-select` 控件会显示 `description`；`NapCatConfig.html()` / `.plainText()` 生成的 key 以 `_` 开头，会被控制台整条过滤。

## 七、网页后台与 HTTP 接口

注册页面（`plugin_init` 里）：

```js
ctx.router.page({
  path: 'admin',                 // 页面路径段
  title: '本地便签板',
  description: '添加 / 删除便签',
  htmlFile: 'webui/admin.html',  // 相对插件根目录
});
```

打开方式：

- 控制台 → 插件 → 卡片上的「打开控制台」按钮；
- 直接访问 `/plugin/<插件ID>/page/admin`。

接口分两类，**默认用第一类**：

| 注册方法 | 实际地址 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `ctx.router.get/post/put/delete('/notes', fn)` | `/api/Plugin/ext/<插件ID>/notes` | **需登录** | 后台页面读写数据 |
| `ctx.router.getNoAuth('/ping', fn)` | `/plugin/<插件ID>/api/ping` | **免登录、公网可达** | 只放健康检查这类无敏感信息的接口 |

```js
ctx.router.get('/notes', (req, res) => res.json({ code: 0, data: notes }));
ctx.router.post('/notes', (req, res) => {
  notes.push({ id: Date.now(), text: String(req.body?.text || ''), at: new Date().toISOString() });
  save(ctx);
  res.json({ code: 0 });
});
```

页面里怎么调：用宿主注入的全局变量拼绝对路径，别猜相对路径。

```html
<script>
  const ID = window.__KAKAKE_PLUGIN_ID__ || 'kz-plugin-hello';
  const API = `/api/Plugin/ext/${ID}`;   // 需登录；页面已带登录态
  fetch(`${API}/notes`).then((r) => r.json()).then((r) => { /* … */ });
</script>
```

静态资源：

```js
ctx.router.static('/static', 'webui');   // 插件根目录下的 webui/ 映射到 /plugin/<ID>/files/static/
ctx.router.staticOnMem('/live', [        // 内存文件，适合实时状态，不落盘
  { path: 'status.json', contentType: 'application/json', content: () => JSON.stringify({ ok: true }) },
]);
```

> `getNoAuth` 的路由是**真正公开**的：任何能访问到控制台端口的人都能打。不要在这里返回密钥、文件内容、内网信息。

## 八、启停、安装与卸载

- **启停**：插件列表卡片右下角的开关。开了 → `plugin_init`；关了 → `plugin_cleanup`。
- **连接面板里看不到它**：扩展插件不属于任何连接，连接里的「插件」列表不会列它，也没有子开关。
- **安装**：把文件夹丢进 `plugins/`，或在控制台「上传 zip」/ 插件商店安装；导入时按 `kz-plugin-` 前缀识别。
- **卸载**：插件列表垃圾桶 → 可选是否同时删除 `data/<插件ID>` 里的数据（删了不可恢复）。

状态文件是 `data/kz-plugins.json`（缺省即视为开启），与其它几类的 `plugins.json` / `gf-plugins.json` 等互不影响。

## 九、完整示例：本地便签板

示例在 [`kz-plugin-hello/`](./kz-plugin-hello/)：

```text
kz-plugin-hello/
  index.mjs          ← 配置项 + 三个接口 + 页面注册
  webui/admin.html   ← 一个不用构建的原生 HTML 页面
  package.json
  plugin.json
  插件文档.md         ← 控制台「查看说明」读它
```

装法：

1. 整个 `kz-plugin-hello` 文件夹拷进 `plugins/`；
2. 控制台 → 插件 → 找到「本地便签板」，打开总开关；
3. 卡片上点「打开控制台」→ 出现便签页面，可添加 / 删除；
4. 卡片右下角齿轮 → 改「面板标题」「最多保留条数」，保存后立刻生效（示例实现了 `plugin_set_config`，所以不重载）。

## 十、卡住了？照这里查

| 现象 | 原因 / 处理 |
| --- | --- |
| 插件列表里根本没有它 | 目录名没以 `kz-plugin-` 开头；或没放在 `plugins/` 下 |
| 显示 `error` 状态 | 入口没导出 `plugin_init`；或 `plugin_init` 里抛错。看「日志」页 |
| 卡片没有齿轮按钮 | 没导出任何配置项（`plugin_config_schema` / `plugin_config_ui` / `plugin_get_config`） |
| 有齿轮但弹窗是空的 | schema 在 `plugin_init` 里才填充，而插件当前没加载（总开关关着） |
| 打开后台 404 | `htmlFile` 路径写错（相对插件根目录，注意大小写） |
| 后台 403 | 总开关没开，或插件加载失败（未加载的插件不提供后台） |
| 页面里接口 401 | 调的是 `/api/Plugin/ext/...` 但页面不是从控制台打开的（没登录态） |
| 调 `actions.call` 报错 | 这是设计如此：扩展插件没有连接，发不了消息 |
| 关了开关定时器还在跑 | `plugin_cleanup` 里没清理定时器 |
| 改了代码没反应 | 控制台插件页点「重载」，或关开一次总开关 |

## 十一、什么时候别用它

- 要收发群消息、私聊消息 → 用 `kakake-` / `GF-` / `sssx-plugin-`。
- 要按机器人账号隔离数据、每个号一份配置 → 用账号型插件。
- 要做的事情依赖「当前是哪个群/哪个用户发来的」→ 扩展插件根本收不到事件。
