# 插件开发（基础）

> 读完这一页，再从三条轨里任选一条——**野鸡 TS 开发**（写 `src/index.ts` → 构建 → 装产物）、**野鸡 JS 开发（ESM 版）**（直接改 `.mjs` 就能跑）、**野鸡 JS 开发（CJS 版）**（同样的东西，换成 `require` / `module.exports` 写法，老插件移植选它），你就能写出一个能跑的插件。

**最终效果**：对方发 `你好`，机器人回 `你好呀`；在群里发 `禁言 123456789 60`，机器人调用协议接口把那人的禁言 60 秒。

> 第五节（事件字段）和第六节（接口速查）是随时回来查的表，第一次读可以先跳过。

---

## 一、先记住这 3 件事

1. **插件就是一个文件夹**，放进咔咔珂的 `plugins/` 目录。
2. **文件夹名必须以 `kakake-` 开头**，例如 `kakake-plugin-hello`。
3. **入口文件必须导出 `plugin_init`**，框架靠它认出这是插件；要收消息，再导出 `plugin_onmessage`。

一个能用的插件目录长这样：

```text
plugins/kakake-plugin-hello/
  package.json   ← 名字、入口（main）、type: module
  plugin.json    ← 显示名、入口（entry）、简介
  index.mjs      ← 你的代码
  插件文档.md     ← 可选：控制台插件列表的「查看说明」就读它
```

> **CJS 写法的插件**（`require` + `module.exports`）把入口换成 `index.js`、`package.json` 里写 `"type": "commonjs"` 就行，其余一模一样。宿主带了 CJS 兼容层：老插件不改代码也能直接装进去跑，连 `package.json` 都不放也行——详见「野鸡 JS 开发（CJS 版）」。

> **为什么第 3 条是硬要求**：宿主加载时会检查入口有没有导出 `plugin_init`，没有就直接判定为无效插件并报「缺少 plugin_init」。名字拼错、忘了写 `export` / `module.exports`，都会卡在这一步。

> **两个 JSON 是建议放，不是必须**：入口查找顺序是 `plugin.json` 的 `entry` → `package.json` 的 `main` → `index.mjs` → `index.js` → `index.cjs` → `main.mjs` → `main.js` → `main.cjs`。所以只丢一个 `index.mjs`（或 `index.js`）也能被加载、也能跑，只是控制台里会显示成文件夹名（`kakake-plugin-hello`）、没有中文名和简介。想让插件在列表里像个正经插件，两个 JSON 一起放。

> **适用范围**：这一整套规则说的是 **OneBot11 连接**下的插件（`kakake-` 开头）。宿主还认另外三类——`GF-`（QQ 开放平台）、`WX-`（微信）、`ss-plugin-`（KOOK 等），它们各有自己的上下文和示例，本教程不涉及。zip 导入时宿主会按包名自动识别类型。

## 二、一次消息的一生

1. 有人在群里发了一条消息；
2. 咔咔珂从协议端收到这条 **OneBot11 事件**；
3. 按连接找到「已开启」的插件，逐个调用 `plugin_onmessage(ctx, event)`；
4. 你的代码从 `event` 里取出文字、判断是哪条指令；
5. 用 `ctx.actions.call(接口名, 参数)` 让协议端把回复发出去。

> **顺序**：同一个事件，宿主会先调 `plugin_onevent`（**所有**事件都会进来，包括撤回、戳一戳这类非消息事件），再对消息事件调 `plugin_onmessage`。本教程只用得到后者。

> **注意**：插件是**挨个被调用**的，你的函数返回值**不会拦截**别的插件。所以如果装了两个都认「你好」的插件，群里会出现两条回复——这不是故障。

## 三、名词表

### 框架给你的东西

- **`plugin_init`** —— 插件初始化函数，加载时调用一次，适合打日志、读配置。
- **`plugin_onmessage`** —— 收到消息时调用。`on` = 当……时，`message` = 消息。
- **`plugin_cleanup`** —— 插件**关闭或重载**时调用，用来收尾：清定时器、断连接、把内存里的数据落盘。
- **`ctx`** —— 上下文（context），框架给你的「工具箱」。
- **`ctx.logger`** —— 打日志用的对象，`ctx.logger.info('…')` 会出现在控制台「日志」页。
- **`ctx.actions.call`** —— 调协议端接口的**唯一通式**。
- **`ctx.dataPath`** —— 这个插件专属的数据目录（按连接账号分开）。要存文件（缓存、名单、数据库）就存这里，不会因为你覆盖插件目录被清掉。
- **`ctx.configPath`** / **`ctx.pluginPath`** / **`ctx.pluginName`** —— 插件的配置目录 / 自身目录 / 自身名字。
- **`ctx.adapterName`** —— 当前连接的协议适配器名。`ctx.actions.call` 不传它也照样能用（框架走默认值）。
- **`ctx.router`** —— 进阶：给插件挂 HTTP 接口和网页后台。本教程不讲。
- **`ctx.pluginManager`** —— 进阶：查其它插件、读写插件状态。本教程不讲。

### 事件（event）里有什么

- **`event`** —— 这一次「有人发了消息」的整包数据。
- **`event.message`** —— 消息内容，**JSON 消息段数组**，形如 `[{ type: 'text', data: { text: '你好' } }]`。
- **`event.message_type`** —— `'group'` 群聊 / `'private'` 私聊。
- **`event.group_id`** —— 群号（群聊才有）。
- **`event.user_id`** —— 发消息那个人的 QQ 号。

> 这里只列了最常用的 4 个字段，**完整字段表见第五节**。

### 调接口时会用到的词

- **`action`** —— 接口名（字符串），例如 `'send_group_msg'`。
- **`params`** —— 这个接口需要的参数对象；键名来自 OneBot11（如 `group_id`），不能自己乱起。
- **`send_group_msg`** —— 往**群**里发消息。
- **`send_private_msg`** —— 往**私聊**发消息。
- **`set_group_ban`** —— 群**禁言** / 解除禁言。
- **`duration`** —— 禁言时长，单位**秒**；传 `0` 表示解除禁言。
- **消息段（message segment）** —— 一个 `{ type, data }` 对象，代表消息里的一段内容（文字 / @ / 图片 / 引用…）。多条消息段按数组顺序拼成一条消息。**常用消息段见第六节。**

### 代码基础（够用就行）

- **`export`** —— 把函数交出去给框架；不 export，框架找不到。（CJS 版对应 `module.exports = { … }`）
- **`require`** —— CJS 版里引入别的文件 / 内置模块；上面那句 `export` 的 CJS 对应写法。
- **`async` / `await`** —— 调接口要等结果，用 `await` 等它做完再往下走。
- **`function`** —— 给一小段步骤起个名字，方便反复调用。
- **`const` / `let`** —— 声明变量；`const` 不再改绑定，`let` 可以改。
- **`if` / `===`** —— `if` = 如果……就……；`===` = 两边**一模一样**才算对。

> **一条贯穿全程的写法**：判断指令用「**正向匹配**」——发的正是某条指令才做事；不要写「不等于就拦下来」。

## 四、示例里的 4 条指令

| 对方发送 | 机器人做什么 |
| --- | --- |
| `你好` | 回复 `你好呀` |
| `帮助` | 回复可用指令列表 |
| `ping` | 回复 `pong` |
| `禁言 QQ号 秒数` | 调 `set_group_ban`（仅群聊，机器人需有群管权限；秒数 `0` 为解除） |

**只走 JSON 消息段，不走 CQ 码**

- 取文字：从 `event.message` 数组里找 `type: 'text'` 的段；
- 发消息：传 `[{ type: 'text', data: { text: '…' } }]`；
- **不要**用 `raw_message`，也**不要**自己拼 / 拆 `[CQ:…]` 字符串——不稳定，用久了容易出怪问题。

## 五、事件里有哪些字段（速查）

一条群消息事件大概长这样：

```json
{
  "post_type": "message",
  "message_type": "group",
  "sub_type": "normal",
  "message_id": 12345,
  "group_id": 987654321,
  "user_id": 123456789,
  "self_id": 111111111,
  "time": 1730000000,
  "message": [{ "type": "text", "data": { "text": "你好" } }],
  "raw_message": "你好",
  "sender": { "user_id": 123456789, "nickname": "小明", "card": "群名片", "role": "member" }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `post_type` | string | 事件大类。消息事件固定 `'message'`；另有 `'notice'` / `'request'` / `'meta_event'`（只在 `plugin_onevent` 里见得到） |
| `message_type` | string | `'group'` 群聊 / `'private'` 私聊 |
| `sub_type` | string | 群聊：`normal` / `anonymous` / `notice`；私聊：`friend` / `group` / `other` |
| `message_id` | number | 这条消息的 ID。**撤回、引用回复**都要用它 |
| `message` | array | **JSON 消息段数组**，取内容用这个 |
| `raw_message` | string | 原始字符串（可能是 CQ 码）。教程不建议用 |
| `user_id` | number | 发消息那个人的 QQ 号 |
| `group_id` | number | 群号，只有群聊有 |
| `self_id` | number | 机器人自己的 QQ 号 |
| `time` | number | 事件时间戳（**秒**） |
| `sender` | object | 发送者资料：`user_id`、`nickname`（昵称）、`card`（群名片，可能为空）、`role`（`owner` / `admin` / `member`）、`level`、`title` |
| `font` | number | 字体，忽略即可 |

**三个最常见的用途**

```js
// 1. 判断发送者是不是管理员 / 群主
const role = event.sender && event.sender.role;
if (role === 'owner' || role === 'admin') { /* … */ }

// 2. 取昵称（群名片优先，没设就用昵称）
const name = (event.sender && (event.sender.card || event.sender.nickname)) || event.user_id;

// 3. 撤回刚才那条消息
await ctx.actions.call('delete_msg', { message_id: event.message_id });
```

## 六、常用协议接口与消息段（速查）

### 调接口的通式

```js
await ctx.actions.call(接口名, 参数对象);
```

- 成功 → 返回接口的 `data`；
- 失败 → **抛错**，必须 `try / catch`（见三条轨的「⑥」）。

### 常用接口

| 接口名（action） | 作用 | 必需参数 |
| --- | --- | --- |
| `send_group_msg` | 发群消息 | `group_id`、`message` |
| `send_private_msg` | 发私聊 | `user_id`、`message` |
| `send_msg` | 让协议端自己判断发群还是私聊 | `message`，加 `group_id` 或 `user_id` |
| `delete_msg` | 撤回消息 | `message_id` |
| `get_msg` | 查一条消息的详情 | `message_id` |
| `set_group_ban` | 群禁言 / 解除 | `group_id`、`user_id`、`duration`（秒，`0` = 解除） |
| `set_group_whole_ban` | 全员禁言开关 | `group_id`、`enable` |
| `set_group_kick` | 踢出群成员 | `group_id`、`user_id`（可选 `reject_add_request`） |
| `set_group_card` | 改群名片 | `group_id`、`user_id`、`card` |
| `get_group_member_info` | 查群成员资料 | `group_id`、`user_id` |
| `get_group_list` | 机器人的群列表 | 无 |
| `get_friend_list` | 机器人的好友列表 | 无 |
| `get_login_info` | 机器人自己的账号资料 | 无 |
| `set_group_add_request` | 同意 / 拒绝入群申请 | `flag`、`approve` |
| `set_friend_add_request` | 同意 / 拒绝加好友 | `flag`、`approve` |
| `send_like` | 给好友点赞 | `user_id`、`times` |

> 接口名和参数来自 OneBot11 标准，不同协议端（NapCat、LLOneBot 等）可能额外多提供一些。名字写错、参数缺了、没权限，都会在 `ctx.actions.call` 抛错，`err.message` 里能看到原因。

### 常用消息段

| `type` | 用途 | `data` 里的关键字段 |
| --- | --- | --- |
| `text` | 纯文字 | `text` |
| `at` | @某人 | `qq`（填 `'all'` 表示 @全体） |
| `image` | 图片 | `file`（本地路径 / URL / `base64://...`） |
| `face` | QQ 表情 | `id` |
| `reply` | 引用回复 | `id`（就是对方的 `message_id`） |
| `record` | 语音 | `file` |
| `video` | 视频 | `file` |
| `file` | 文件 | `file`、`name` |

**组合示例：引用对方那条消息、@ 他一句**

```js
await ctx.actions.call('send_group_msg', {
  group_id: event.group_id,
  message: [
    { type: 'reply', data: { id: event.message_id } },
    { type: 'at', data: { qq: event.user_id } },
    { type: 'text', data: { text: ' 收到' } },
  ],
});
```

> `message` 数组里消息段的**顺序**就是消息里的顺序。`text` 段里的空格会原样保留，所以 `' 收到'` 前面那个空格是为了和 @ 分开。

## 七、怎么装、怎么测

1. **拷文件夹**
   - JS 轨（ESM 版）：把 `JavaScript/ESM/kakake-plugin-hello/` **整夹**拷到 `plugins/kakake-plugin-hello/`。
   - JS 轨（CJS 版）：把 `JavaScript/CJS/kakake-plugin-hello-cjs/` **整夹**拷到 `plugins/kakake-plugin-hello-cjs/`。
   - TS 轨：先在 `TypeScript/hello-src/` 里 `npm install` → `npm run build`，再把生成的 **`kakake-plugin-hello/` 产物夹**拷过去。
2. **开总开关**：控制台 → 插件 → 打开这个插件的总开关。
3. **开连接开关**：控制台 → 连接 → 选中你的 OneBot 连接 → 打开该插件的连接开关（需机器人已登录、有 QQ 号）。
4. **逐条测**：`你好`、`帮助`、`ping`。
5. **群内测**：`禁言 <目标QQ> 10`（机器人要有禁言权限，别拿真人试）。
6. **看日志**：控制台「日志」页应该能看到插件打印的加载信息。

> 插件也可以打成 zip 在控制台导入：宿主会自动剥掉多余的一层目录，并把旧前缀 `napcat-plugin-` 统一改成 `kakake-`。

### 给插件加自我介绍

在插件目录里放一个 **`插件文档.md`**，控制台插件列表就会出现「查看说明」按钮，把这个 Markdown 渲染出来。用法、配置项说明、常见问题写在这里，比塞在代码注释里有效。

### 插件的名字从哪来

- **插件 ID** 始终是**文件夹名**（`kakake-*` 目录不会被 JSON 里的 `name` 覆盖）。
- **控制台显示的插件名**按顺序取第一个有值的：`plugin.json` 的 `displayName` → `package.json` 的 `plugin` → `package.json` 的 `name` → `plugin.json` 的 `name` → 文件夹名。
- 所以**改名要动四处**：文件夹名（决定 ID）、`plugin.json.displayName`、`package.json.plugin`，以及两个 JSON 里的 `name`（zip 导入时宿主会把 `name` 写成插件 ID，把它和文件夹名保持一致最省事）。

## 八、卡住了？照这里查

### 机器人完全不理我

- 总开关 + 连接开关是不是**都开了**（两个都要开）；
- 「日志」页有没有 `插件已加载`；
- 日志若提示消息格式不对 → 去协议端把**消息上报格式**改成**数组（array）**；
- 是不是别的插件也认这条指令（返回值不拦截，见第二节的注意）。

### 日志报「缺少 plugin_init」

入口没有正确导出：检查名字拼写、有没有写 `export`（CJS 写法是 `module.exports = { … }`）、打包后有没有被改名。

> CJS 写法的常见坑：写成 `exports = { plugin_init }` 是不行的——给 `exports` 重新赋值会断开它和 `module.exports` 的引用，框架拿到的是空对象。要整体交出去就写 `module.exports = { … }`。

### 插件列表里看不到我的插件

- 文件夹是否放在 `plugins/` 下、且名字以 `kakake-` 开头；
- 插件加载失败时**不会**从列表里消失，而是显示成 `error` 状态，点开能看到原因（「日志」页也会有一条 `[PluginLoader] … 验证失败`）。

### 列表里能跑，但显示的是文件夹名 / 没有简介

`package.json` 或 `plugin.json` 缺了，或者里面的 `displayName` / `plugin` / `description` 是空的。补齐 JSON 后回到插件页刷新即可（见第七节「插件的名字从哪来」）。

### 改了代码没反应

运行时读的是**产物**。改了源码（`src/index.ts`）就必须重新 `npm run build`，再覆盖产物夹。

### 禁言没生效

机器人不是管理员 / 群主时接口会失败。**接口失败会抛错**，所以要用 `try / catch` 接住，否则你什么都看不到（详见三条轨的「⑥」）。

## 九、本教程讲什么 / 不讲什么 / 然后去哪

**会讲**：收消息、按指令回复、`ctx.actions.call` 调协议接口（发消息 + 禁言）、加 @ 和引用回复、事件字段与常用接口速查、装进去能跑、插件收尾（`plugin_cleanup`）、出错怎么查。

**不讲**：插件网页后台（HTML / `webui` / 远程模块）、配置项 Schema（`plugin_config_schema`）、插件 HTTP 路由（`ctx.router`）、复杂权限体系、定时任务框架、`GF-` / `WX-` / `ss-plugin-` 三类插件。

**学完之后的三步**

1. **想要完整能力清单** → 读宿主源码 `src/plugin/plugin.types.ts`：`NapCatPluginContext` 就是 `ctx` 的真实类型，`PluginModule` 是插件能导出的所有钩子（含配置、路由、事件）。
2. **想看真实插件怎么写** → 看项目根目录的「其他插件源码」（例如 `MK_AI`：带配置页面、网页后台、多文件结构）。
3. **想给自己的插件加配置项或后台页面** → 照着上面的真实插件抄，比从零写快得多。
