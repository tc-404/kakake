# 咔咔珂 · 接口代理教程

插件想发消息、查群信息、戳人、点赞……但协议端有三套（NapCat / SnowLuma / QQ 官方），
接口名和参数键名各不相同，怎么办？

**接口代理就是回答这个问题的**：你只写 `kakake_api('接口短名', 'GET/POST', 参数)` 这一种写法，
由 kakake 判断当前连接背后坐的是谁，翻译成对应协议的原生请求发出去，再把结果包成统一
形态交还给你。

> 本文面向**插件作者**和**外放 API 调用方**。管理后台的日常操作（连接管理、开关）请看
> 「连接教程.txt」；免登录只读的运行概览接口是另一回事，见「外放API对接文档.md」。

## 一、三条铁律

代理层的所有行为都由这三条推导出来，写代码前先记住：

| # | 铁律 | 对你意味着什么 |
|---|------|--------------|
| 1 | **返回值透传** | 上游给什么就返回什么，代理层一个字段不改。元信息挂在并列的 `_proxy` 字段上，不会污染你的数据 |
| 2 | **永不空返回** | 超时、报错、协议不支持、参数缺失……一律返回失败信封。你**永远不需要** try/catch，也不用判 undefined——判断 `res.status === 'ok'` 一种写法就够 |
| 3 | **协议不支持就是报错** | 野生机器人调官方专属能力（或反向）直接失败，除非显式传 `force: true` 探索。宁可报错也不假装能通 |

## 二、三十秒上手

插件上下文里的 `ctx.kakake_api` 就是统一入口，它是**一个可以直接调用的函数**，
上面还挂着几个方法（钩子、查询、逃生舱，后面逐节讲）。

```js
// 发一条群文本消息：不用管当前连接是 NapCat、SnowLuma 还是官方机器人
const res = await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group',        // group=群聊 / private=私聊
  group_id: 123456,      // 野生用 QQ 号；官方连接则换 group_openid
  message: '大家好',
});

if (res.status === 'ok') {
  console.log('发出去了，消息 ID：', res.data.message_id);
} else {
  // 失败也一定有值：res.message 是人话说明，res._proxy.failure 是失败分类
  console.warn(res.message, res._proxy.failure);
}
```

三个要点：

- **第一个参数是接口短名**——全部短名在控制台「接口代理」页可以查，带中文说明和参数表；
- **第二个参数是 HTTP 方法**——绝大多数接口用 `'POST'` 即可；
- **返回值永远是信封**：`{ status, retcode, data, message, wording, echo, _proxy }`，
  其中 `data` 是上游原文（透传，一字不改）。

## 三、统一发消息（send_msg）

**发消息只有一条接口**，中文名就叫「发消息」。不要再找 send_text / send_image——
它们已经并进来了，作为**别名**保留，老代码不用改。

内容形态由参数 JSON 决定，三种写法覆盖所有场景：

### 3.1 纯文本

```js
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group',
  group_id: 123456,
  message: '你好，世界',
});
```

`message` 传字符串就是纯文本。

### 3.2 单发一张图 / 一条语音 / 一段视频

```js
// 单发图片（三种资源来源任选其一，权重完全相同）
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  file: 'C:/pictures/cat.jpg',                       // ① 本地绝对路径
});
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  file: 'https://example.com/cat.jpg',               // ② 远程 URL
});
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  file: 'base64://iVBORw0KGgo...',                   // ③ base64 载荷
});

// 单发语音 / 视频：用 media_type 区分，默认 image
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'private', user_id: 10001,
  file: 'C:/audio/hello.amr',
  media_type: 'record',                              // image / record / video
});
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  file: 'C:/video/clip.mp4',
  media_type: 'video',
});
```

### 3.3 图文一起发（消息段数组）

`message` 传 OneBot 消息段数组即可任意组合，媒体段的 `data.file` 同样支持
本地路径 / URL / base64：

```js
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  message: [
    { type: 'text',  data: { text: '看这张图 ' } },
    { type: 'image', data: { file: 'https://example.com/cat.jpg' } },
    { type: 'text',  data: { text: '再配一句话' } },
  ],
});
```

### 3.4 便捷组合

`file` 和 `message` 同传时，媒体段在前、文字在后：

```js
await ctx.kakake_api('send_msg', 'POST', {
  scene: 'group', group_id: 123456,
  file: 'base64://iVBORw0KGgo...',
  message: '配图说明文字',
});
// 等价于 message: [{image 段}, {text 段}]
```

### 3.5 官方机器人侧的自动处理

官方 OpenAPI 的发消息规则和野生完全不同（msg_type 0/7、媒体要先上传换 file_info），
这些代理层全自动处理，你不用关心：

- **纯文本** → `msg_type=0` 直发，不会多做一次上传；
- **带媒体** → 自动先调 `/v2/groups/{group_openid}/files`（或 users）上传：
  远程 URL 直接走 `url` 字段，本地路径由服务端读成 base64 走 `file_data`，
  `file_type` 按媒体类型自动填（图 1 / 视频 2 / 语音 3），拿到 `file_info` 后
  再以 `msg_type=7` 发出；
- **被动回复**（官方 5 秒时限）→ 传 `msg_id` / `msg_seq` / `event_id`，野生侧自动忽略。

### 3.6 别名兼容表

| 旧短名 / 原生接口名 | 现在归属 |
|---|---|
| `send_text` / `send_image` | 别名，解析到 `send_msg` |
| `send_group_msg` / `send_private_msg` | 别名（也是实际的野生原生 action） |
| `/v2/groups/{group_openid}/messages` 等官方 path | 别名，按老名字搜索也能找到 |

> 其余发送类接口（合并转发 `send_forward`、JSON 卡片 `send_ark`、收藏表情
> `send_custom_face` 等）语义独立，仍是单独条目，不并入发消息。

## 四、连接寻址：conn 参数

多条机器人连接同时在线时，用 `opts.conn` 指定打到哪一条：

```js
await ctx.kakake_api('get_login_info', 'POST', {}, { conn: 'snowluma' });  // 连接名
await ctx.kakake_api('get_login_info', 'POST', {}, { conn: '3858833831' }); // 也可以用连接 id（控制台连接管理页可查）
```

**不传 conn 时的兜底顺序**（`src/proxy/resolve/target.ts` 里的既定规则）：

1. 事件上下文里绑定的连接——消息从哪条连接进来，回复就发回哪条，**不会串门**；
2. 插件绑定的默认连接；
3. 都没有（定时任务等场景）→ 第一个已连接的 OneBot 连接，其次官方连接。

两条纪律：

- 传了 `conn` 但找不到这条连接 → 直接报错并列出可用连接，**绝不静默回落**到别的连接；
- 连接存在但没启用 / 未连接 → 同样明确报错。

## 五、失败信封与 _proxy 元信息

### 5.1 失败分类（`_proxy.failure`）

| 分类 | retcode | 含义 | 典型原因 |
|---|---|---|---|
| `upstream` | 上游自有码 | 协议端正常回了失败 | 没权限、被风控、参数上游不收 |
| `timeout` | -1002 | 超时 | 协议端没在时限内响应（默认 30s，可传 `timeoutMs` 覆盖，钳制 5s~600s） |
| `network` | -1007 | 连接层出错 | 断连、DNS、非预期异常 |
| `unsupported` | -1001 | 当前协议没这个能力 | 野生调官方专属接口；可 `force: true` 强发 |
| `intercepted` | -1008 | 被 before 钩子拦截 | 某个插件或你自己的钩子返回了 false |
| `id-space` | -1003 | ID 空间不匹配 | 拿 QQ 号填官方 openid（反之亦然） |
| `missing-param` | -1004 | 必填 / 路径参数缺失 | 少传了东西，报错信息会点名缺什么 |
| `unknown-api` | -1005 | 注册表没有这个短名 | 拼错名字了 |
| `not-connected` | -1006 | 连不上 | 未连接 / 被停用 / 是 KOOK 或微信连接（这两类暂不走代理） |

### 5.2 `_proxy` 里有什么

```js
{
  api: 'send_msg',              // 你调的短名
  protocol: 'snowluma',         // 这次实际落到哪个协议（napcat / snowluma / official）
  variant: 'group',             // 命中的场景变体
  connectionId: 'd4770b68',     // 走的哪条连接
  onebotImpl: 'snowluma',       // OneBot 连接背后的实现（探测结果）
  native: 'send_group_msg',     // 实际发出的原生 action / path——排查时看它
  httpMethod: 'POST',
  elapsedMs: 509,               // 耗时
  timeoutMs: 30000,
  httpStatus: 200,              // 上游 HTTP 状态码（官方侧必有）
  failure: undefined,           // 失败分类；成功时没有这个键
  source: 'my-plugin@3858833831', // 哪个插件的哪条账号实例调的
}
```

> 万一上游原文里真的有个字段叫 `_proxy`（概率极低），代理层会自动改挂
> `__kakake_proxy` 并在 `failure` 里留痕，不会悄悄覆盖你的数据。

## 六、钩子：before / after / error

三个钩子都返回**注销函数**，且**按插件作用域隔离**——插件卸载时自动摘干净，
不会泄漏到已销毁的上下文。

```js
// before：发请求前。返回 false 拦截；返回对象则替换参数；返回 undefined 放行
const offBefore = ctx.kakake_api.before((api, params, hookCtx) => {
  if (params.message?.includes('敏感词')) return false;      // 拦下
  return { ...params, message: `[已审核] ${params.message}` }; // 改写
});

// after：拿到结果后（只读，改了也不生效）
const offAfter = ctx.kakake_api.after((api, params, result) => {
  log.info(`${api} -> ${result.status}`);
});

// error：失败时被通知，err 里有 failure / message / meta
const offError = ctx.kakake_api.error((api, params, err) => {
  alert(`接口 ${api} 挂了：${err.failure}`);
});

offBefore(); offAfter(); offError(); // 用完注销；不注销则随插件卸载自动清理
```

喜欢另一种写法的话：`ctx.kakake_api.on.before(fn)` 等价于 `before(fn)`。

> 注意：钩子自己抛异常**不会**拖垮调用，按放行处理（有单测锁这个行为）。

## 七、注册表查询与逃生舱

### 7.1 查注册表（插件自检能力用）

```js
ctx.kakake_api.list();                    // 全部条目摘要（不含示例，避免过大）
ctx.kakake_api.list({ protocol: 'snowluma', category: 'group' }); // 按协议/分类过滤
ctx.kakake_api.get('send_msg');           // 单条详情：参数表、各协议实现、示例
```

每条摘要带：`name`（短名）、`title`（中文名）、`summary`（说明）、`category`
（分类）、`support`（支持哪些协议）、`params`（参数表：键名 / 类型 / 是否必填 /
说明 / 示例值）、`risk`（read / write / danger）等。控制台「接口代理」页展示的
就是这份注册表。

### 7.2 逃生舱：`kakake_api.native(...)`

注册表没收录、或者你就是要发一个原生 action / path 时：

```js
// OneBot 连接传 action 名
await ctx.kakake_api.native('get_version_info', {}, { conn: 'snowluma' });
// 官方连接传 path
await ctx.kakake_api.native('/v2/groups/{group_openid}/messages', { ... });
```

返回值和 `kakake_api(...)` 完全同构（同样带 `_proxy`），但**跳过变体选择与参数
翻译**——参数键名对不对全靠你自己。别拿它当常规手段，它是逃生舱不是正门。

## 八、NapCat 与 SnowLuma 的实现识别

NapCat 和 SnowLuma 都自称 OneBot v11，但部分接口的 action 名与参数键名不一致，
代理层必须知道对面坐的是谁。双保险：

1. **连接页下拉**（连接管理 → 协议端实现）显式指定 napcat / snowluma，指定了就不探测；
2. **自动识别**：连上后发一次 `get_version_info`，按 `app_name` 认实现，结果按连接缓存。

认不出来时按 NapCat 走（生态里最常见），并且 `_proxy.onebotImpl` 会记 `'unknown'`
——不假装确定，提醒你去连接页把实现名选对。

## 九、外放给 HTTP 调用方

想让**框架外的程序**（脚本、面板、别的服务）调机器人能力，可以打开接口代理外放：

1. 控制台「系统设置」→ 打开「接口代理外放 API」（默认关闭）；
2. 用控制台登录密钥做 Bearer 鉴权：

```bash
# 参数走 query（GET）
curl -H "Authorization: Bearer <控制台密钥>" \
  "http://<地址>:8787/api/v1/get_group_info?group_id=123456"

# 参数走 body（POST）
curl -X POST -H "Authorization: Bearer <控制台密钥>" -H "Content-Type: application/json" \
  -d '{"scene":"group","group_id":123456,"message":"大家好"}' \
  "http://<地址>:8787/api/v1/send_msg"
```

规则要点：

- **不另造凭证**：鉴权就是控制台登录密钥；
- **分桶限流**：按「来源 IP + 接口短名」每分钟 60 次，与登录限速是两套独立状态——
  外放接口被打爆不会把登录入口一起锁死；
- **HTTP 状态码的分工**：代理层**受理**了请求就回 200，真实成败看 body 里的信封
  （401 密钥错 / 403 开关没开 / 404 没有这个短名 / 429 限流，这些才是真实状态码）；
- 「能以机器人身份发消息」和「给外部看一眼运行状态」（另一个免登录只读开关）风险
  量级完全不同，所以是两个独立开关。

## 十、维护命令与新增接口

### 10.1 两条命令

```bash
npm run build:proxy-sources   # 重新抓取三份上游源快照（NapCat action 目录 + bot-docs api-v2）
npm run check:proxy           # 覆盖率 + 一致性门禁：未覆盖的上游接口会逐条列出
```

快照的原始来源放在 `src/proxy/registry/_sources/`（`_napcat/` 与 `_botdocs/` 不入库，
用 `extract-subtree.py` 从仓库压缩包解出）。

### 10.2 新增一条接口（贡献者流程）

1. 在 `src/proxy/registry/entries/<分类>.ts` 里加一个 `ProxyApiEntry`；
2. `name` 用简洁英文短名（`/^[a-z][a-z0-9_]{1,39}$/`），中文说明写在 `title`；
3. `alias` 把全部原生 action / path 塞进去，保证老接口名还能被搜到；
4. 每个协议给一份 `impl`；协议不提供的变体写 `stub: true` 并注明原因；
5. 补齐 `examples.request / success / error`——**示例要来自实测，不要编造**；
6. 跑 `npm run check:proxy` 确认没引入孤立引用，跑 `npm test` 过分发内核测试。

写法规范详见 `src/proxy/registry/entries/_CONVENTIONS.md`。

## 十一、已知硬限制

**QQ 号 ↔ openid 之间没有官方互转通道。** 野生机器人只有 QQ 号，官方机器人只有 openid，
而且同一个 QQ 群在不同官方机器人下 `group_openid` 都不同——跨机器人的转换缓存必然串号。

所以代理层**不猜测、不转换**：检测到空间不匹配就不发请求，直接返回写明
「需要什么 / 传入的看起来是什么 / 为什么不能转 / 去哪儿拿正确的」的失败信封。
这不是偷懒，是静默出错比明确报错危害大得多。

另外两件事要知道：

- **KOOK / 微信连接暂不走代理**：这两类连接的协议形态与 OneBot / 官方差异太大，
  调用会返回 `not-connected` 分类下的明确报错；
- **危险接口不会替你把关**：`risk: 'danger'` 只是控制台标红提示，代理层照发不误——
  踢人、禁言、退群的确认逻辑在你自己的插件里。

## 十二、排错速查表

| 现象 | 先看什么 | 常见原因 |
|---|---|---|
| 报 `unknown-api` | 短名拼写 | 去控制台「接口代理」页搜中文名找正确短名 |
| 报 `not-connected` | 连接管理页连接状态 | 连接没启用 / 掉线 / conn 名写错（报错会列出可用连接） |
| 报 `unsupported` | `_proxy.protocol` | 这条连接的协议端真没这能力；确认是不是该走另一条连接 |
| 报 `missing-param` | 报错信息点名的参数 | 少传必填项，或 scene 取值不在 group/private/channel/dms 里 |
| 报 `id-space` | 你填的 ID 形态 | 官方连接要 openid，别拿 QQ 号硬填 |
| 报 `upstream` | `_proxy.native` + 上游 message | 代理层没错，是协议端拒了：看权限、风控、参数值本身 |
| 报 `timeout` | `_proxy.elapsedMs / timeoutMs` | 协议端没回；大文件上传可传 `timeoutMs: 120000` 加大时限 |
| 发出去没反应但 status=ok | `_proxy.native` | 确认实际落到了哪个原生接口，再去协议端日志查 |
| 想本地调试不出网 | 控制台「模拟消息」 | 模拟上报会真实触发已加载插件，发送被拦截展示 |
